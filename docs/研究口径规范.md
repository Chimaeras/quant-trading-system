> 文档日期：2026-07-30  
> 对应工作项：QP-001（冻结 T+2/T+3 标签与成交口径）  
> 口径版本：`research_convention_v1`  
> 代码真相源：`com.quant.research.ResearchConvention`

本文件冻结「预测什么、何时可用、如何成交」的统一定义。后续 `LabelPipeline`、`PredictionService`、`HistoricalReplayService` 等研究模块必须以本口径为准，不得散落硬编码。

## 1. 预测目标

每个交易日收盘数据完成后，针对当日可交易股票池输出：

| 字段 | 含义 |
|---|---|
| `signal_date` | 信号所使用数据的截止交易日 |
| `entry_assumption` | 默认下一交易日开盘可成交；研究可切换 VWAP/收盘，须作为不同 entry 口径版本 |
| `prob_up_t2` | 从实际入场价到第 2 个持有交易日退出价，净收益大于阈值的校准概率 |
| `prob_up_t3` | 从实际入场价到第 3 个持有交易日退出价，净收益大于阈值的校准概率 |
| `expected_return_t2/t3` | 样本外期望净收益，可选但不替代上涨概率 |
| `uncertainty` | 置信区间、模型分歧或低样本告警 |
| `rank` | 当日可交易股票池内排序 |
| `reasons` | 主要正/负贡献、触发条件、风险与失效条件 |
| `model_version` | 模型、特征、标签和代码版本 |
| `data_snapshot_id` | 使用的数据快照和数据截止时间 |

**重要**：`CodexShortCycleScoringEngine` 输出的 `rule_score`（0–100 截面百分位）**不是**上涨概率，前端/接口不得标记为「上涨概率」。`rule_score` 仅作为 baseline/challenger 与概率模型的输入特征之一。

## 2. 上涨标签定义

T+2、T+3 分别建模，**不混合**为同一标签：

```text
y_h = 1[(exit_price_h × (1 − slippage) × (1 − commission − sell_tax)
         / (entry_price × (1 + slippage) × (1 + commission)) − 1) > min_net_return]
```

- `h ∈ {2, 3}`（持有交易日数）。
- `entry_price` = `signal_date` 下一交易日开盘价（默认）。
- `exit_price_h` = 入场后第 h 个持有交易日收盘价。
- `min_net_return` 默认 `0.0`；研究中另设 0.5%、1% 等阈值时，**必须作为不同 `label_version`**，不得覆盖默认标签。
- 成本默认：买入佣金万三、卖出印花税万五、单边滑点万二（与 `ScoringBacktestRequest` 默认值对齐）。
- **佣金买卖两侧都收**，买入腿与卖出腿各自为两级乘性（`(1±slippage) × (1±费率)`）。

> **勘误（Q-R010-01，2026-09-14）**：本节原写作
> `exit_price_h × (1 − sell_tax − slippage) / (entry_price × (1 + commission + slippage))`，
> **卖出腿漏了 `commission`** 且写成加性式；4 个实现站点（`LabelFactoryService`、
> `FactorResearchService` 两处、`ScoringBacktestService` 两处同构副本）一律为上式。
> 声明与实现之差 `f_impl − f_doc = −2.9984e-4`，主项 `−commission`（**−3.00 bp of E**）⟹
> **实现为准，声明曾错**。本次勘误只改声明文本与 `ResearchConvention.labelDefinition()` 字符串，
> **未改任何计算与历史数值**；受影响的历史净收益结论须按「原声明偏乐观 ≈ 3.00 bp of E」重新表述
> （见 `research/paper_loop/decision_queue.md` 的 `D-R010-05`，该重算**未**由 agent 执行）。
> 另注：本仓库曾把「多空收益差」命名为 `long_short_spread`，它实为**两个多头腿净收益之差**，
> 不是美元中性多空（`D-R003-01`/`D-R004-01`），引用该字段时须带此限定。

## 3. 成交与拒单处理

涨停无法买入、停牌、跌停无法卖出、退市等**不得删除样本**，必须按成交状态单独记录并进入组合回测：

| 状态码 | 含义 |
|---|---|
| `FILLED` | 正常完成买入与退出卖出 |
| `NOT_BUYABLE` | 涨停一字板/开盘涨停，无法买入 |
| `SUSPENDED` | 信号日或持有期内停牌 |
| `NOT_SELLABLE` | 退出日跌停无法卖出 |
| `DELISTED` | 持有期内退市 |

A 股 T+1：买入当日不可卖出。

| 字段 | 含义 |
|---|---|
| `signal_date` | 信号所使用数据的截止交易日（= 选股 `trade_date`） |
| `data_cutoff_time` | 数据快照截止时间（PIT 数据可用时间） |
| `prediction_created_at` | 预测生成时间 |
| `entry_date` | 实际入场交易日（默认 = signal_date 下一交易日） |

任一信号必须能回答：「使用了截至何时的数据、预测哪个持有期、按什么成交、输出是分数还是概率」。

## 6. 边界样例

| 场景 | 期望处理 |
|---|---|
| 信号日为春节前最后交易日 | entry_date 为节后首个交易日；h 按交易日计数，跳过假日 |
| 信号日次日开盘涨停 | 状态 `NOT_BUYABLE`，不进入收益样本，但保留记录 |
| 持有期内停牌 | 状态 `SUSPENDED`；若退出日仍停牌则不产生 exit_price |
| 退出日跌停 | 状态 `NOT_SELLABLE` |
| 上市不足 N 日 | 不进入可交易股票池（由可交易性闸过滤，QP-004 细化） |
| 不同板块涨跌停幅度 | 由 `TradingLimitRules` 按板块与 ST 状态推断（主板 10%/ST 5%/创业板科创板 20%/北交所 30%） |

## 7. T+1 次日方向标签（第三轮新增，与 T+2/T+3 并行）

> 对应工作项：第三轮「T+1 次日选股核心闭环」｜ 常量 `ResearchConvention.HORIZON_T1` / `T1_LABEL_NOTE`

**目标**：T 日收盘后预测次日(T+1)上涨方向，供「次日候选 TopN → 次日操作」工作流使用。

- **标签定义**：`y_1 = 1[close[t+1] / close[t] − 1 > min_net_return]`，close-to-close 方向，**无成本**。
- **区别于 T+2/T+3 成交口径标签（TRADED）**：T+1 方向标签仅预测次日收盘方向，不建模入场/退出的可执行净收益；两者**并行、不混用**（`label_snapshot.label_type` 区分：`T1_DIRECTION` / `TRADED`）。
- **可执行验证**：次日候选的**操作验证**用「次日开盘买入 → 次日收盘卖出（扣费）」回测，与方向标签解耦。
- **涨停/情绪特征**：涨停/连板/涨停家数/晋级率/次日溢价全部由本地 K 线推导（`LimitUpEcologyService`），无外部数据依赖。
- **候选核销**：候选清单（rule_score，非概率）落库 `t1_candidate`；次日结束后回填每只的次日涨幅/高开/涨停并聚合命中率。

## 8. 论文驱动改进轮次（R001–R015）产生的项目级口径（第四轮新增）

> 来源：`research/paper_loop/decision_queue.md` 的 `D-R008-08/09`、`D-R011-02/04`、`D-R012-01`、`D-R014-10`。
> 本节把此前**只存在于单轮预注册或单轮报告**的口径提升为**项目级**约定。
> 本节初版遵循「加法优先」；**2026-09-15 裁定 B「改名字」后**，§8.1 的两个同名键已实际改名
> （`avg_turnover_pct` / `avg_turnover_ratio`），见下方第 1/2/4 条的更新说明。

### 8.1 「换手率」在项目内至少指代**四个不同的量**，同名不可互用

审计（`D-R008-08`/`D-R008-09`）发现项目内两处惯例结论**相反**、对外却同名：

| # | 出处 | 键/字段（**2026-09-15 改名后**） | 实际含义 | 单位 | 是否有持仓序列 |
|---|---|---|---|---|---|
| 1 | `DataService` SQL | `AVG(COALESCE(m.turnover_rate,0)) AS avg_turnover_pct` | **市场换手率**（个股 `turnover_rate` 的截面均值） | %（键名 `_pct`） | 不适用 |
| 2 | `BacktestTurnoverService` → `TurnoverResponse` | `avg_turnover_ratio`（族：`max/min_turnover_ratio`、`*_actual_denominator`） | **候选名单替换率**（`1 − 交集/分母`） | 分数 0–1（键名 `_ratio`） | **无** |
| 3 | `CrossSectionNeutralizer` | `LOG_MV_FROM_TURNOVER` | **市值推算的数据来源标记** | 不是率 | 不适用 |
| 4 | `RollingExperimentService` | `turnover` | 明确输出 `"UNAVAILABLE"` + 「换手需组合执行口径（MP-020/021）才可评估」 | — | 无 |

**口径裁定（2026-09-15 裁定 B：改为「改名消歧」，键名即量纲）**：

0. **量纲写在键名里**：市场换手率一律 `_pct`、候选替换率一律 `_ratio`；**不保留旧名的兼容别名**
   （旧名 `avg_turnover` 不再可读，消费方须改用新名）。逐日行同理：`turnover_ratio` /
   `turnover_ratio_actual_denominator`。
1. **两个「换手率」不是同一个量**，不得互相引用或互相校准；跨模块比较前必须先把单位对齐到同一列。
2. **#2 的分母是请求参数 `top_n`**，不是当日实际名单规模 ⟹ 短员日会被**系统性高估**
   （名单未变时 `1 − m/top_n > 0`）。载荷已并列发射 `denominator`（`REQUEST_PARAM_TOP_N`）、
   `avg_turnover_ratio_unit`（`RATIO_0_1`）、逐日 `prev_size`/`curr_size`/`intersection_count`/`short_handed`，
   以及按当日实际规模归一的 `turnover_ratio_actual_denominator` 与配对口径 `same_strategy_pair`，
   读者可任选口径并按披露的量**精确复算**。
3. **#4 与本条 #2 不矛盾**：#4 说的是「**组合执行口径**的换手」（需要持仓序列）不可评估，
   #2 说的是「**候选名单**的替换率」（不需要持仓序列）。两者共用中文「换手」一词是**用词重叠**，
   不是结论冲突。新写的字段**必须**在名字里带上单位或口径限定（如 `_ratio` / `_pct` / `_actual_denominator`）。
4. 展示层标签**必须带单位**：`换手率(%)`（#1）、`平均替换率`（#2，前端按 `pct2` = `× 100` 换算并显示 `%`，
   无定义时显示「—」而不是 0%）。
5. **策略过滤回显只有归一后的两个键**（`D-R008-05`，裁定 B）：`strategy_requested`（原始请求值，
   `null`/空串/纯空白**一律归一为 `null`**）与 `strategy_effective`（未过滤时 `"ALL"`，真正过滤时即该策略名）。
   回显必须与实际过滤条件一致。旧的单键 `strategy`（对 `null` 回 `"ALL"`、对 `""` 回 `""`，同一分支两种回显）
   **已删除**，不再保留兼容别名；判定「本次到底过滤了没有」一律读 `strategy_effective` / `grouped_by_strategy`。

### 8.2 「备选集合」的合格形态（`D-R011-04`）

机械判定的判据来源若要写成「项目级备选集合」，必须满足：

- 形态为**枚举列表**或**显式取值域**；
- **单一常量不算**备选集合（没有可选性）；
- **单族 UI 的取值域不构成项目级备选集合**（前端某一处下拉框的候选值 ≠ 项目对某概念的正式取值域）。

为「项目级」的必须是**仓库内被声明为取值域**的东西（如常量表、类型联合、DDL 约束、词表常量）。

### 8.3 机械文本检索必须先做**子串假阳性**检查（`D-R011-02`）

R011 的 `robust` 在 `robustZ(residual, MAD)` 与 「robust Z on residuals」上命中**方法名子串**，
使 `V17` 的机械判定被翻转（实测 `NOT_VIOLATED` ≠ 冻结期望 `REGISTERED_ONLY`）。

**项目级约定**：

1. 任何用于**判定**的文本检索，**优先使用词边界匹配**（`\b` 或等价手段），不得裸用子串包含；
2. 若冻结词表尚未改成词边界，则**该轮判定结论必须以逐条人工判别为准**，并把判别过程写入报告；
3. 每轮首次检索后必须**显式报告子串假阳性检查结果**（命中数与逐条性质），
   该检查本身是本轮负知识的一部分。

### 8.4 `metric_scope` 是**承重键**，取值域为 **5 值**（`D-R012-01`）

| 值 | 含义 |
|---|---|
| `RAW` | 毛口径。**同名 `RAW` 在不同面指向不同价格基准**，须与 `price_basis` 联合阅读（见 8.5） |
| `COST_APPROX` | 成本后近似净口径 |
| `EXECUTABLE` | 可执行口径，**仅**对 FILLED 样本给出 |
| `FILLED_SAMPLE` | 仅 FILLED 样本子集 |
| `UNAVAILABLE` | 该口径在本面不可用（**不得**用 0 或空块冒充） |

**对外声明必须在代码内与该表一致**（`FactorResearchService` 类 Javadoc 已列全 5 值）。
若将来新增取值，**同时**更新：本表、类 Javadoc、前端类型声明，并作为契约变更评审。

### 8.5 「一面一基准」：同名的量在**不同面**必须能区分基准

同一键名在不同面承载不同基准，是本项目最反复出现的缺陷族（价差毛/净、价格 RAW/QFQ、
取整 4dp/原值、IS/OOS）。**项目级约定**：

- 每个载荷块**必须**自述 `price_basis`、`long_short_spread_cost_basis`、`rounding_rule`；
- 未取整原值以 `*_exact` 并列发射（载荷 4dp，DTO 面为原值）；
- 分组边界规则**必须**自述（`group_boundary_rule` = `INDEX_EQUAL_SPLIT_STABLE_SORT`）——
  并列 score 的相对次序**不作保证**（取决于上游查询返回的行序），故分组收益在并列行序变化时可能微幅改变，而 `rank_ic` 不受影响；
- 退化/空输入分支**必须发射与正常分支相同的键集**（`null` 表示「无定义」，**不等于 0**）。

### 8.6 预注册必须**逐变体冻结** `reachability` 等级（`D-R014-10`）

R014 的 `reachability` 只冻结了**阶梯**（`REACHABLE_PUBLIC_API > REACHABLE_CLIENT_INPUT > SYNTHETIC_ONLY > UNREACHABLE`），
逐变体等级由运行前落盘的 `config.json` 给出 ⟹ 运行中在冻结根内找到 **7** 处守卫**反证**该等级。

**项目级约定（后续同类装置）**：

1. 逐变体 `reachability` **纳入预注册冻结表**，不得只放在运行时 `config.json`；
2. 等级判定**必须附守卫清单证据**（哪些守卫使该路径不可达，文件:行）；
3. 若冻结后仍发现守卫反证，**保留**原判定并在报告中如实登记，**不得**事后放宽 `K` 判定。
