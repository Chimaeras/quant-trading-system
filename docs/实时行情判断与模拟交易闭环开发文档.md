# 实时行情判断与模拟交易闭环开发文档

> 项目：quant-trading-system  
> 状态：开发设计稿  
> 范围：实时行情查询、策略判断、目标持仓、风控、模拟下单与模拟成交  
> 安全边界：只做模拟交易，不接入真实券商，不自动操作真实账户

## 1. 目标

当前项目已经具备日线行情、因子研究、选股评分、策略回测、组合回测和模拟账户能力，但还缺少一条可以持续运行的决策闭环。本阶段要实现：

~~~text
行情查询
  ↓
行情标准化、质量与时效检查
  ↓
技术特征与策略判断
  ↓
目标持仓与调仓数量
  ↓
交易前风控
  ↓
模拟订单
  ↓
模拟成交
  ↓
现金、持仓、T+1、费用、净值更新
  ↓
前端查询、日志、对账和复盘
~~~

## 2. 本阶段边界

### 2.1 要实现

1. 查询自选股、候选股或策略股票池的最新行情。
2. 保存行情来源、行情时间、接收时间、时效和质量结果。
3. 合并实时行情、日线、财务、技术指标和现有策略评分。
4. 生成可追溯的 DecisionRun 和 StrategySignal。
5. 将信号转换为目标权重、目标市值和目标股数。
6. 执行现金、持仓、T+1、涨跌停、停牌、仓位、换手和行情新鲜度检查。
7. 生成模拟订单，按照成交规则创建模拟成交。
8. 更新现金、持仓批次、可卖数量、手续费、印花税和净值。
9. 支持幂等、暂停、重试、恢复和审计。
10. 前端展示行情、判断理由、风控结果、订单、成交和账户变化。

### 2.2 不实现

- 高频、毫秒级低延迟和盘口做市。
- QMT、MiniQMT、券商 API 或真实账户自动下单。
- 自动管理真实账户密钥。
- 让大模型直接产生订单。
- 未经过历史回放验证的新闻情绪自动影响模拟账户。
- 为本功能立即拆微服务或引入复杂消息基础设施。

首期采用模块化单体和可插拔行情适配器。行情先使用轮询，未来可以替换为 WebSocket、QMT 或其他供应商，而不改变策略、组合和模拟交易领域模型。

## 3. 现有代码基线

| 现有能力 | 现有位置 | 本阶段处理方式 |
|---|---|---|
| 单股实时行情 | RealtimeQuoteService、MarketController | 保留数据源逻辑，改造成批量适配器并落库 |
| 日线行情 | MarketData、MarketService | 作为历史特征输入 |
| 原始执行价格 | RawPriceResolver | 作为模拟成交的价格入口 |
| 费用和滑点 | TradingFeePolicy | 作为回测和模拟交易的统一策略 |
| 交易日历 | TradingCalendarService | 用于市场阶段、调度和 T+1 |
| 数据门禁 | DataQualityGateService | 增加行情时效和覆盖率判断 |
| 模拟账户 | SimulationSession、SimAccountService | 继续作为模拟账户聚合根 |
| T+1 持仓批次 | PositionLot | 继续计算可卖数量 |
| 日频预测 | PredictionRun、PredictionSnapshotItem | 日频继续使用，盘中新增 DecisionRun |
| 组合回测 | PortfolioBacktestService | 抽取可复用规则，不能直接当作实时执行器 |
| 系统就绪 | SystemReadinessService | 增加行情源、运行器和模拟账户状态 |

当前代码中的几个边界必须保持：

1. GET /api/market/realtime 是一次查询，不是持续行情流。
2. POST /api/order/place 是模拟下单，不代表已有真实 OMS 或券商能力。
3. 策略只输出 Signal，不能直接写订单。
4. 订单创建不等于成交，账户只能接受已确认的 Fill。
5. 复权价只用于研究和展示，不能用于涨跌停、资金和成交判断。
6. 行情为空、过期或质量异常时，必须阻断或输出 ABSTAIN，不能默默使用旧数据交易。

~~~text

        ↓

        ↓

        ↓

        ↓

        ↓

        ↓
交易前风控
        ↓

        ↓
模拟成交引擎
        ↓
模拟账户账本
        ↓
~~~

领域链路固定为：

~~~text
MarketQuoteSnapshot
    ↓
FeatureSnapshot
    ↓
StrategySignal
    ↓
PortfolioTarget
    ↓
RiskDecision
    ↓
PaperOrderIntent
    ↓
PaperOrder
    ↓
PaperFill
    ↓
PositionLot / AccountSnapshot / NavSnapshot
~~~

| 层 | 输入 | 输出 | 禁止事项 |
|---|---|---|---|
| 行情层 | 数据源响应 | 标准行情快照 | 直接生成订单 |
| 特征层 | 行情、日线、财务 | 特征和质量标记 | 修改账户 |
| 策略层 | 特征、股票池、市场状态 | 信号、分数、理由 | 直接下单 |
| 组合层 | 信号、持仓、资金 | 目标权重、目标数量 | 直接成交 |
| 风控层 | 调仓、行情、账户 | 通过、拒绝、降级 | 绕过硬风控 |
| 订单层 | 风控通过的意图 | 订单状态 | 把订单当成交 |
| 成交层 | 订单、行情、成交规则 | 成交回报 | 修改订单意图 |
| 账户层 | 成交回报 | 现金、持仓、净值 | 使用未确认成交 |

## 5. 端到端业务流程

### 5.1 盘前准备

盘前只准备数据和运行环境，不生成订单：

1. 检查今天是否为交易日。
2. 加载股票主数据、ST、停牌、上市状态和交易规则。
3. 检查历史日线是否覆盖策略窗口。
4. 检查行情源连接状态。
5. 检查模拟会话、现金和持仓是否有效。
6. 初始化 TradingDayContext。
7. 标记前一交易日未完成订单。

任一关键检查为 BLOCKED 时，不允许进入自动判断循环。

### 5.2 行情查询与入库

每轮行情任务：

1. 根据股票池生成 instrument 列表。
2. 创建 QuoteIngestBatch 和唯一 requestId。
3. 调用 MarketDataProvider，Controller 不直接请求外部 HTTP。
4. 将供应商字段映射为统一字段。
5. 记录 marketTime、receivedAt、source 和交易阶段。
6. 校验价格、成交量、涨跌幅、最高最低价。
7. 计算 freshnessSeconds。
8. 通过基础校验的记录标记为 VALID。
9. 失败标的记录明确原因。
10. 写入请求数、成功数、失败数、过期数和异常数。

### 5.3 特征与判断

根据 strategyVersion 创建 DecisionRun：

1. 固定 strategyVersion、dataVersion、asOf 和运行参数。
2. 读取最新有效行情和历史日线。
3. 计算涨跌幅、5/10/20 日动量、均线位置、波动率。
4. 计算成交量相对均值倍数、换手率分位数和距离涨跌停空间。
5. 加载现有因子或评分结果。
6. 执行股票池和可交易性过滤。
7. 输出 BUY、HOLD、SELL 或 ABSTAIN。
8. 保存分数、置信度、特征、过滤原因和质量标记。

行情过期、缺失、因子缺失或市场关闭时，只能输出 ABSTAIN。

### 5.4 组合构建

策略信号不直接等于买入数量。组合层：

1. 读取当前现金和持仓。
2. 读取已持有股票的可卖数量。
3. 过滤 ABSTAIN。
4. 按分数排序或使用策略权重。
5. 应用单票、行业、总仓位、现金和换手约束。
6. 转换为目标市值和目标股数。
7. 按 100 股交易单位向下取整。
8. 计算 deltaShares = targetShares - currentShares。
9. 只有 deltaShares 不为 0 才创建订单意图。
10. 保存 PortfolioTarget。

### 5.5 交易前风控

| 风控项 | 阻断条件 |
|---|---|
| 行情新鲜度 | 超过配置 TTL |
| 市场阶段 | 非允许交易阶段 |
| 交易日 | 非交易日或日历缺失 |
| 标的状态 | 停牌、ST、退市整理、禁止交易 |
| 涨跌停 | 买入涨停或卖出跌停 |
| 资金 | 现金不足或低于现金下限 |
| 持仓 | 卖出超过可卖数量，违反 T+1 |
| 数量 | 非 100 股整数倍，且不是清仓例外 |
| 仓位 | 超过单票、行业或总仓位上限 |
| 换手 | 超过单日换手或交易金额上限 |
| 重复 | 已存在同会话、标的、方向的未完成订单 |
| 运行状态 | kill switch 开启或数据质量 BLOCKED |

风控结果必须落库，至少支持 PASS、REJECT、DEGRADED、ABSTAIN，并保存 reasonCode、规则版本和账户快照。

### 5.6 模拟下单与成交

~~~text
RiskDecision.PASS
    ↓
PaperOrder.CREATED
    ↓
PaperOrder.ACCEPTED
    ↓
PaperFill.CREATED
    ↓
账户账本更新
~~~

没有有效成交价格时只能处于 ACCEPTED 或 PENDING_FILL，不得把信号参考价直接记为成交价。

### 8.3 时效规则

- receivedAt 为空：INVALID。
- lastPrice 小于等于 0：INVALID。
- marketTime 早于允许窗口：STALE。
- 请求成功但返回空集合：PARTIAL 或 FAILED。
- 供应商超时：保留错误记录，不使用上一次行情自动交易。
- 只有行情在 TTL 内，才允许产生非 ABSTAIN 信号。

### 9.2 输出

每个标的都要保存方向、分数、置信度、参考价格、关键特征、理由、行情快照 ID 和质量状态。

~~~json
{
  "instrument": "600000.SH",
  "direction": "BUY",
  "score": 82.5,
  "confidence": 0.71,
  "referencePrice": 12.36,
  "validity": "VALID",
  "reasonCodes": ["TREND_ABOVE_MA20", "VOLUME_CONFIRMATION"],
  "features": {
    "return_5d": 0.083,
    "volume_ratio_20d": 1.42
  }
}
~~~

第一版策略运行器：

~~~text
股票池过滤
  → 行情有效性过滤
  → 交易状态过滤
  → 计算依赖特征
  → 调用已有策略
  → 生成分数、方向和理由
  → 应用阈值
  → 输出 Signal，不创建订单
~~~

| 信号 | 含义 |
|---|---|
| BUY | 允许组合层考虑增加仓位 |
| HOLD | 当前仓位不需要调仓 |
| SELL | 允许组合层考虑降低仓位 |
| ABSTAIN | 数据、市场或策略条件不足，不做交易判断 |

## 10. 组合与目标持仓

首期组合器实现 Top-N 或等权二选一，并支持单票最大权重、总仓位上限、现金下限、最大换手和最大持仓数。

~~~text
targetMarketValue = totalAsset * targetWeight
rawTargetShares = targetMarketValue / executablePrice
targetShares = floor(rawTargetShares / lotSize) * lotSize
deltaShares = targetShares - currentShares
~~~

调仓顺序：

1. 先处理卖出，释放现金。
2. 再按分数从高到低处理买入。
3. 每笔订单创建后重新计算剩余现金。
4. 失败必须记录原因，不能静默替换股票。
5. 替补标的必须生成新的组合版本。

价格必须来自有效执行报价，展示用复权价不能参与目标股数计算。

## 11. 模拟成交模型

### 11.1 成交价格

| 模式 | 使用场景 | 规则 |
|---|---|---|
| LAST_PLUS_SLIPPAGE | 无盘口 | 买入最新价加滑点，卖出最新价减滑点 |
| BID_ASK | 有买一卖一 | 买入卖一，卖出买一 |
| NEXT_QUOTE | 轮询模拟 | 等待下一次有效快照 |
| NEXT_BAR_OPEN | 历史回放 | 下一分钟或下一交易日开盘 |

没有有效价格时不得成交。成交必须保存 priceSource 和 quoteSnapshotId。

### 11.2 成交数量

- FULL_FILL：满足价格、状态和资金条件时全部成交。
- PARTICIPATION_CAP：成交数量不超过当前成交量乘以参与率。

首期默认使用 PARTICIPATION_CAP，允许部分成交和超时取消。

### 11.3 A 股规则

- 买入数量按 100 股取整。
- 当日买入当日不可卖。
- 卖出不得超过可卖数量。
- 停牌不能成交。
- 涨停买入、跌停卖出默认不成交或待成交。
- 不能用复权价判断真实成交可行性。
- 手续费和滑点统一使用 TradingFeePolicy。

### 11.4 费用

~~~text
grossAmount = fillPrice * filledShares
commission = max(grossAmount * commissionRate, minimumCommission)
stampTax = sell ? grossAmount * stampTaxRate : 0
slippageAmount = abs(fillPrice - referencePrice) * filledShares
~~~

具体比例必须来自版本化 TradingFeePolicy，不能散落在服务代码中。

## 12. 订单状态机

~~~text
CREATED
  ↓
RISK_CHECKING
  ├── REJECTED
  └── ACCEPTED
        ↓
PENDING_FILL
  ├── PARTIALLY_FILLED → PENDING_FILL
  ├── FILLED
  ├── CANCELLED
  └── EXPIRED
~~~

规则：

- REJECTED、CANCELLED、EXPIRED、FILLED 为终态。
- 已成交数量只能追加成交记录，不能修改历史成交。
- 一个 clientOrderKey 只能创建一个有效订单。
- 订单创建不等于成交。
- 账户只接受 PaperFill。
- 重试前必须查询已有订单，不能重复创建。

请求必须固定 simulationSessionId、strategyKey、strategyVersion、quoteBatchId 或 asOf、idempotencyKey。默认只生成信号和目标组合，不创建订单。

~~~text

GET  /api/paper/sessions/{sessionId}/account-snapshots

~~~

调仓接口只接受已生成的 decisionRunId 或 portfolioTargetId，不接受前端直接传入任意成交价作为成交事实。

### 13.5 异步任务

~~~text
PENDING -> RUNNING -> SUCCEEDED
                  -> PARTIAL
                  -> FAILED
                  -> CANCEL_REQUESTED -> CANCELLED
~~~

批量行情、策略判断和批量模拟成交使用 taskId、runId 查询，不在 HTTP 请求线程执行长时间计算。

## 19. 安全和运行保护

- 模拟和未来实盘环境使用不同配置和账户标识。
- 默认只读，明确执行模拟下单命令才允许写订单。
- 默认关闭任何真实券商适配器。
- 不允许前端传入成交价覆盖成交引擎。
- 模拟账户、策略、订单和运行日志按用户或账户隔离。
- 生产环境禁止默认关闭鉴权。
- kill switch 开启后，所有新调仓和模拟订单都必须拒绝。
- 服务恢复时先扫描未终态订单，再继续执行。

~~~text
你正在修改 quant-trading-system。

本阶段只实现实时行情查询、策略判断、目标持仓、风控、模拟订单和模拟成交，禁止接入真实券商，禁止真实自动下单。
~~~

## 22. 完成判定

以下条件全部满足时，才认为本阶段完成：

- 能批量获取并保存最新行情。
- 能查询行情来源、行情时间和数据延迟。
- 能根据固定策略版本生成可解释信号。
- 行情过期时不会生成有效交易信号。
- 能生成目标持仓和调仓差异。
- 每笔调仓都有风控结果。
- 能正确处理模拟订单的拒单、未成交、部分成交和全部成交。
- 成交后现金、持仓、T+1、费用和净值一致。
- 任务重试和服务重启不会重复下单或重复成交。
- 前端可以查看行情 → 判断 → 目标 → 风控 → 订单 → 成交 → 账户完整链路。
- 有历史回放或固定样本证明信号和成交可以复现。
- 没有代码路径可以在未明确配置的情况下触发真实券商下单。

完成上述闭环后，项目才从“选股和模拟账户”升级为“可持续运行的量化交易决策与模拟执行系统”。
