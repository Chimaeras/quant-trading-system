# 实时监控、分析与模拟下单全面审计及优化计划

日期：2026-08-19  
范围：`modules/compute-python/paper/watch`、Paper Live 行情/账户/风控、Java 代理、Vue 监控页

## 1. 结论

项目已经具备“交易时段轮询行情 → 聚合已收盘分钟 bar → 产生技术信号 → 组合风控 → 妙想模拟盘提交 → 本地审计与监控页”的最小闭环，并已实现双重 live 开关、交易日历、T+1 可卖数量、涨跌停硬闸、重复委托拦截、未知提交冻结和提交后账户复查。

但当前实现仍属于可联调的个人 Paper Live，而不是可长期无人值守的真实量化执行系统。最关键的差距是：全市场行情完整性尚未被可靠验证，分钟状态不能跨重启/跨日恢复，同轮委托缺少资金与风险预留，订单没有完整生命周期管理，监控日志按全市场逐股追加后不可长期扩展。

## 2. 已确认问题与优先级

### P0：本轮必须修复

1. **全市场批量行情运行时与解析错误**
   - `snapshot_many` 使用 `QuoteValidity` 但未导入，真实进入批量分支会触发 `NameError`。
   - 通用数值解析禁止负数，导致负涨跌幅被解析为 `None`，大盘急跌中位数风控失真。
   - `clist/get` 以候选代码分块并传 `secids`，无法保证响应严格按这些代码过滤；可能重复返回市场排序前 N 条并造成大面积 `MISSING`。
   - 批量行情用本地接收时间代替源行情时间，无法真正执行过期检查。

2. **组合风控可被同轮连续委托穿透**
   - 后一笔买单仍使用轮初 `avail_balance` 和持仓市值。
   - 已有活动买单的剩余名义金额没有计入 `max_total_weight`，待建仓代码没有计入 `max_positions`。
   - 明确拒单也增加 `day_trade_count`，使交易次数统计与“已受理/状态未知订单”不一致。

3. **交易状态损坏时错误地 fail-open**
   - `state.json` 无法解析时会把日交易次数、冷却和未知提交全部清零后继续。
   - 状态写入不是原子替换，进程终止可能留下半文件。

4. **监控数据绕过生产鉴权**
   - 后端鉴权拦截器只覆盖 `/api/**`，而含账户资产、委托与动作信息的 `/pyapi/**` 未覆盖。

### P1：接近真实系统所需的下一阶段

1. **分钟 bar 检查点与预热服务**
   - 全市场模式每天从零累计；MA20/5 分钟默认约 100 分钟无买入能力，重启后再次失忆。
   - 应将已收盘 bar 写入专用时序存储，并在开盘前完成全市场预热；持仓与高优先级候选优先恢复。
   - 在没有可靠批量分钟数据源前，不应并发轰炸公开单股 K 线接口来伪装“全市场即时预热”。

2. **两级实时选股架构**
   - Level 1：对全市场快照执行价格、成交额、停牌、板块和数据质量筛选。
   - Level 2：只对活跃候选和全部持仓维护盘口/分钟序列、策略和执行级行情。
   - 明确记录全市场覆盖率、延迟分位数、缺失代码和降级原因。

3. **订单生命周期管理（OMS）**
   - 建立本地订单状态机：CREATED/SUBMITTED/PARTIAL/FILLED/CANCELLED/REJECTED/UNKNOWN。
   - 定时对账部分成交，超时撤单或撤改，卖单与买单使用不同 TTL；UNKNOWN 必须人工或柜台证据解除。
   - 资金、持仓、费用和滑点按成交回报更新，而不是按提交即成交。

4. **日志与监控扩展性**
   - 全市场最新快照应进入覆盖写的 latest snapshot/时序库，不应每分钟为几千只股票追加 `QUOTE` 事件。
   - 事件流只保留异常、可交易信号、风控和订单状态变更；文件读取增加索引/轮转和保留期。

### P2：策略真实性与运维

1. 将单策略切换升级为策略组合、信号冲突仲裁、行业/风格暴露控制和波动率仓位。
2. 增加开盘集合竞价、午间、尾盘禁开仓窗口，以及停牌、ST、退市整理、不同板块价格笼子规则。
3. 建立回测—仿真—Paper Live 同一策略/费用/撮合口径，加入延迟、部分成交、冲击成本模型。
4. 增加进程守护、心跳、外部告警、指标采集、自动收盘对账和次日恢复演练。

## 4. 验收门槛

1. 批量行情测试同时覆盖正跌幅、负跌幅、源时间过期、分页重复/缺页和未返回代码。
2. 两笔同轮买入不能穿透现金底线、总仓位或最大持仓数；活动买单承诺被计入组合暴露。
3. 明确拒单不消耗“今日已受理交易数”；未知提交仍冻结并占用计数。
4. 状态文件损坏时 dry-run 可继续观察，但 live 必须 BLOCKED，且不会调用 `trade`。
5. 鉴权开启时 `/pyapi/**` 需要有效 token；鉴权关闭时保持本地单用户兼容。
6. 所有测试通过后，结论最多为“可进入全市场 dry-run 与受控模拟盘联调”，不能宣称已达到生产实盘等级。
