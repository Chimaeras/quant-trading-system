# 实时行情判断与妙想模拟盘接入完整开发文档

> 项目：quant-trading-system  
> 版本：v2.0  
> 状态：融合开发设计稿  
> 范围：实时行情查询、本地策略判断、妙想模拟盘下单、成交查询、对账与复盘  
> 安全边界：只接入东方财富妙想模拟组合，不接真实券商、不接真实资金、不做无人值守自动确认

## 1. 结论先说

本项目已经具备日线行情、因子研究、选股评分、T+1 候选、回测、组合回测和内部 SimAccount，但缺少实时决策到模拟委托的完整链路。

本阶段应新增一条独立的 Paper Live 链路，不改写选股主航道：

~~~text
Java 日频选股/T+1 候选
        ↓
Python Paper Live 应用
        ↓
妙想行情查询 / 资金 / 持仓 / 委托
        ↓
本地纯函数研判与风控
        ↓
dry-run 结果
        ↓
人工确认
        ↓
妙想模拟盘限价委托
        ↓
再次查询委托、持仓、资金并生成对账
~~~

重要结论：

1. 妙想接口是问句查数加模拟交易 API，不是 Tick 推送。
2. 本阶段的实时是有限观察池的轮询实时，不是交易所级行情流。
3. 妙想账户的资金、持仓和委托是外部执行真相源。
4. 项目内部 SimAccount 是历史时钟模拟账本，不能和妙想账户混写。
5. 第一阶段使用 Python CLI 最合适，不阻塞 Java 选股服务。
6. 文档足够开始 P0-P3 的骨架、解析器、纯函数和 dry-run 开发；绑定账户并拿到真实 JSON 前，不足以宣称完整可运行。

## 3. 目标与非目标

### 3.1 本阶段目标

1. 查询观察池股票的最新价格、涨跌幅、成交量和量比。
2. 保存查询时间、行情时间、来源、原始 JSON 哈希和解析结果。
3. 从 Java T1Candidate 或本地候选文件加载观察池。
4. 合并候选、行情、妙想账户、持仓和未完成委托。
5. 生成 BUY、HOLD、SELL、ABSTAIN 或 NOOP 判断。
6. 根据资金、单票上限、交易单位和交易状态计算模拟订单。
7. dry-run 只生成意图，不调用交易接口。
8. confirm 模式经人工确认后逐笔调用妙想模拟盘限价委托。
9. 下单后重新查询委托、持仓和资金。
10. 连续运行时不重复下单、不因超时盲目重发、不把未知状态当成失败。
11. 为后续 Java API、数据库和前端接入预留稳定 Port。

### 3.2 不实现

- 真实资金、真实券商柜台和 QMT/MiniQMT。
- 高频、逐笔行情和盘口低延迟交易。
- 全市场实时轮询。
- 盘中重算全市场因子。
- 让新闻、资讯或大模型直接决定是否下单。
- V1 自动止损、自动卖出、自动补单和自动撤单循环。
- 将妙想账户和内部 SimAccount 写入同一张真相表。

V1 只做“昨日 T+1 候选 → 今日实时可交易性判断 → 人工确认的模拟买入”。卖出和完整组合调仓在 V2 单独实现。

必须遵守：

- 不使用本地理论持仓覆盖妙想返回的可用数量。

## 6. 妙想接入前置条件

### 6.1 配置

~~~powershell
$env:MX_APIKEY = "你的密钥"
$env:MX_API_URL = "https://mkapi2.dfcfs.com/finskillshub"
~~~

约束：

- MX_APIKEY 不能入库、入 Git、写前端或打印日志。
- MX_API_URL 只允许官方基址。
- V1 本地 CLI 使用环境变量，后续服务使用密钥管理。

### 6.2 模拟账户绑定

1. 打开妙想 Skills 页面：https://dl.dfcfs.com/m/itc4
2. 获取 MX_APIKEY。
3. 创建或领取模拟组合。
4. 将模拟组合绑定到当前 Key。
5. 运行资金查询确认绑定成功：

~~~powershell
cd E:\Project\quant-trading-system\modules\compute-python
python -m paper.cli ping
~~~

P0 成功标准：

- 请求成功。
- 返回总资产。
- 返回可用资金。
- 能区分“账户为空”和“未绑定账户”。

未绑定通常返回 code=404。P0 前允许写 Adapter、解析器和单测，但禁止 trade 和 cancel。

### 6.3 外部接口约束

| 约束 | 规则 |
|---|---|
| 品种 | 仅 A 股 |
| 交易代码 | 6 位数字，如 600519，不带 .SH/.SZ |
| 数量 | 正整数且为 100 的倍数 |
| 沪市价格 | 限价最多 2 位小数 |
| 深市价格 | 限价最多 3 位小数 |
| 市价 | useMarketPrice=true 时不依赖 price |
| 交易时间 | 工作日 09:30–11:30、13:00–15:00 |
| 配额 | code=113 时停止本轮 |
| 域名 | 只允许 mkapi2.dfcfs.com |

集合竞价、价格限制、订单状态和模拟盘 T+1 必须绑定后实测。

## 7. 妙想 Adapter

### 7.1 分层

~~~text
mx_http.py
  → 统一 POST、Header、超时、重试、错误码和原始 JSON

quote_client.py
  → /api/claw/query

broker_client.py
  → balance
  → positions
  → orders
  → trade
  → cancel
~~~

mx_moni.py 只作为人工验证和接口参考。策略代码和 runner 不调用自然语言 CLI，也不让 LLM 生成交易问句。

### 7.2 通用请求

~~~text
POST
Content-Type: application/json
apikey: MX_APIKEY
~~~

每次请求记录 requestId、endpoint、开始时间、结束时间、耗时、重试次数和是否可安全重试。

查询接口可以有限重试。trade 和 cancel 超时必须先查 orders，不能立即重发。

### 7.3 结果归一化

交易接口兼容：

~~~python
ok = bool(result.get("success")) or str(result.get("code")) == "200"
~~~

行情 query 还要处理顶层 status=0。

统一结果模型：

~~~text
MxResult
  success
  code
  message
  data
  raw
  endpoint
  request_id
  received_at
  retry_count
~~~

原始 JSON 按 run_id 和 endpoint 落盘并脱敏。

### 7.4 错误码

| 代码/现象 | 含义 | 处理 |
|---|---|---|
| 200 或 success | 成功 | 解析 data |
| 0 | query 成功形式 | 解析行情 |
| 113 | 调用次数用尽 | 停止本轮并告警 |
| 114/116 | Key 无效 | 停止，不重试 |
| 115 | 未带 Key | 停止并检查配置 |
| 404 | 未绑定组合 | 停止交易并提示绑定 |
| HTTP 4xx/5xx | 网关或网络 | 仅查询有限重试 |
| 非交易时间文案 | 时段外 | skip，不硬打 |
| 可撤委托不存在 | 已成或已撤 | 刷新 orders |
| JSON 不完整 | 网络或服务异常 | 保存原文并失败 |

## 8. 行情查询与快照

### 8.1 Query 接口

接口：

~~~text
POST /api/claw/query
~~~

固定问句模板：

~~~text
{stock_name}({stock_code}) 最新价 涨跌幅 成交量 量比
~~~

约束：

- 默认一标的一请求。
- 不使用“应不应该买”一类问句。
- 不让 LLM 自由生成问句。
- 不进行全市场实时轮询。
- 多代码一问须绑定后实测稳定才开放。

### 8.2 解析路径

已知结果路径：

~~~text
data.data.searchDataResultDTO.dataTableDTOList[]
entityTagDTO.secuCode
entityTagDTO.marketChar
table.headName
table.<指标编码>
nameMap
field.returnName
field.dateGranularity
~~~

解析步骤：

1. 顶层 status 非 0 时返回 QuoteError。
2. 用 secuCode 对齐请求代码。
3. 用 nameMap 和 field.returnName 匹配最新价、涨跌幅、成交量、量比。
4. 取最后一个非空值。
5. 归一化代码、名称、价格、涨跌幅、成交量、量比和时间。
6. 保存 raw JSON 和 raw hash。
7. 解析失败只影响该股票，不把整批错误伪装成成功。

涨跌幅单测必须覆盖：

~~~text
0.38
0.0038
0.38%
~~~

字段未冻结前，缺字段必须 QUOTE_PARSE_ERROR。

### 8.3 Quote 模型

~~~text
Quote
  code
  name
  exchange
  last
  pct_chg
  volume
  amount
  volume_ratio
  market_time
  received_at
  source
  freshness_seconds
  validity
  raw_hash
  raw_path
~~~

有效性：

- last 缺失或小于等于 0：INVALID。
- market_time 缺失：INVALID 或 UNKNOWN_TIME。
- received_at 缺失：INVALID。
- 超过 PAPER_QUOTE_STALE_SEC：STALE。
- volume=0：默认 NOT_TRADABLE。
- 返回空数据：该票失败，不使用上一次数据自动下单。

### 8.4 轮询和配额

- 观察池建议不超过 10 只。
- 每轮只查候选和已有持仓。
- dry-run 和 confirm 尽量复用同一个 quote batch。
- code=113 后停止本轮全部 query 和 trade。
- 不允许全市场扫描。
- 同一标的要有最短查询间隔和本地缓存。

### 10.2 V1 判断

~~~text
非允许交易窗口
  → 全部 NOOP / TIME_WINDOW

PAPER_HALT=1
  → 全部买入 NOOP / HALT

对每只候选：
  创业板或科创板且开关关闭
    → NOOP / BOARD_BLOCKED
  无有效 quote 或 last<=0
    → NOOP / QUOTE_MISSING
  quote 过期
    → NOOP / QUOTE_STALE
  成交量为 0 或明确停牌
    → NOOP / NOT_TRADABLE
  真实涨停价可用且 last>=涨停价
    → NOOP / LIMIT_LOCKED
  涨停价不可用
    → dry-run 提示；confirm 硬拦截 / LIMIT_DATA_UNAVAILABLE
  已有持仓股数 >= 目标股数
    → NOOP / ALREADY_FILLED
  存在同向未完成委托
    → NOOP / DUPLICATE_ORDER
  计算目标数量
  qty < 100
    → NOOP / QTY_TOO_SMALL
  输出 BUY_LIMIT
~~~

V1 默认不开自动卖、不允许市价、不自动补单、不自动撤单循环。

### 10.3 目标数量

V1 采用保守的可用资金基数：

~~~text
target_value = avail_balance * PAPER_MAX_NAME_WEIGHT
target_qty = floor(target_value / last / 100) * 100
target_qty = min(target_qty, affordable_qty)
~~~

建议默认：

~~~text
PAPER_MAX_NAME_WEIGHT = 0.20
PAPER_MAX_TRADES_PER_RUN = 5
~~~

V2 再改为总资产目标权重、总仓位、现金下限、行业约束和组合调仓。

本地费用估算沿用 TradingFeePolicy：

~~~text
commission = max(gross_amount * 0.0003, 5)
stamp_tax = sell ? gross_amount * 0.0005 : 0
slippage = gross_amount * 0.0002
lot_size = 100
~~~

妙想实际扣费以外部账户为准，对账中记录差异。

## 11. 风控闸

风控失败写入 risk_reject_reason，禁止调用 trade。

| 序号 | 风控 | 规则 |
|---|---|---|
| 1 | 绑定 | balance 非成功，整次 run abort |
| 2 | 时段 | 默认只允许连续竞价 |
| 3 | 白名单 | 仅候选池代码 |
| 4 | 板块 | 创业板、科创板默认关闭 |
| 5 | 手数 | qty > 0 且 qty % 100 == 0 |
| 6 | 价格 | 限价必填且符合市场小数位 |
| 7 | 涨跌停 | 可获得真实价格时必须校验 |
| 8 | 资金 | 买入金额加佣金不超过 availBalance |
| 9 | 单票 | 成交后市值不超过单票上限 |
| 10 | 单日 | 不超过 PAPER_MAX_TRADES_PER_RUN |
| 11 | 新鲜度 | quote 未超过 PAPER_QUOTE_STALE_SEC |
| 12 | 重复单 | 无同向未完成委托 |
| 13 | T+1 | 卖出不超过妙想 available_quantity |
| 14 | 账户 | 余额、持仓、委托查询必须可用 |
| 15 | 配额 | code=113 立即停止 |
| 16 | 熔断 | PAPER_HALT=1 禁止开仓 |
| 17 | 人工确认 | 无 --confirm 禁止 trade |
| 18 | 未知状态 | trade 超时或状态未知时冻结 |

缺少真实涨跌停价格时，dry-run 可以警告，confirm 必须硬拦截。

## 12. 主流程、幂等和对账

### 12.1 主流程

~~~text
start
  → 校验配置、交易日历和行情观察池
  → balance；失败 abort
  → load candidates
  → 逐只 query quote
  → positions + orders
  → normalize
  → decide
  → risk
  → 写出 PaperRun
  → dry-run：结束，不调用 trade
  → run --confirm：
       再次确认摘要和配置哈希
       同步逐笔 trade，禁止并发
       记录外部返回
       trade 超时先查 orders，禁止立即重发
  → 再拉 orders、positions、balance
  → 生成 reconcile
  → 写本地 artifacts
end
~~~

### 12.2 幂等键

~~~text
run_key = trade_date + candidate_source + strategy_version + quote_batch_hash + config_hash
client_order_key = run_id + stock_code + side + qty + price_type
~~~

同一 key 不重复创建有效 intent，也不重复调用 trade。

### 12.3 trade 超时

1. 标记 UNKNOWN_SUBMIT。
2. 保存 requestId、请求摘要和错误。
3. 查询 orders。
4. 按代码、方向、数量、价格范围和时间窗口匹配。
5. 唯一匹配则补记 orderId。
6. 无法唯一匹配则冻结该标的，不重发，等待人工处理。

### 12.4 收盘对账

查询 balance、positions、orders 和绑定后确认可用的历史成交接口，输出：

~~~text
submitted_orders
external_orders
matched_orders
unknown_orders
rejected_orders
position_delta
cash_delta
fee_difference
reconcile_status
~~~

出现未知提交、无法解释的持仓差异或资金差异超过阈值时，状态为 BLOCKED。

## 16. 分阶段交付

### P0：绑定和接口实测

- 配置 Key。
- 绑定模拟组合。
- 跑通 balance、positions、orders。
- 保存脱敏 JSON fixture。
- 确认成功包络、字段名、订单状态和可撤条件。

完成：ping 能显示总资产和可用资金；未绑定能识别 404；得到真实持仓和委托字段。

### P1：Adapter 和行情解析

- 实现 mx_http.py、mx_result.py。
- 实现 quote_client.py、broker_client.py。
- 实现 parse_query.py。
- 增加查询重试、原始 JSON 和错误码处理。

完成：quote 能解析 last、涨跌幅、成交量；account 能输出资金、持仓和委托；单测不联网。

### P2：纯函数研判和风控

- 实现 models.py、candidates.py、decide.py、risk.py。
- 固定 BUY_LIMIT、NOOP、ABSTAIN 和 reason_codes。

完成：空候选、非交易时段、非法数量、板块限制、过期行情和缺涨跌停信息均有明确结果。

### P3：dry-run

- 接 Java T1 候选或本地 JSON。
- 查询观察池行情。
- 查询妙想账户。
- 生成完整 PaperRun 和 artifacts。

完成：dry-run 不调用 trade；每个 Intent 可追溯到候选和行情；每个拒绝都有原因。

### P4：人工确认模拟下单

- 实现 run --confirm。
- 逐笔同步 trade。
- 超时先查 orders。
- 下单后查询 orders、positions、balance。
- 生成 reconcile。

完成：交易时间内完成至少一笔测试模拟委托；重复 run 不重复下单；未知状态会冻结。

### P5：连续运行和日报

- 统计配额。
- 增加人工刷新观察池。
- 增加收盘对账。
- 连续运行至少 5 个交易日。

完成：无重复单、无密钥进日志、失败可恢复、差异可解释。

### P6：Java 和前端封装

仅在 P4/P5 稳定后增加 Java Port、PaperRunService、Flyway 审计表、Paper API 和人工确认页面。

### P7：卖出和完整组合调仓

另立需求实现止损、到期、跌出名单、卖出、撤单、部分成交、目标持仓和组合级换手。

## 18. 安全和运行保护

- 日志、CLI 和 UI 明确写“模拟 / paper”。
- Key 只走环境变量或受控本机配置。
- Key 不进入请求日志、异常堆栈和 artifacts。
- 自动循环默认 dry-run。
- V1 不允许定时自动 confirm。
- trade 和 cancel 使用独立命令入口。
- trade、cancel、run --confirm 必须人工确认和审计。
- 请求域名白名单只允许官方基址。
- kill switch 开启时全部买入阻断。
- 查询失败可以有限重试；trade/cancel 超时先对账。
- 外部账户状态 UNKNOWN 时冻结同标的操作。
