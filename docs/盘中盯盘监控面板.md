# 盘中盯盘监控面板

对 `paper/watch` 盯盘引擎的全量分析操作日志做可视化：行情获取 → bar 聚合 → 信号计算 → 买卖点推导 → 风控逐闸 → 下单动作，全程留痕并可回放。

## 数据链路

```
WatchLoop 各环节 emit()
  → logs/paper/watch/<日期>/events.jsonl   （append-only 事件流水，已脱敏）
  → python -m paper.cli watch-serve        （只读 API，默认 127.0.0.1:8790）
  → 前端 /watch/monitor                    （游标增量轮询，3s）
```

## 事件类型

| type | 含义 | detail 关键字段 |
|---|---|---|
| CYCLE | 每轮起止 | phase=start/end, status, bars/signals/submits/errors 计数 |
| QUOTE | 行情快照获取成功 | last, pct_chg, volume, validity |
| QUOTE_FAIL | 行情获取失败 | message |
| BAR_CLOSED | 5 分钟 bar 收盘确认 | open/high/low/close, volume, start_ts/end_ts |
| SIGNAL | 策略信号（含 hold） | action, strategy, detail 内含 MA/MACD/BOLL 过程值 |
| SIZING | 买卖数量推导 | avail_balance×weight→target, affordable, final_qty |
| RISK_GATE | 风控逐闸轨迹 | result, reject_reason, gates=[{gate,result}...] |
| SUBMIT | 下单动作 | status=SUBMITTED/REJECTED/UNKNOWN_SUBMIT/DRY_RUN, order_id |
| ACCOUNT | 提交前后账户快照 | total_assets, avail_balance, positions, open_orders |
| ERROR | KLINE_DISABLED / STOP_RUN / 观察池错误 | scope, message |

## 启动

```bash
# 1. 盯盘（另开终端，默认 dry-run）
cd modules/compute-python
python -m paper.cli watch

# 2. 只读面板 API（只绑定 127.0.0.1，不下单不联网）
python -m paper.cli watch-serve            # 默认 8790，--port 可改

# 3. 前端
cd modules/web && npm run dev              # 菜单「账户 → 盘中盯盘监控」
```

非交易时段打开面板，选历史日期即为当日复盘回放。

## API

- `GET /api/watch/days` — 可用交易日
- `GET /api/watch/{date}/events?after_seq=&code=&type=&limit=` — 事件增量（游标）
- `GET /api/watch/{date}/state` — state.json + 最近一轮 CYCLE
- `GET /api/watch/{date}/ticks` — 每轮 tick 摘要

## 安全边界

- 事件写入前统一过 `sanitize_payload`，不落 API Key / uid / accID 等敏感字段
- watch-serve 纯只读本地文件，默认仅 127.0.0.1，无任何下单端点
- dry-run 事件的 SUBMIT status 为 DRY_RUN，与真实提交明确区分
