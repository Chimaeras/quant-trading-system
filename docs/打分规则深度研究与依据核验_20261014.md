## 0. 结论摘要（先看这一段）

### 0.1 一句话结论

**这套打分规则的工程实现质量明显高于其统计证据质量。** 四项曾被指出的技术指标缺陷里有三项已经修复；代码里充满了主动披露失败原因的设计（`fail-closed`、`degraded`、`skip_reason`、`probability_verified=false`）；但**除了 T+1 次日候选的阈值有真实标定数字（无法复跑）之外，其余六套打分规则的权重和阈值几乎全部是未经验证的先验值**，而系统里唯一一次因子回测的样本量小到系统自己都判定"无效"。

### 0.3 三个最需要关注的发现（按严重度排序）

#### 发现 1【严重】唯一一次因子回测：IC 看起来很好，但有效截面日只有 4 天

数据库 `backtest_run` 表只有 **1 行**（`BT-20260805170807-1266`，2026-08-05 创建）。它的 `factorAnalysis` 输出：

```
rankIcMean = 0.2477   rankIcIr = 1.3069   rankIcPositiveRate = 1.0   longShortSpread = 0.0494
crossSectionDays = 4  totalObservations = 611
```

`rankIcMean = 0.248` 在量化里是**异常高**的数字（业界有效因子通常 0.03~0.06）。但把它拆开看：

| 截面日 | rankIc | 样本量 |
|---|---|---|
| 2026-04-22 | +0.1758 | 10 |
| 2026-05-22 | +0.5636 | 10 |
| 2026-06-30 | +0.1921 | 37 |
| 2026-07-07 | +0.0591 | **554** |
| 合计 | | 611 |

- **611 条观测里 554 条（90.7%）来自同一天**，所以这个 0.248 实质是"某一天的一个数"。
- **有效独立样本 = 4 个交易日**。平均 IC 的 95% 置信区间在这个样本量下无法与 0 区分。
- `rankIcPositiveRate = 1.0` 是 4/4，不是统计意义上的"100% 为正"。

系统**自己**已经判定它无效：

```json
{"t3_effective": false, "t5_effective": false,
 "verdict": "当前样本下 T+3/T+5 Rank IC 不足，公式短周期预测力弱或样本不足",
 "confidence": "低",
 "disclaimer": "IC>0.02 且截面日≥5 仅作启发式阈值，非投资建议"}
```

**这一点值得表扬**：系统没有把这个 0.248 包装成"因子有效"，而是用自己的闸门（截面日 ≥5）把它判为无效并标注置信度低。但这同时意味着：**目前没有任何一套打分规则被这个系统自己的数据证明过有效。**

配套的收益统计同样是负的（`backtest_run.response.holdingPeriodStats`）：

| 持有期 | 胜率 | 平均收益 | 观测数 |
|---|---|---|---|
| T+3 | 47.50% | **−0.587%** | 40 |
| T+5 | 41.03% | **−2.252%** | 39 |
| T+10 | — | — | 40 |
| T+20 | — | — | 30 |

采样区间 `2026-02-05 ~ 2026-08-04`，但 `totalTradingDays = 5`、`dailyDetails` 只有 **5 天**（4-22 / 5-22 / 6-30 / 7-07 / 7-29）。也就是说这个回测实际上不是每日选股，而是**在结果集里挑了几个有 `selector_result` 落库的稀疏日期**。这与 `docs/研究口径规范.md:98` 的自我披露一致："当前回测依赖过去实际保存的 `selector_result`，信号日稀疏 → QP-007 将建历史逐日重放"。

#### 发现 2【严重】成本口径在数据库里没有被记录，且从未做过概率校准

- `backtest_run.net_cost_convention_version = **NULL**`
- `commission_rate = sell_tax_rate = slippage_rate = **0E-8**`（全零），而同一行的 `assumptions` JSON 里却写着 `commission_rate: 3.0E-4, sell_tax_rate: 5.0E-4, slippage_rate_each_side: 2.0E-4`。
  → **声明与落库不一致**。成本到底是"按 assumptions 声明计算但没写进成本列"，还是"根本没按净成本算"，从这一行无法判别。
- 可靠性正面的证据：代码里成本模型本身是对的且被测试钉死。`FactorResearchEngineCostBasisTest` 断言单腿往返成本必须是**乘性复合** `(1−滑点)(1−佣金−印花税)/((1+滑点)(1+佣金))` ≈ **15.0bp/腿（往返约 30bp）**，并显式断言"加性读法漏掉卖出腿佣金，主项差恰为 −3.00bp"。这个测试质量很高。
  → 结论：**成本算法可信，成本记录不可信**。
- `calibrator_registry` 表 **0 行**、`prediction_run` 表 **0 行**、`prediction_snapshot_item` 表 **0 行**、`portfolio_backtest_run` 表 **0 行**。
  → 那个"从 Score 90 升级为经样本外校准的 P(T+2上涨)"的目标（`docs/短周期概率选股系统优化迭代规划_20260730.md:18`）**一次都没有执行过**。
- `selector_result.ic_value` 非空 **0/72 行**，`ir_value` 非空 **0/72 行**。这与 `docs/研究口径规范.md:254-265` 的自我披露一致：该列是**死列**，全仓无写入路径。文档甚至写明"禁止把该列当作 IC/ICIR 的任何载体"——**这是主动披露，值得肯定**。

#### 发现 3【中】"排除 ST"在实证输出里没有生效，且有原始实现缺陷

`assumptions.selector_tradability.exclude_st = true`，但唯一那次回测的选股明细 43 行里有 **2 行是 ST 股**：

```
2026-05-22  rank=2  600360  *ST华微    finalScore=60.37
2026-05-22  rank=8  002529  *ST海源    finalScore=56.63
```

根因不是"漏了过滤"，而是 `ScoringUtils` 里 ST 排除的实现方式（子 agent 提取的原始代码）：

```java
// ScoringUtils 中 ST 排除分支：行情表没有名称字段就整体放行
if (name == null || name.isBlank()) { return; }   // 不排除
if (name.contains("ST")) { ... 排除 ... }
```

`docs/研究口径规范.md:97` 已经自我披露过这个数据缺陷："`stock_info` 主要是当前名称/状态，历史 ST/退市/行业变更非 PIT → QP-004 将建历史证券主数据"。所以这是**已知问题**，但本次核验的增量价值是：**它已经污染了唯一的实证输出**——那唯一一次回测的 TopN 里就有 ST 股。

（对照：成交约束是**真的**在披露，不是空话。明细里出现了 `h3:LIMIT_DOWN_AT_CLOSE` × 3、`h20:BEYOND_CALENDAR` × 13 等跳过原因，与 `docs/研究口径规范.md:65-77` 的"不得删除样本，必须按成交状态单独记录"一致。）

## 3. 逐方法核验

### 3.1 经典多因子（CLASSIC_SELECTOR）

#### 3.1.1 实际公式（medium 默认路径）

`ClassicFactorCalculator.java:203-204`：

```java
finalScore = weightTrend() * trend + weightMomentum() * momentum
        + weightVolume() * volumeScore - weightRiskPenalty() * riskPenalty;
```

权重默认值（`ScoringProperties.java:66-69`，YAML 中**无** `classic-factor` 节点，故运行时恒为默认值）：

| 维度 | 权重 | 位置 |
|---|---|---|
| trend | 0.35 | `ClassicFactorCalculator.java:46` |
| momentum | 0.20 | `:50` |
| volume | 0.20 | `:54` |
| riskPenalty | **−0.25（减项）** | `:58`，应用在 `:204` |
| **权重和** | **1.00** | — |

四个子分数：

```java
// trend  (ClassicFactorCalculator.java:182-186)
trend = clamp( (ma20 > ma60 ? 35 : 0)
             + clamp(ret20, -10, 25)
             + 0.5 * clamp(ret60, -15, 35), 0, 100 );

// momentum  (:188-193)
momentum = clamp( clamp((rsi14 - 40) * 1.5, 0, 35)
                + clamp((macdHist / price) * 40000, 0, 35)
                + clamp(volumeRatio * 12, 0, 30), 0, 100 );

// volume  (:195-196)
volumeScore = clamp( (avgAmount20 / minAvgAmount) * 60 + volumeRatio * 20, 0, 100 );

// risk  (:197)
riskPenalty = clamp( vol20 * 1.5 + mdd60 * 1.2, 0, 100 );
```

#### 3.1.2 依据评估

**方向有依据（C 级）**：
- trend 用 `ma20 > ma60` 判趋势方向 + `ret20`/`ret60` 动量，这是标准趋势跟踪构造。
- risk 用 20 日波动 + 60 日最大回撤，与"低波动异象"和"回撤惩罚"方向一致。
- momentum 用 RSI 与 MACD 柱状值 —— 这是**技术分析**而非学术因子，见 §5 对 RSI 的评估。

**魔数无依据（这是主要问题）**：

| 魔数 | 位置 | 问题 |
|---|---|---|
| `40000` | `:191` | `macdHist/price × 40000` —— 乘以 4 万倍纯属把量纲拉到 0-35 区间，**没有任何标定** |
| `×1.5` / `×12` / `×60` / `×20` / `×1.5` / `×1.2` | 各处 | 全部是把原始值映射进 0-35/0-100 的**缩放系数**，无一个来自标定 |
| `trend` 中 `35` 分的一次性加分 | `:183` | `ma20 > ma60` 是布尔量，却给 35 分（占 trend 理论上限 77.5 的 45%），这个比例无依据 |
| `ret20` 截断 `[-10, 25]` | `:184` | 截断点无依据 |

**注释与代码不一致（2 处，已确认）**：

| 位置 | 声明 | 实际 |
|---|---|---|
| `ClassicFactorCalculator.java:12` | 类注释"趋势40% + 动量25% + 量价20% - 风险15%" | medium 用 0.35/0.20/0.20/0.25 |
| `StrategyFormulaRegistry.java:101` | `final = 0.40×shortHorizon + 0.25×momentum + 0.20×volume - 0.15×risk` | `ClassicFactorCalculator.java:35-40` 用 `SHORT_W_RISK = 0.25`，且正权重除以 0.85 归一化 |

#### 3.1.3 硬门槛

打分前置（任一不满足返回 `Optional.empty()`）：

```java

isSignalBarOnTradeDate(bars, tradeDate)              // :136，必须等于 signal date
```

#### 3.1.4 短周期 Codex 变体

`horizonProfile = SHORT_3_5D` 时，`StockSelectorService.java:65,188-223` 会把请求**整体转交** `CodexShortCycleScoringEngine`：

```
S_raw = (0.55 + 0.10·G)·T + 0.20·F + (0.25 − 0.05·G)·R + 0.05·T·tanh(F)
Score = 100 × PercentileRank(S_raw)
```

其中 `T = 0.28·Z(ER20−ER5) + 0.20·Z(ER5) − 0.15·Z(ER1) + 0.17·Z(MAAlign) + 0.10·Z(RSIShape) + 0.10·Z(VolConfirm)`（`:407-413`）。

**这是全系统设计最讲究的一条公式**，因为它是唯一做了**截面中性化**的：
`winsorize(2.5/97.5) → OLS(x ~ 1 + lnMV + 行业哑变量, ridge=1e-4) → robustZ(MAD, clip ±3)`（`CrossSectionNeutralizer.java`）。
中性化是学术因子检验的标准做法，说明作者知道"原始财务/规模指标必须先剔除市值和行业影响"。

**但有两个实现级问题**：

1. **`isReliableLogMvSource` 恒返回 `false`**（`CrossSectionNeutralizer.java:71-74`），`isReliableMarketCapReliability` 只认 `"OFFICIAL"`（`:84-86`）。只要"不可靠样本 ≥ 半数"（`:155-167`）就**整体跳过市值中性化**（mode = `SKIPPED_MV_RELIABILITY`）。也就是说：**市值中性化在多数字场景下可能根本没执行**。这直接决定了 `F`（质量估值因子）是否真的剥离了规模效应。
2. **Classic 的 shortProfile 分支在服务层不可达**（`ClassicFactorCalculator.java:176-214` 只在单测中被触发），但 `StrategyFormulaRegistry` 仍把它当作正式路径描述。这是**代码与文档的契约不一致**。

**系数和不为 1**：G=1 时 `(0.55+0.10) + 0.20 + (0.25−0.05) + 0.05 = 1.10`。加权和不为 1 本身不是错（后面还要取百分位），但意味着"G 越大总分整体越高"，即**牛市里所有股票分数系统性抬升**，这会让跨市场状态的分数不可比。

#### 3.1.5 经典多因子的证据等级：**C**

理由：方向和构造方法（趋势/动量/量能/风险四维 + 截面中性化 + 百分位）与国际因子投资实践一致，属**有依据**；但 0.35/0.20/0.20/0.25 这四个权重、以及所有缩放魔数**从未用本项目数据标定过**，唯一一次回测的截面日只有 4 天。

#### 3.2.1 实际公式

#### 3.2.2 依据评估

**这条规则的依据最强（C 级，接近 B 级方向）** —— 因为"超跌反弹"对应的是 A 股最被实证支持的因子之一：**短期反转**。文献上有大量 A 股证据：

- [Only strong short-term contrarian effect exists in Chinese stock market: The role of the T+1 trading mechanism](https://www.sciencedirect.com/science/article/abs/pii/S1059056024006452)（*International Review of Economics & Finance*, 2024）—— 直接研究 T+1 制度如何造成 A 股的不对称反转，与"超跌后反弹"机制高度相关。
- [Positive feedback trading, the T+1 rule, and asymmetric return reversals in China](https://www.sciencedirect.com/science/article/abs/pii/S0264999326003123)（*Economic Modelling*）—— T+1 导致正反馈交易与非对称反转。
- [Short-Term Reversal in Chinese A-Shares: Statistical Predictability, Economic Tradability, and Multiple Testing](https://zenodo.org/records/20520536) —— 标题即点出"A 股短期反转"三个必须同时回答的问题：**统计可预测性、经济可交易性、多重检验**。

特别值得注意的是这三点正好对应本项目缺的东西：有"统计可预测性"方向的设计，但**没有经济可交易性验证**（唯一回测平均收益为负），也**没有多重检验校正**（见 §5.3）。

**具体规则的依据强弱**：

| 规则 | 依据 | 判定 |
|---|---|---|
| `ret60 <= -20 → 15分` | 中期跌幅作为反转前提高度符合文献 | ✅ 合理，但 -20/-10/-5 三档切点无标定 |
| 周K连续阴线 ≥5 → 10分 | "连续下跌"概念合理，但**用周K而非日K**、且"5周"这个阈值无依据 | ⚠️ 弱 |
| 量比 >0.8 → 15分（缩量筑底） | "缩量止跌"是常见技术分析说法，**但学术上换手率与未来收益通常呈负相关**（见 §5.2）。给缩量加分、且权重占 volume 的 60%，**方向可能与文献相反** | ❌ 存疑 |
| RSI <30 → 10分 | 均值回归方向合理；但 RSI 本身的独立预测力存疑（§5.4） | ⚠️ 弱 |
| 布林下轨 2σ/3.5σ | 2σ 是标准；**3.5σ 这个"极端超跌"阈值无依据** | ⚠️ 弱 |
| 252 日分位 <0.10 → 10分 | 位置类因子，合理 | ✅ |
| 无确认封顶 70 | 是有意的风险控制设计，逻辑自洽 | ✅ |

#### 3.2.3 值得肯定的地方

- **Java 与 Python 实现一致**（这是既有文档断言"不一致"但其实已修复的项）。`engines/oversold_rebound_scorer.py:219-226` 与 Java `:638-641` 权重、70 封顶、子规则切点全部对齐。

#### 3.2.4 超跌反弹的证据等级：**C**

理由：策略方向（短期反转）有强文献支持，是七套里理论基础最扎实的；Java/Python 一致性也已修复。但**子项阈值无一标定**，且"缩量加分"方向可能与换手率文献相悖。

### 3.6 T+1 次日候选（唯一有标定的规则）

#### 3.6.1 实际公式

`T1CandidateService.java:900-908`：

```java
double score = 0;
double ret5 = ind[1];
score += Math.max(-15, Math.min(20, ret5 * 100 * 0.4));    // 短期动量
double vr = ((Number) lu.getOrDefault("volume_ratio", 0)).doubleValue();
score += Math.max(-10, Math.min(15, (vr - 1) * 10));       // 量能（量比）
score += Math.max(-10, Math.min(15, ind[2] * 15));         // 趋势位置 (close/ma20 − 1)
return Math.max(0, Math.min(RULE_SCORE_MAX, score));       // RULE_SCORE_MAX = 50.0
```

| 因子 | 项内公式 | 值域 |
|---|---|---|
| 短期动量 | `clamp(ret5*100*0.4, −15, 20)` | [−15, 20] |
| 量能（量比） | `clamp((vr−1)*10, −10, 15)` | [−10, 15] |
| 趋势位置 | `clamp((close/ma20 − 1)*15, −10, 15)` | [−10, 15] |
| **合计** | clamp 到 **[0, 50]** | |

**`rule_score` 不是概率，代码反复声明：**
- `T1Candidate.java:15-16`："0–50 的 rule_score，**非概率**"
- `T1CandidateService.java:44-45`："输出为 rule_score（0-50，截面排序用，非概率）"
- 每条候选写标 `score_type = "RULE_SCORE"`、`is_probability = false`

这与 `docs/研究口径规范.md:29` 的强制规定一致："`CodexShortCycleScoringEngine` 输出的 `rule_score`（0–100 截面百分位）**不是**上涨概率，前端/接口不得标记为「上涨概率」"。

**数据库实测**（最新快照 `2026-10-13`）：4 条候选，`score_type = RULE_SCORE`，`is_probability = False`，`rule_score` 范围 **31.4156 ~ 40.6653**（均值 35.1483）。

#### 3.6.2 阈值标定（唯一的实证依据，但不可复跑）

## 5. 与公开研究的对照（哪条有依据、哪条没有）

### 5.1 短期反转（支撑"超跌反弹"，最强的一条）

A 股短期反转有大量文献支持，且**机制被归因于 T+1 制度**（当日买入次日才能卖，导致正反馈交易与不对称反转）：

- [Only strong short-term contrarian effect exists in Chinese stock market: The role of the T+1 trading mechanism](https://www.sciencedirect.com/science/article/abs/pii/S1059056024006452)（*International Review of Economics & Finance*, 2024）
- [Positive feedback trading, the T+1 rule, and asymmetric return reversals in China](https://www.sciencedirect.com/science/article/abs/pii/S0264999326003123)（*Economic Modelling*）
- [Short-Term Reversal in Chinese A-Shares: Statistical Predictability, Economic Tradability, and Multiple Testing](https://zenodo.org/records/20520536)

**对本项目的意义**：`超跌反弹` 策略方向正确。但注意第二篇的点：**经济可交易性（economic tradability）** 必须单独验证 —— 本项目唯一回测的 T+3 平均收益是 **−0.587%**，正说明"统计上可能有反转，但扣掉成本后不一定能赚钱"。这也解释了为什么 `research_convention_v1` 要把成本设成 30bp 往返（乘性 15bp/腿）。

### 5.2 换手率与成交量（"超跌反弹"缩量加分的方向存疑）

- [Does the turnover effect matter in emerging markets? Evidence from China](https://gimikatalogus.elte.hu/PrimoRecord/cdi_crossref_primary_10_1016_j_pacfin_2021_101551)（*Pacific-Basin Finance Journal*, 2021）
- [Extreme volumes and expected stock returns: Evidence from China's stock market](https://smusg.elsevierpure.com/en/publications/extreme-volumes-and-expected-stock-returns-evidence-from-chinas-s/)（SMU）
- [Trading on trends: How the ordering of historical volume predicts Chinese stock returns?](https://www.sciencedirect.com/science/article/abs/pii/S1057521924004502)（*International Review of Financial Analysis*, 2024）
- [Ownership acceleration and the volume volatility-return link: Evidence from China](https://www.sciencedirect.com/science/article/abs/pii/S0927538X25002434)

**对本项目的意义**：
- 换手率效应在 A 股是**负向**的（高换手 → 未来收益低）为主流结论。
- 但 `超跌反弹` 的 volume 维度给**缩量**加分（量比 >0.8 → +15），而 `趋势打分` 的 `scoreTurnover`（`ScoringRules.java:355-368`）给**换手率 3-8% 且上涨 → 5 分**、**换手率 >15% → 0.5 分**。两者对"高换手"的态度一致（都降权），这点与文献方向不矛盾。
- 不过**量比 >0.8 就给满 15 分**这个切点极宽松（量比 1.0 是均值，0.8 略低于均值），意味着 volume 维度**几乎所有超跌股都能拿满 15 分**，区分度很低。这是一个**可被快速证伪的具体问题**（见 §6 验证清单 V-3）。

### 5.3 多重检验（本项目最大的方法论缺口）

上面 §5.1 第三篇文献的标题点出了三件事，其中"**Multiple Testing**"是本项目完全缺失的一环。

本项目的规则数量：
- 趋势打分 **12 个子项**（每个 3-8 个分支）
- 超跌反弹 **4 个子项** × 各 3-10 个分支
- 经典多因子 **4 个子项** + Codex **6 个 T 因子 + 4 个 F 因子 + 4 个 R 因子**
- 综合三维度 **3 维 × 各 3 子项**
- 多维度 **5 维**

保守估计**上百个阈值/权重**是在同一份数据上被选择或调过的。在这种情况下，即使所有规则都无预测力，也很容易撞出"看起来显著"的组合。而系统对有效性的判定标准是：

```
"IC>0.02 且截面日≥5 仅作启发式阈值，非投资建议"   // shortHorizonValidation.disclaimer
```

**这个标准没有做任何多重检验校正，也没有样本外留出（hold-out）。** 二次验证时必须把这一点作为首要质疑对象。

### 5.4 RSI 的独立预测力（支撑"RSI 因子"的证据偏弱）

- [Volatility vs Strength of Trend: A Duration-Based Analysis of RSI in Malaysian Stocks](https://mysitasi.mohe.gov.my/uploads/get-media-file?refId=37f6b418-d79a-4d5d-a890-dcb2cf632e5c) —— 研究 RSI 的预测力，结论偏向"RSI 的强度与趋势持续期相关"而非"RSI 水平直接预测收益"。
- [Levels: una arquitectura fuzzy para la clasificación y predicción de reversiones en mercados financieros mediante el sistema de niveles dinámicos RSI](https://zenodo.org/records/16732669)（2025）—— 尝试把 RSI 做成模糊分类器，本身说明**原始 RSI 阈值不够用**。

**对本项目的意义**：RSI 在四套规则里被当作核心因子（趋势打分的 8 分、超跌反弹的 10 分、综合三维度的 7 分、经典多因子 momentum 的 35 分中占 `clamp((rsi14−40)*1.5, 0, 35)`），但 **RSI 的独立预测力在文献上证据薄弱**，且 RSI 与动量/反转高度共线。经典多因子把 `(rsi14−40)*1.5` 直接当 momentum 的主要成分，可能是**用 RSI 代理动量**，这不如直接用收益率动量干净。

### 5.5 我未能核验的（诚实披露）

以下我有疑问但**没有找到可靠公开依据**，因此不给出结论，只标注为二次验证时应查的项：

1. **A 股"缩量筑底后放量反弹"是否有实证支撑**（对应 `SHIRNK_THEN_WARM_EXPAND` +5 分）。我检索到的量价文献主要讲"极端成交量""换手率"，未找到直接检验该形态的证据。

3. **布林带 3.5σ 作为"极端超跌"阈值** 的出处（2σ 是标准，3.5σ 未见来源）。
4. **行业偏好加分（银行 +2.5 / 新能源 +2.0）** 的任何依据。我怀疑这是凭经验拍的。

6. **`macdHist/price × 40000`** 这类缩放系数的合理性。

### 6.1 前置约束（不要违反）

| ID | 验证目标 | 具体做法 | 判定标准 |
