## 本轮已完成的关键修改

- `account_scope_registry`：账户作用域为 `execution_mode:session_id`；同名 session 可隔离保存内部/外部数据，旧作用域存在危险中间态时禁止切换。
- `account_sync_state`：外部查询失败只更新错误状态，不删除/清零最近成功快照。
- `external_order`：以 `channel + session_id + broker_order_id` 唯一；保存柜台原态、规范化状态、累计成交、剩余量、均价证据、来源及同步时间。
- 外部成交只按累计成交增量落一次；严格解析 `tradePrice` 时标记 `MX_ORDER_AGGREGATE`，否则用委托价并标记估算；费用未知由 API 返回 `null`。
- 妙想状态 7（部撤）不再算活动委托；4/7/8/9 等终态均不计入在途，10/UNKNOWN 保持风险冻结。
- `watch-serve` 只读启动不再加载交易配置；INTERNAL_PAPER + 公开行情/K 线可在没有 `MX_APIKEY` 时启动。
- 共享前端组件每 5 秒只读取本地投影，显示账户来源、同步时间、新鲜度、持仓、委托、成交、收益和未知字段降级。

## 已确认现状

- 原有 Java `SimAccountService` 是历史演练/手工模拟账户，不能作为盯盘成交的并行写入端。
- Python 已有 `local_order`、`fill`、`account_snapshot`、`sim_account`、`sim_position`，但部分查询仍只以 `session_id` 为范围。
- 外部账户快照已经由 WatchLoop 落库，但 watch-serve 的账户和收益读取仍偏向内部 `sim_*` 表。
- 外部委托没有完整的独立镜像投影，终态委托与外部未关联委托无法稳定、去重地展示。
- `PaperConfig.from_env()` 当前无条件要求 `MX_APIKEY`；内部模式和只读 watch-serve 需要解耦。
