# 深度审查与修改计划 R33（2026-09-11）

## 一、本轮范围与方法

R1–R32 已覆盖 N+1 查询、事务边界、线程池拒绝策略、异常映射、跨端口径对齐、幂等键、并发锁、竞态守卫、原子写等类别。本轮**刻意换面**，只审此前从未系统审过的五个维度：

1. **数据库 schema 与 Flyway 迁移一致性**（`ddl-auto: validate` 的实际覆盖面、索引、精度、唯一约束）
2. **前端认证/路由守卫/HTTP 传输层**（此前只审视图层）
3. **Python 盯盘 OMS 状态机 + 内部撮合账务数学 + 重放确定性**
4. **watch-serve HTTP 服务层 + 运维脚本 + 部署配置**
5. **Java 应用生命周期/启动顺序 + 入参校验完整性 + 查询与字符串构造安全**

方法：5 路并行深审 → **逐条读源核验**（本轮代理误报 3 条与 2 条重复报告项被剔除，见第三节）→ P1/P2/P3 分级 → 修复 + 回归测试。

### 一个贯穿本轮的观察

本轮 6 条 P1 里有 4 条**不是代码写错，而是"两个必须一致的地方悄悄不一致了"**：

- 迁移建了 `top_n`，实体映射出 `topn`；
- 前端路由有 `/research/*`，SPA fallback 前缀列表没有；
- Python 流水线改成 `30_000_000`，同一条流水线的 PowerShell 版本还是 `30000`；
- 策略/风控层允许零股卖出，撮合层把零股数量取整成 0。

这类缺陷的共同特征是**没有任何一侧报错**，只在特定入口（全新装库、生产刷新、双击 .bat、账户有零股时）静默走错。它们也不会被现有测试拦住——因为测试覆盖的是"被调用的函数"，不是"两侧的契约"（R32 已因此吃过一次亏，本轮又出现 4 次）。

## 三、判废 / 已判定项（不修改，附理由）

- **判废（代理 P2）：「重复成交时仍无条件落盘账户快照 → 二次记账」**。位置与机制判断正确（`internal_broker` 先就地改内存账户，再由 `apply_internal_execution` 按 `fill_id` 幂等，最后**无条件** `save_simulation`）。但该条**在 R31 已登记为暂缓并明确判定「受 bar checkpoint 门控，当前不可达」**——`process_bars` 只处理新闭 bar，同一 `client_order_id + bar.end_ts` 不会二次进入。按「不重复处理已判定项」的约定，本轮不改，继续保留登记。
- **判废（代理 P2）：「`docker-compose` 未接线 watch-serve → 监控页全 502」**。现象成立，但**不存在可用的配置级修法**：watch-serve 为安全起见只允许绑定回环地址（`serve()` 显式拒绝非 `127.0.0.1/localhost/::1`），因此容器内经 `host.docker.internal` 访问宿主会因宿主侧回环绑定而失败；正确解法是在 compose 网络内为 Python 侧新增独立服务与镜像（且需评估把交易状态端口暴露到 bridge 网络后的鉴权面），属部署形态变更，登记暂缓。本轮只修其中确定错误的一处（健康检查探错接口，见 P2-3）。
- **判废（代理 P3）：「`StockInfoRepository.search` 的 LIKE 未转义 `%`/`_`」**。查询本身是参数化的（`concat('%', :keyword, '%')` 由 Hibernate 生成绑定参数），不存在注入；`keyword=%` 的后果只是「命中全部行」，而结果集受分页上界约束。属加固项，登记不改。
- **已核查无问题**：`ddl-auto: validate` 下实体与 V1–V22 的列覆盖/类型族（除上述 `topN` 一处，全量脚本比对通过）；全库无 `FOREIGN KEY` 但删除路径无「删父留子」孤儿行；唯一约束与实体 `uniqueConstraints` 无双真源；字符集统一 utf8mb4；SQL 注入（全部命名参数，唯一动态拼接仅 int 类型的 `days/limit`）；路径遍历（`ModelImportService.readControlledLocal` 拒 `..`/绝对路径/盘符；serve 侧日期需匹配 `DATE_RE` 且必须在实际目录列表内）；前端开放重定向（`//evil.com` 经 vue-router `createWebHistory` 归一为同源路径）、403 与 401 不混淆、守卫 deny-by-default、axios 链路 errorId 透传、`code!=200` 严格拒绝；`@PostConstruct` 不抛异常；请求路径上的 IO 均 try-with-resources；前端路由守卫漏保护、GET 数组序列化、响应解包一致性、Pinia 竞态（`reqSeq` 守卫）。

## 四、暂缓（需产品/运维决策或结构性改造，已登记）

1. **`portfolio_*` 系列金额列用 `DOUBLE`**（`initial_cash/final_nav/price/amount/commission/stamp_tax/nav/unrealized_pnl`）：组合回测逐调仓日累加，浮点误差随天数放大、回测不可复现。V11 已把 `backtest_run` 的费率列修为 `DECIMAL`，但 V9/V20 的新表未同步。改法需迁移 + 实体改 `BigDecimal` + 全部计算路径改造，属独立一轮的工作量。（代理 A-P2-5）
2. **Python 内部撮合与 Java `SimAccountService` 记账口径不一致**：①费用取整（Python 全程不取整，Java 逐笔 `HALF_UP` 到分）；②买入佣金是否进持仓成本（Python 计入 `avg_cost`，Java `costPrice = execPrice` 不含佣金）。同一笔交易两端展示的成本与已实现盈亏不同，**需先确定以哪端为权威口径**再对齐——单方面改会改变用户可见的账务数字。（代理 C-F9）
3. **跨日滚动静默丢弃未对账的 `unknown_submits`**：`state.py` 在 `trade_date` 不匹配时返回全新 state，`_live_halted` 又是内存态，重启即清空；若该单实际已成交而本地从未记账，次日起本地与柜台静默背离且无任何残留告警。正确解法要与 OMS 过期语义、审计表一并设计（只是"携带到次日"会让早盘继续冻结）。（代理 C-F4）
4. **`reconcile_day` 只比对柜台侧**，不做本地 OMS/账户交叉核验，也不解除任何冻结；因此"对账通过"不等于本地账务与柜台一致。属覆盖面缺口（非当前错误路径），需先定义交叉核验的差异分类。（代理 C-F8）
5. **启动恢复无实例归属**：孤儿任务判定用的是数据库全局状态（`WHERE status='RUNNING'`），多实例/滚动重启会把**另一实例正在跑**的任务标成 FAILED 并重排。当前 compose 为单副本故不可达，需引入 owner/租约字段。（代理 E-P2-2）
6. **`baseline-on-migrate: true` 未配 `baseline-version`**：存量库（早期由 Hibernate 建表）以 version=1 打基线后**永不执行 V1**，于是 V1 定义的索引/唯一键在新装库与升级库之间静默分叉（V4 只收养了两张表的索引名）。改 `baseline-version: 0` 会让存量库重跑 V1，需先确认 V1 全部语句幂等，属运维决策。（代理 A-P3-3）
7. **compose 弱口令默认值与端口暴露**：`MYSQL_ROOT_PASSWORD: ${DB_PASSWORD:-123456}`、后端同样默认 `root/123456`、`3306:3306` 发布到宿主所有网卡。改为必填/仅绑 `127.0.0.1` 会打断现有"不改 .env 直接 up"的用法，属运维决策（R32 对同类「鉴权关闭」问题亦只加醒目 WARN 未硬失败）。（代理 D-P2-5）
8. **仓库跟踪了审计产物**：`docs/paper-captures/2026-08-18_capture.json`（真实账户余额/持仓/委托原文）、`quant-trading-system-startup.log`（18MB）、`output/scoring/**` 均被 `git ls-files` 跟踪，`.gitignore` 只匹配 `*_capture_raw.json` 故漏掉实际文件名。**已进入历史，删除只能防止继续恶化**；且这些文件非本轮产生，是否继续跟踪属用户取舍，故只报告不执行（建议 `git rm --cached` + 补 `.gitignore`：`.env*`、`*.log`、`output/`、`docs/paper-captures/*_capture*.json`）。（代理 D-P3-6）
9. **`@Query` 的 `LIKE` 通配未转义**（见第三节判废）；**`DataInitializer` 首启非原子**（单副本不可达）；**`enableScheduling` 之外的启动期 `Files.walk` 未关闭**（一次性，句柄泄漏级）；**前端 token 无本地过期校验**（后端 `JwtService` 已校验 exp，仅表现为过期后延迟到首个私有请求才踢出）、**多标签页无 `storage` 事件同步**（下次请求即自愈）。
