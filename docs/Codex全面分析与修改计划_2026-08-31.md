#### P1-5 ClassicFactorCalculator 质量闸绕过 + 流动性量纲
- **证据**：`ClassicFactorCalculator.java:208` `passMinTrendScore = shortProfile ? shortHorizonScore >= 35 : trend >= minTrendScore;` 短周期分支**把配置的 `minTrendScore` 硬编码成 35**（质量闸绕过；当前路由把短周期转 codex 引擎故此分支近死路，但存在泄漏风险）。`:196` `(avgAmount20 / Math.max(1, minAvgAmount)) * 60` 与 `:174` `volumeRatio = amount.get(size-1) / Math.max(1d, avgAmount20)` —— `Math.max(1, ...)` 把 <1 阈值压成 1、把阈值当无量纲，需与 `amount` 同单位；单位错位时流动性子分或饱和到 60 或近似为 0，信息量低。
- **影响**：阈值被绕过 / 流动性子分失真。
- **修复**：短周期分支尊重配置阈值（或显式路由/死分支注释）；修正 `Math.max(1, minAvgAmount)`/`Math.max(1d, avgAmount20)` 量纲与 0/负阈值防护；补单元测试。
- **【已处理 2026-08-31】** (a) `:208` 短周期质量闸从硬编码 `shortHorizonScore >= 35` 改为 `shortHorizonScore >= minTrendScore`，尊重配置阈值，避免路由改动时放行不合格股；(b) `:196` 流动性分从 `avgAmount20/Math.max(1,minAvgAmount)*60` 改为 `minAvgAmount>0 ? (avgAmount20/minAvgAmount)*60 : 0`——未配置门槛（minAvgAmount<=0）时不再因除数为 1 而饱和到 60，与 `ScoringUtils.passesMinAvgAmount` 的 `minAvgAmount<=0` 放行语义对齐；(c) `:174` `volumeRatio` 从 `Math.max(1d, avgAmount20)` 改为 `avgAmount20>0 ? 当日额/avgAmount20 : 0`——avgAmount20=0 时归 0 而非按 1 元分母爆大。新增 2 个回归测试：短周期尊重 minTrendScore（高阈值拒、0 阈值过）、minAvgAmount 未配置时 volumeScore 不饱和 60。注意 `minTrendScore` 默认 0（UnifiedScoringService:894），普通分支 `trend>=0` 恒真，行为不变。
- **风险**：中。**验证**：`mvn test` 全套 302 通过（300 + 2 新增）。
