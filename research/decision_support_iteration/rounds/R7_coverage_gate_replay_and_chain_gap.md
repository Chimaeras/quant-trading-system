## 3. 幸存者偏差与前视：可测性界定

### 3.1 幸存者偏差：不可测（`survivorship_probe.py`）

| 事实 | 值 |
|------|-----|
| `market_data` 键数 | 5,839 |
| `stock_info` 键数 / 其中 `status=1` | 5,835 / 5,835 |
| **`market_data` 键中不在 `stock_info` 的** | **4**（`001257\|SZSE`、`001312\|SZSE`、`603293\|SSE`、`603459\|SSE`） |
| `stock_info.status` 为 NULL / ≠1 的行数 | 0 / 0 |
| `stock_info` 是否有退市相关列 | **否**（列：id, stock_code, stock_name, exchange_type, exchange_type_name, industry, sector, list_date, status, total_shares, circulating_shares, created_at, updated_at） |

**含义**：行情库中每一个键**都是当前在市标的**。期内已退市标的的行情
**整体不存在**，且主表无退市字段。

⇒ 这也解释了为什么离线评价的 `drop_reasons` 里
`NOT_IN_UNIVERSE` / `NOT_YET_LISTED` **都是 0**（不是没丢，而是没有可丢的对象）。

**结论**：幸存者偏差**存在但无法用本地数据量化**——
它不是「被过滤掉了 N 行」（可计数），而是「从未存在」（不可计数）。
所有离线收益数字都**不能**声称已消除该偏差。

### 3.2 前视 ST 过滤：**已确认的自身方法学缺陷**

`offline_eval.py:205`：

```python
px["is_st"] = px["name"].fillna("").str.upper().str.contains("ST")
```

`name` 来自 `stock_info`（**当前**截面，`offline_eval.py:120`）。
⇒ 用 **今天** 的股票名去过滤 **2026-01..08 的历史日**：
一只 2026-07 才被实施退市风险警示的股票，其 2026-01 起的**全部**行都会被 `drop(..., "ST")` 剔除。

**这是「用未来信息剔除未来输家」**：方向是**乐观**的（剔除了后来的差标的）。

**量级已界定**（`halted_codes_profile.py`）：评价窗口内中途停止交易的 23 个代码中，
**20 个当前名称为 `*ST`/`ST`**（如 `000004 *ST国华`、`002808 *ST…`）。
这 23 个代码因为 ① 当前名字含 ST、② 在窗口内提前停止交易导致 `bars_in_window < 30`，
被**双重**排除 —— 在评价的**任何一天**都不可被选中。

⇒ **前视 ST 过滤确实存在，但其可影响范围已被限制在「当前 ST 名单」之内，
且这批标的本来就因数据不足而不可选。**
因此它**不改变**已有的收益结论，但**必须**作为局限披露。

**处置（本轮）**：因 `stock_info` 无 `status` 历史、也无历史 ST 名单，
**无法在本地修复**；不做任何猜测性改动。已写入局限清单（见 §5）。

### 3.3 不可成交剔除：量级很小

`offline_metrics.py:120` 用 `tradable = sub[~sub["unfillable"]]`
把「次日一字板 / 次日无数据」的选股**整体剔除**后再算均值。
已存档结果中 B0（生产规则 Top10）为：

```
total_picks = 215,  total_unfillable = 3,  unfillable_ratio = 0.01395 (1.40%)
```

3/215 ⇒ 对均值的直接影响 **< 0.02%**（即使 3 个全按 −10% 计），
**不构成实质偏差**。方向亦不确定（一字板是错过盈利，停牌可能伴坏消息）。

## 7. 本轮的一处生产代码改动（仅注释，无行为变化）

第 2 轮发现的 L4（注释归因不完整）在本轮顺手修正：
`T1CandidateService.java:188-196` 的覆盖率闸注释此前把
「分母键 ∖ 当日有 bar 的键 ≈ 358」**只**归因于「284 个双 exchange_type 代码」。
本轮回放的隐含验算表明该归因不成立：

- 修正口径下 `expected_NEW = |主表键 ∩ 活跃键|`，而 `当日 bar 数` 恰好 ≈ `expected_NEW`
  （如 2026-08-11：expected_NEW=5,462 = 当日 bar 5,462）；
- 正因如此 `coverage_NEW ≈ 0.997 < 1.0`；
- 而「284 个双 exchange 代码」**两个键都有 bar**，属于 `covered`，**不构成**这 358 的缺口。

注释已改为如实区分两部分：284 个迁移遗留（**不构成缺口**）与
约 358 个「在主表中但 [T-60d, T] 内无任何 bar」的键（**才是缺口**）。

**该改动是纯注释**，不改变任何执行路径；已回归 **18/18 通过、BUILD SUCCESS**。
