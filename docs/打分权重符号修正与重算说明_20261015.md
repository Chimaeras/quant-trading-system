## 3. 必须随结论一起读的局限

1. **样本仅约 1 年**（2025-10-13 ~ 2026-08-31），且市场环境**不同质**
   （横截面成员在 2026-02 与 2026-04 两次跃升：约 3,620 只 → 约 5,462 只）。
2. **"负 IC"可能是该年度的风格**，不能保证外推到其他市场环境。
   本修正是"在这个样本上符号一致"的**必要条件**，不是充分条件。
3. 这是**符号修正，不是权重优化**。权重数值仍是原文档结构的映射值。
4. **未提高区分度**：Q5−Q1 仅 3.85 pp，故**不能当上涨概率用**（见阶段5）。
5. 阶段5 已证：校准后的 Brier（0.25396）**不如**常量基准率（0.25022），
   根因是区分度不足，与本次符号修正无关。

## 4. 副作用与配套改动

### 4.1 一个测试的前提被证伪

`UnifiedFactorScoringEngineTest.factorScoreIsMonotonicInTheDominantFactorWhenOnlyItVaries`
原断言"分数随构造序号严格递增"。改符号后 `TREND_MA` 成为**负号主导因子**，
分数改为递减，测试失败。

**这不是回归**，而是该测试原本就**脆弱**：它隐含假设了旧的权重符号。
且 20 只的合成截面里横截面百分位本身存在并列（实测第 0、1 只行为端点伪影，
第 2 只起才严格单调），逐点严格单调在该截面上**本就不成立**。

**改法**：改为断言**引擎的真正契约**——分数方向必须与主导因子的权重符号一致
（按 `TREND_MA` 百分位排序后比较端点分数差的符号）。
这样以后再改权重不必再改断言。

全量后端测试 **611 passed / 0 failed**。

### 4.2 必须重算已落库的截面

`factor_cross_section_score` 存的是**逐因子百分位**，而 `CrossSectionNormalizer.normalize()`
只接收 `features` 与 `factorIds`、**不接收 weights**
（实测 `UnifiedFactorScoringEngine:133-134`），故**百分位与权重无关**。

但**复合分与权重有关**。所以改符号后：
- 已存的百分位**仍然有效**；
- 但用它按新权重算出的复合分，与"改前存的复合分"不是同一个数。

**同时**还有行业中性化的口径问题（阶段2 §6）：约 94 天是行业为空时算的（未中性化），
η² ≈ 0.09~0.16；而已中性化的日期 η² ≈ 0.003。

**故两项口径问题一次解决**：用新权重 + 已生效的行业中性化，重算全部 213 个日期。

已给 `xsec_collect.py` 增加 `--redo-before <date>`：

```powershell
python xsec_collect.py --start 2025-10-13 --end 2026-08-31 --per-month 30 --redo-before 2026-12-31
```

（`--redo-before` 取一个晚于区间末端的日期即表示"全部重算"。）

**验证已验证**：重算后的 2025-10-13 ~ 2025-10-17 实测 η² = 0.0006~0.0013（已中性化）。
