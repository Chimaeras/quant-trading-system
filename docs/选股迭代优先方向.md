# 选股迭代优先方向

本文件定义 `quant-trading-system` **持续优化循环的业务主航道**。  
Cursor（`docs/Cursor量化系统持续优化执行手册.md`）与 Codex（`docs/Codex量化系统持续优化执行协议.md`）均须优先遵守本文。

---

## 1. 迭代目标（用户视角）

帮助个人投资者**更准、更稳、更可解释**地完成 A 股筛选：

- 从全市场或配置范围内，得到**值得进一步研究**的候选股票列表；
- 每只候选应附带**得分、排名、触发原因、失效条件与数据日期**；
- 宁可输出「今日无合格标的」，也不凑满 TopN；
- 筛选结果应能回溯：**用的哪套策略、哪版因子、哪日行情**。

---

## 2. 优先建设模块（代码落点）

| 优先级 | 模块 | 主要路径/入口 |
|--------|------|----------------|
| A | 经典多因子选股 | `StockSelectorService`、`ClassicFactorCalculator`、`POST /api/selector/run` |
| A | 超跌反弹选股 | `OversoldReboundScoringService` |
| A | 趋势 / 综合 / 多维度打分 | `StockTrendScoringService`、`ComprehensiveScoringService`、`MultiDimScoringService` |
| A | 统一打分工作台 | `UnifiedScoringService`、前端 `StockPicker` |
| B | 行情与数据质量（选股地基） | `HistoricalDataService`、数据更新任务、`market_data` |
| B | 股票池与可交易性 | ST/停牌/流动性/涨跌停过滤、历史时点池 |
| C | 选股效果验证 | `ScoringBacktestService`、持有期 forward return |
| D | 单股策略回测 / 模拟账户 | `StrategyBacktestEngine`、`SimAccountService` |

**A 类问题优先于 C/D 类**（先让「选得准」再让「回测/下单」更完善）。

---

## 3. 扫描与选题顺序（在 P0 之后）

存在多个候选问题时，按以下顺序选题（仍须满足 P0→P1→P2→P3）：

```text
1. 选股未来函数 / 信号日数据时点错误 / 可交易性遗漏（P0/P1）
2. 行情与入库质量影响选股输入（重复 K 线、OHLC 异常、缺失交易日）
3. 因子定义、权重、阈值、质量闸（不得绕过 minTrendScore、流动性等硬条件）
4. 股票池过滤（ST、停牌代理、零成交量、涨跌停、上市时间）
5. 选股结果可解释性（reasons、factor_snapshot、策略版本、数据日期展示）
6. 前端选股体验（筛选、排序、导出、空状态、假设说明）
7. 选股效果度量（打分回测口径、幸存者偏差披露、持有期统计）
8. 回测成交模型 / 模拟交易 / 自动下单
9. 通用工程（性能、安全、文档、样式）
```

---

## 4. 每轮鼓励的验证方式

| 改动类型 | 最低验证 |
|----------|----------|
| 因子/选股逻辑 | 单元测试 + `mvn test`；必要时固定样例股手工核对 |
| 股票池/可交易性 | 边界用例测试（ST、零成交量、涨跌停） |
| API/前端选股页 | `vue-tsc` + 相关页面字段与接口文档一致 |
| 数据层 | Repository/解析测试 + 抽样入库校验 |

---

## 5. 明确低优先级（本轮迭代少做）

- 与选股无关的 UI 美化、大范围格式化；
- 微服务拆分、新机器学习预测模块；
- 高频交易、复杂组合优化；
- 无证据的因子权重「调优」。
