## 2. 缺陷 1：东财代码后缀把北交所 920xxx 判成了沪市

**位置**：`fetch_industry.py` 的 `suffix()`

```python
# 旧（错）
return "SH" if code.startswith(("6", "9")) else "SZ"
# 新
if code.startswith(("4", "8", "92")): return "BJ"
return "SH" if code.startswith("6") else "SZ"
```

**后果**：`920xxx` 是**北交所**代码，旧逻辑给它拼 `.SH`，
请求 `920001.SH` 在东财侧不存在 → **永远返回空**。

**证据（决定性）**：修前无行业的 **295 只，100% 都是 `920xxx`**，其他代码段一只不缺：

```
无行业代码的分布:
   920xxx (北交所新代码)               295     ← 全部
```

修 `suffix()` 后重抓，**579 只（含之前未抓的）全部成功、失败 0**。
即这 295 只是**纯代码缺陷**，不是数据源缺失。

**这个缺陷不是孤例**：本库自身在 7 处都把 `4/8/92` 开头判为 BSE
（`HistoricalDataService:947`、`MarketService:34/224`、`WatchlistService:136`、
`TradingLimitRules:27`、`StockAnalysisService:274`、`RealtimeQuoteService:116`），
唯独这个抓取脚本用了 `"9"→SH`。

## 3. 缺陷 2：空候选清空盯盘观察池（观察池 204 → 6 的根因）

**位置**：`paper/watch/store.py` 的 `sync_default_watch_pool()`

```python
values = list(rows)
if not values:          # ← D-2 新增的守卫
    return
with self._transaction():
    self._conn.execute("DELETE FROM watch_pool_member WHERE manual=0")
    ...
```

**旧行为**：`values` 为空时**仍然执行** `DELETE ... WHERE manual=0`，
把全部非人工成员删光。

**为什么这是缺陷**：「候选为空」有两种**完全相反**的成因：
- (a) 上游热门榜真的返回 0 条 → 清池或许合理；
- (b) 上游取候选**失败**（限流 / 超时 / 覆盖闸不通过 / 观察日不合法）。

调用方 `loop.py:447-450` 在 `source in {"t1","t1_no_candidate","t1_overflow"}`
时调用本方法，而 `source="t1_invalid_day"` 时 `candidates` 被显式置为 `[]`（`loop.py:444`）。
于是 T1 模式下一次候选获取失败，观察池就被清成**只剩人工成员**
——实测由 **204 只掉到 6 只**。

**「取不到」不等于「没有」**，故空输入直接返回，保留既有池子。

**回归测试**（`paper/tests/test_watch_pool.py`，2 条新增）：
- `test_empty_candidate_list_does_not_wipe_hot_pool` —— 空候选后池子仍是 6 只；
- `test_non_empty_candidate_list_still_replaces_hot_members` —— 对照组，
  确保没把修复做成「永不刷新」。

`paper/tests` 全量 **366 passed**，无回归。

## 4. 行业中性化生效验证（不靠代码自述，靠数据）

### 4.1 接口层确认

只读入口 `POST /api/scoring/unified/engine/all-strategies`（不落库）实测：

```
signalDate=2026-07-01  耗时 58.3s
  industry_neutralization_skipped = False      ← 已生效
  market_cap_neutralization_skipped = True     ← 仍降级（无官方市值源，预期）
```

### 4.2 更强的证据：η² 断点

**判据设计**：行业中性化会把残差在行业内去均值，故中性化后
「因子百分位被行业解释掉的比例」η² 应趋近 0。

实测发现一个**天然实验**：已落库的 2026-01-22 ~ 2026-01-28（5 天）
η² ≈ 0.003，而前后日期 η² ≈ 0.09~0.11。

跨因子、跨策略一致（下表为 η²）：

| 因子 | 2026-01-21<br>(断点前) | 2026-01-27<br>(断点内) | 2026-01-30<br>(断点后) |
|---|---|---|---|
| TREND_MA | 0.1052 | **0.0074** | 0.1085 |
| MOM_20 | 0.0909 | **0.0025** | 0.0936 |
| VOL_RATIO | 0.0734 | **0.0028** | 0.1225 |
| TREND_MACD | 0.0843 | **0.0029** | 0.1661 |
| MAXDD_60 | 0.0638 | **0.0036** | 0.0662 |
| VOLATILITY_20 | 0.1035 | **0.0074** | 0.1368 |
| RSI_14 (超跌/多维) | 0.1121 | **0.0020** | 0.1322 |
| KDJ_J (超跌/多维) | 0.1786 | **0.0046** | 0.1806 |
| MOM_60 (超跌) | 0.0682 | **0.0053** | 0.0655 |
| REV_5 (超跌) | 0.2001 | **0.0054** | 0.1336 |

**10 个因子、3 个策略、同一个断点位置** ⟹ 这是**管道开关行为**，不是因子噪声。
**行业中性化确实在起作用。**

### 4.3 两个例外：中性化对它们无效

| 因子 | 断点前 | 断点内 | 断点后 | 判定 |
|---|---|---|---|---|
| **VOL_PRICE** | 0.0540 | **0.0940** | 0.0717 | 中性化后行业暴露**升高** |
| **LIQUIDITY_20** | 0.1264 | 0.1286 | 0.1227 | **几乎不变** |

即这两个因子的行业暴露**不是线性可去均值的那部分**。
`LIQUIDITY_20`（20 日流动性）本质上就是行业属性（银行/公用事业天然高流动性、
科技股天然低），行业内去均值对它的作用有限。
`VOL_PRICE` 甚至反向——具体原因未查明，**列为待查项，不臆断**。

## 5. 诚实披露：中性化对 IC 的提升不显著

用 §4.2 的天然实验做「同因子、同策略、只差是否中性化」的对照
（`natural_experiment.py`，因子 `TREND_MA`，T+5）：

| 组 | 天数 | 平均 IC | 中位 IC | IC 标准差 | IC>0 占比 |
|---|---|---|---|---|---|
| 已中性化 | **6** | −0.0351 | −0.0147 | **0.0493** | 16.7% |
| 未中性化 | 94 | −0.0496 | −0.0270 | 0.1364 | 38.3% |

**能说的**：
- 中性化组 IC **波动小得多**（σ 0.049 vs 0.136）——符合设计意图（去掉一个系统性风险源）；
- 平均 IC 略有改善（−0.0351 vs −0.0496）。

**不能说的**：
- **已中性化组只有 6 天**，远不足以支撑显著性结论；
- IC>0 占比反而更低（16.7% vs 38.3%），与「改善」不一致；
- 因此**不能宣称"中性化提升了打分能力"**。它修正的是一个**方法论缺陷**
  （打分里混入了不可控的行业押注），而不是一个**收益来源**。

## 6. 遗留问题：已落库的截面**不同质**，需要重算

### 6.1 问题的由来

行业数据是**今天补的**，而截面是**过去几小时逐批算的**。
所以同一张 `factor_cross_section_score` 表里：
- 约 **94 天**是行业为空时算的（**未**中性化，η² ≈ 0.09~0.16）；
- 约 **5 天**（2026-01-22~28）+ 今天补算的日期是**已**中性化（η² ≈ 0.003）。

**混合两者做 IC / 回测，等于把两个不同口径的因子混在一起比。**

### 6.2 处置

已给 `xsec_collect.py` 增加 `--redo-before <date>`：只重跑该日期之前**已完成**的日期。

```powershell
python xsec_collect.py --start 2025-10-13 --end 2026-08-31 --per-month 30 --redo-before 2026-01-22
```

在补录任务（`pwsh-475`，至 2026-08-31）跑完后执行，
把 2025-10-13 ~ 2026-01-21 这 71 天按新口径重算，使全表同质。
预估 **~110 分钟**。

**在此之前，阶段1/阶段3 的 IC 数值都应视为"混合口径"，仅供方案排序，不作结论。**
