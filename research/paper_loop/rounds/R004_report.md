## 1. 一句话结论

**判定 REJECTED。项目里那个叫「多空收益差 / 多空 spread / 超额」的数，在六条轴上有四条与文献标准定义结构不同构；
其中两条是数值型的，且其中一条会直接翻转样本外的符号。**

按重要性排序：

1. **成本轴（数值型，最有工程后果）**：项目冻结成本表达式在**两条腿各收一次**往返成本（15bp），
   但项目算的那个「多空 spread」是**两个多头腿之差**，成本在差分中**抵消**。
   用项目**自己的**成本表达式把真正的双腿美元中性组合算出来，与项目值之差
   `G(12bp)` 在 IS 是 **+30.1463bp**、在 OOS 是 **+29.9893bp**
   （阈值 `max(5bp, 0.30×|S_twoleg|)` = 25.1559bp / 5.0000bp，**两段均触发**，**同号**）。
   ⟹ **OOS 的 +18.9129bp「多空收益差」在真正的双腿净口径下是 −11.0764bp，符号是反的。**
   这是本轮唯一具直接工程后果的发现（`D-R004-01`，协议 §7 保留权限，待用户决策）。
   注：R003 给的 `c_rt = 12bp` 用的是 R003 自己的 `apply_cost`（只收买入侧），
   **比项目实际往返低 3bp**（= 1×佣金）；本次测量改用项目实际表达式，故 `G ≈ 2×15bp` 而非 `2×12bp`。
2. **毛/净轴（数值型）**：名为 `RAW` 的块与名为 `COST_APPROX` 的块**不是同一个量的两种口径**。
   `RAW` 用 qfq `close[t+h]/close[t]−1`，`COST_APPROX` 用 raw `open[t+1] → raw close[t+1+h]`。
   实测「成本项」只占用户可见的「净 − 毛」差的 **0.45%（IS）/ 0.07%（OOS）**，
   剩下 **99.55% / 100.07%** 全是窗口项（入场时点 + 一天位移 + 复权基准）⟹ `K3` 触发。
   即：**用户在前端看到的「毛 vs 净」差异，几乎全部不是成本造成的。**
3. **基准轴 + 尺度轴（结构性）**：全仓**不存在数值型超额字段**（`excess*` 命中 0 处）、
   **不存在 Rf 序列**（`risk_free / 无风险` 命中 0 处），唯一的基准对照是一个**布尔** `outperform`；
   且**同一个量在两个界面上的口径标注不对称**——`FactorResearch.vue` 标注 `metric_scope`，
   而 `ScoringBacktest.vue` 的「多空收益差」卡片**什么都不标**。`K5`、`K4s` 均触发。
4. **同构的两条轴必须同量级地报告（不是走过场）**：**符号轴**（高 − 低，交换首末组精确取负，`1.000e+00` 级）
   与**分位间距轴**（`i*g/n` 等数量分位）**与标准定义同构**。
   本轮**没有**把「四条轴不同构」扩大成「口径全错」——见 §5 的直接判定表。
5. **分组数轴（数值型，只触发一半，按冻结文本不计入判定）**：项目 `J` 是**编译期常量 5**、无入参，
   而 CCF2019 的立场是「J 是调参量，标准取 10，最优常远大于 10」。
   实测 IS 把 J 从 5 提到 10，spread 从 **−36.7610bp 变到 −53.7067bp**（Δ = **−16.9457bp**，
   `t_NW = −3.1460`）⟹ IS 侧远超声噪；但 OOS 侧 Δ = **+4.6084bp**（`t_NW = 0.3405`，`|Δ| < 5bp`），
   **不同号且不达幅值** ⟹ `K2` 的冻结文本（要求 IS/OOS 均满足）**未触发**。
   如实报告：**这是一条「一半触发的敏感性」，不纳入判定**（§6.2）。

**因此本轮的产出是「工具修好、口径测准、且发现了一个会翻符号的偏差」**，不是一篇论文被证伪。
被杀死的是**项目自己的命名主张**，不是 FF2015 或 CCF2019。

## 8. 已知偏差披露（必填）

1. **(ii) 是代理，不是原式**：A3 的 `(ii) 项目 COST_APPROX` 在本地**不可计算**（`market_price_raw` = 0 行）。
   本轮用「同窗口 (iii)/(iv)」把差值**分解**为成本项与窗口项。**这个分解是代理解释**，
   不等于项目真实 `COST_APPROX` 的数值。**但它不削弱 `K3`**：两种读法都触发（§4.3）。
2. **双腿构造是一种约定**：我用的双腿是
   `R_L = mean_high[(1+g)·a/b − 1]`、`R_S = mean_low[a − (1+g)·b]`，腿级相加。
   这**不是**论文给的公式（FF2015 不含成本），是**算术推导**。
   其它约定（如把短腿写成 `−[(1+g)·b/a − 1]`、或 `R_L − g_L − 2c` 的线性近似）会给出**不同但同量级**的 `G`。
   本轮**只报告这一种约定**并把解析式写出，是为了让任何人可以**换约定重算**并检验 `K1` 是否仍触发。
   **按当前约定，`G ≈ 2×15bp = 30bp`，且 `G(0) = 0` 精确成立（T3）。**
3. **`long_short_spread` 的 `RAW` 块与 `COST_APPROX` 块样本集不同**：`COST_APPROX` 缺少 raw 价即跳过，
   ⟹ 两块的**成分股集合**可能不同（本轮因 `market_price_raw` 为空而无法测量这个差异的规模）。§4.3 的分解已把这一点列在窗口项里。
4. **NaN 安全聚合**：`spread_stats` 用 `nanmean` 并计 `dropped_obs`。实测全部单元 `dropped_obs = 0`，
   即本轮的 OOS/IS 面板上**没有**发生「因缺价而丢观测」。这条约定**不改变任何阈值**，
   但在别的数据切片上可能生效，故显式披露。
5. **基准覆盖率 74.42%**：`index_quote` 000300 只覆盖面板窗口 645 天中的 480 天。
   §4.6 的「净 vs 毛」对照用的是被覆盖的那部分日子的均值，**不是**全窗口对照。
6. **`market_price_raw` 为空的后果被低估了**：它不只是「(ii) 算不出」——
   它意味着**生产环境的 `COST_APPROX` 路径在本地会跳过所有观测**，
   此时 `emptyNetIcBlock()` 仍会写出 `metric_scope = COST_APPROX` 与 `long_short_spread = 0.0`。
   ⟹ 一个**公开契约**下的歧义：读者无法区分「成本后净收益恰好为 0」与「无 raw 数据、全部跳过」。
   已登记 `D-R004-03`，**不在本轮修改**。
7. **两个 J 常量不是同一个闸**：`RANK_IC_GROUP_COUNT = 5`（分组数）与 `RANK_IC_MIN_CROSS_SECTION_SIZE = 10`（截面下限）

## 9. 本轮教训（写入下一轮预注册设计）

1. **「审计器本身」必须先被审计，且阳性对照要连到被审计量。** `K6` 的第一次运行**误标了合规行**，
   根因是金丝雀夹具自相矛盾——如果金丝雀只验「格式」而不验「成本/符号/尺度的语义一致性」，
   它**不可能**发现这个错。本轮的 `K6` 之所以有效，是因为它要求审计器对**同一套被审计规则**在**已知答案的行**上作答。
2. **恒等式必须在最便宜的地方钉死。** `T3`（双腿零成本 = 单腿）是本轮最关键的一条断言：
   它把「我的双腿构造是否正确」从「看起来合理」变成「`abs_diff = 0.0`」。
   **R001/R003 的教训在 R004 上的形态是：任何新构造都要先证明它在退化点上回到已知量。**
3. **预注册里的「检索计数」不是证据，而是假设。** P-6 的「后端 17 处、前端 0 处」两个数**都错**，
   根因是**读了被截断的 grep 输出**。
   ⟹ 下一轮起：**预注册中任何形如「N 处命中」的断言，必须附可复现的完整命令，且命令不得带 `head`/`tail`/`grep -c` 之类的截断**。
4. **不要把自己的实现错误诊断为「预注册缺陷」。** 我一度怀疑 `K1` 的同号子句误写（E-3），
   实际是我自己的双腿构造恒为 0。**在改写/质疑冻结文本之前，必须先把实现证伪到不可能再错。**
5. **「两个量相减」不等于「同一个量的两种口径」。** A3 是本轮第二条数值型发现，且它**不依赖任何新论文**——
   只需要问「这两个块的价格窗口是否相同」。这条检查成本极低、普适性高，应作为下一轮其它审计的模板。
6. **符号级的偏差比幅值级的偏差更危险。** A1 的 `G` 在 IS 只是「更负一些」，在 OOS 却**把符号翻过来**。
   ⟹ 下一轮起，任何口径审计都要专门检查「偏差是否会翻转符号」这一维度。
7. **`market_price_raw` 空表这件事在 R003 就已存在但未被识别为契约问题。** 本轮把它升级为 `D-R004-03`：
   **空的输入 + 默认的占位输出 + 仍然标称的口径 = 一个可被误读的公开接口**。
