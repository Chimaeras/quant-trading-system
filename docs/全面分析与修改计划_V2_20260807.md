## 0. 执行摘要

### 0.1 相对北极星的阶段判断

V1 后项目从“概率研究基座”快速扩展为具备数据快照、raw 标签、研究任务、实验、预测快照和组合回测等接口的模块化单体；但一次提交新增约 1 万行、139 个文件，且原实施记录明确多项仅做 MVP/契约桩、未做真实库迁移和全量浏览器冒烟。V2 的最终判断是：**结构化骨架已明显前进，但尚未达到“可信概率选股系统”阶段；当前仍属于“规则 baseline 可用、研究基础设施原型化、概率生产链必须关闭”的阶段。** 最大鸿沟不是再加模型，而是 snapshot 实际不冻结、质量门禁未接线、模型/校准器契约不完整，以及组合回测存在现金因果错误。

本计划共 30 项：**P0 7 项、P1 19 项、P2 4 项**。19 个原路由均有组件且都在菜单可达，但其中 10 个需要按半残/构建受阻/结果误导优先处置：数据质量、选股日报、自选股池、股票详情、T+1 候选、因子研究、概率研究、打分回测、模拟账户、持仓对账。另有组合回测、研究任务、行情批次三个后端能力没有完整页面入口。

### 0.3 V2 Top 问题

截至当前代码复核，已确认的最高风险不是“功能还没做完”，而是若干路径已经能运行、却会生成时间错位、语义虚假或不可复现的结果：

| 优先级 | 已确认问题 | 直接后果 | 首要处置 |
|---|---|---|---|
| P0 | `PredictionService.pickSelectorResult` 在目标日无结果时回退全局最新 CLASSIC 结果，再用目标日发布 | 历史预测可读取未来选股结果；当日预测可把陈旧候选伪装成今日候选 | 禁止跨交易日回退；无同日结果即 `ABSTAINED` |
| P0 | 概率训练/校准 UI 与部分接口仍默认 `label_v1`，且 `dataSnapshotId` 可空 | 正常用户路径继续使用前复权旧标签；V1 的 raw/快照治理被绕开 | 新研究强制 `label_v2 + snapshotId`；v1 只读 legacy |
| P0 | purge/embargo 只数 trainEnd 与 testStart 之间的交易日，没有按标签实际退出日判断 | `h=2` 时训练标签可在测试首日收盘才退出，形成未来函数 | 以 `lastTrainLabel.exitDate < testStart` 为唯一判据 |
| P0 | “校准概率”发布未加载校准器；champion 只粗校验 horizon/featureVersion，不绑定策略、标签、快照、schema、输出类型 | 模型可跨策略/版本错配；未校准 logistic 值被标成校准概率 | 建立完整 deploy contract，缺一项即拒绝发布 |
| P0 | 组合回测先按收盘卖出、再按开盘买入，并使用卖出所得现金 | 使用未来才获得的现金回填当天开盘成交，NAV 与成交均失真 | 同一交易日严格按时间排序：开盘事件先于收盘事件 |
| P0 | snapshot 只记录当前全表聚合，`cutoffTime` 不参与取数；训练/标签/回放仍查询可变现表 | 相同 snapshotId 无法重放，历史截止时点仍包含后来数据 | 冻结数据版本，或所有读取强制 `known_at/ingested_at <= cutoff` |
| P0 | 数据质量门禁没有接入训练、校准与实验晋级；现有检查多为全表总量而非目标区间/快照 | 关键写路径可绕过门禁，劣质数据仍能产出候选模型 | 服务事务入口统一 `assertAllowed`，按用途、区间、快照评估 |
| P1 | 异步研究任务取消与执行竞争；取消后底层仍可写库并被改回 COMPLETED/PUBLISHED | 已取消任务仍可能产生正式产物；重启后 RUNNING 可永久悬挂 | 持久化状态机、协作式取消、checkpoint 与原子发布 |
| P1 | Python 正式 `research run` 不读数据也不训练，无 `data_path` 时仍输出 `status=ok` 的零权重 artifact | 占位产物可能被误认为可导入/生产模型 | stub 固定为 `DEMO/NON_PRODUCTION`，正式命令无真实训练即失败 |
| P1 | 新增组合、批次、研究任务、实验等写/重计算接口未完整纳入鉴权 | 可匿名触发数据写入或高成本计算 | 默认保护 `/api/**`，仅显式放行健康检查、登录等白名单 |

本轮还确认两类工程回归：Web 静态类型检查有 3 个错误；Java 编译因本机 Maven 镜像域名不可解析而未能独立复验。二者都必须作为后续验收门槛，不能沿用“此前编译通过”的结论。

### 0.4 半残/误导功能处置原则

- 新增 Controller/Entity 但无页面入口或消费链路：标“API 基座/未接线”，不计完成。
- 返回固定值、占位数据、仅内存/JSON 简化实现：按真实能力改名为 MVP/Beta，禁止生产语义。
- 会产生错误概率、错误成交或错误历史截面的路径：P0 先阻断，再补终态。
- 只有编译或静态核对、没有真实 DB/页面/金融样例验证的项：状态最高为“待运行验收”。

## 1. 系统功能与场景地图

### 1.1 用户旅程

1. 日常：数据批次与质量门禁 → 规则/概率双轨预测 → 候选解释 → 人工决策 → 日报与到期核销。
2. 研究：不可变 snapshot → PIT universe/特征 → raw 标签 → 时序隔离训练/校准 → 实验门禁 → champion。
3. 验证：候选前瞻收益 → 事件驱动组合回测 → 模拟账户/持仓对账 → 误差回流。

### 1.2 V1→V2 能力成熟度矩阵

|---|---|---|---|---|

### 1.3 目标架构与实际落地差距

目标链路应为：`原子数据世代 → FROZEN snapshot → PIT universe + 完整特征快照 → raw execution label → purged rolling OOS → base model + calibrator → 人工审计晋级 → 同日 prediction snapshot → 组合回测/日报/核销`。当前已经有几乎所有同名类和表，但多数连接只是 lineage 字符串或 API 调用，实际读取仍指向可变现表。V2 不建议再新增平行模块，而应把以下四条“虚线”变成硬约束：

1. snapshotId 从备注字段变成 repository 读上下文；
2. data gate 从查询页面变成领域服务入口的决策凭证；
3. experiment/model/calibrator 从 JSON 描述变成严格 deploy contract；
4. prediction items 从旁路记录变成日报、组合回测和核销的唯一不可变输入。

## 2. 分维度问题清单

### 2.1 Web

- `api/data.ts`、`DataQuality.vue`、`ProbabilityResearch.vue` 的研究默认仍为 `label_v1`，且关键表单允许不选 snapshot，用户主路径与 V1 的 raw 标签/可追溯目标相反。
- 数据质量页仍调用旧同步 replay；没有承接 signal replay、market batch 与 research task API，因此这些能力是“后端 API 基座”，不是完成的产品功能。
- 组合回测只有 API 封装，无路由、菜单和页面；研究异步任务同样没有可视化进度、取消、恢复和结果入口。
- 预测生成响应只返回 track 摘要、不返回候选明细；页面若不随后查询 snapshot，会出现“生成成功但无候选”的误导状态。
- 已执行非测试型静态检查 `npx vue-tsc --noEmit`，有 3 个阻塞错误：`StockDetailView.vue` 错误导入 `EChartsOption`；`WatchlistView.vue` 的 autocomplete callback 返回类型错误；select handler 参数类型过窄。
- 概率研究页只凭 `stage=champion` 表示“可生产”，没有展示或校验策略、snapshot、label、schema、calibration 等 deploy contract。

### 2.2 Java

- 预测：同日选股缺失时跨日回退；CLASSIC 缺失时会任取其他策略；champion 绑定字段不足；未应用校准器却发布为 `CALIBRATED_PROBABILITY`。
- 标签/训练：V2 标签算法方向正确，但 snapshot 仅验存在；训练、校准没有数据质量门禁，purge/embargo 存在标签退出日重叠。
- 实验：没有任何受支持的 `setStage("champion")` 路径，只有 CHALLENGER/REJECT；现有门禁未评估 Brier/ECE、稳定性和完整数据质量。
- 组合回测：日内事件顺序错误；成交价允许 raw→qfq 回退；没有最低佣金；停牌/退市未闭合仓位可一直按入场价估值。
- 模拟账户：历史订单的 `firstBuyDate`、T+1 解冻使用 `LocalDate.now()` 而非订单交易日；同样存在 qfq 回退与最低佣金缺失。
- 日报：候选动态读取最新 `selector_result`；prediction lineage 只是附加说明，报告内容不是 prediction item 的不可变投影。
- 行情批次：`batchId` 不持久化，数据直接写生产表，STAGED/PUBLISHED 只是返回文案；无原子切换、日期一致性和恢复点。
- PIT：LIMITED 降级虽被标识，但 provider 把 null/unknown 来源当 official；历史涨停生态仍通过当前名称识别 ST。
- 信号回放：最多 60 日、只持久化 top-20 摘要 hash；FAILED manifest 也会被复用，无法重试；一次长事务无 checkpoint/cancel。
- 异步任务：`Future.cancel(true)` 与完成写回竞争；业务返回 `INSUFFICIENT_DATA` 等也可能统一标 `published=true`；重启后 RUNNING 无恢复策略。

### 2.3 Python

- `main.py research run` 是 artifact stub：不加载数据、不拟合模型；即使未提供 `data_path`，也能生成零权重/配置权重且 `status=ok` 的文件。
- 提供 `data_path` 时只检查路径存在，不验证 schema、时间区间、标签版本、PIT 字段，也不计算真实 OOS 指标。
- `artifact_hash` 只覆盖 weights/bias/features，不能代表训练数据、标签、环境和代码；依赖只有下限约束、无锁文件。
- Java 侧 model registry 没有完整导入/审核接口，schema hash 只做非空或字符串相等校验，尚未形成跨语言生产契约。

### 2.4 数据与跨层契约

- `DataSnapshotService` 的 cutoff 未约束查询；指纹只是全表 count/min/max/sum 的弱聚合，既非数据冻结，也可能碰撞。
- `label_snapshot` 的收益、价格、最大有利/不利变动均为 `DECIMAL(38,2)`，Java 却按收益 8 位、价格 4 位写入，数据库会截断关键数值。
- 默认/dev 同时使用 Hibernate `ddl-auto=update` 与 Flyway；`baseline-on-migrate=true` 可能跳过 V1，后续 `ALTER TABLE` 又对 Hibernate 已加列/索引不幂等。
- ModelVersion 缺少显式 strategyType、snapshotId、outputKind、labelVersion、calibrationVersion、schemaHash 列，只将部分信息埋在 JSON。
- raw/qfq 取价政策在标签、评分回测、组合回测和模拟账户间重复且不一致；“raw preferred”仍会静默回退 qfq。
- `experiment_run.metrics` 等大对象使用 TEXT，嵌套完整报告/resultIds 后可能超过 64KB；组合回测将完整 orders/NAV 存一行 LONGTEXT，也不利于分页和大区间执行。

## 5. V2 详细修改计划（V2-MP-001…）

以下条目是可直接执行的工程任务；文件行号在实施前以当时分支重新定位，类/方法名是稳定锚点。

### V2-MP-001（P0）禁止预测候选跨交易日回退

- **证据/根因**：`PredictionService.pickSelectorResult` 在目标日无结果时调用 `findFirstByStrategyTypeOrderByCreatedAtDesc` 获取全局最新 CLASSIC，再以请求的 `tradeDate` 创建快照；CLASSIC 不存在时还会从同日其他策略任取第一条。
- **影响**：历史生成可使用未来选股结果，在线生成会把陈旧候选伪装成今日数据；预测、日报和到期核销都失去日期语义。
- **目标**：候选集必须满足 `selectorResult.tradeDate == prediction.tradeDate` 且 `strategyType` 与 track 契约一致；缺失即明确 abstain，绝不回退日期或策略。
- **实施步骤**：1）删除全局 latest fallback；2）请求显式携带 strategyType，或为每条 track 固定策略；3）无同日已完成 run 时写 `ABSTAINED/NO_SAME_DAY_SELECTOR_RESULT`，items 为空；4）响应返回 sourceResultId/sourceTradeDate；5）日报只消费已发布 prediction items。
- **主要文件**：`service/PredictionService.java`、`controller/PredictionController.java`、`api/predictions.ts`、`views/research/ProbabilityResearch.vue`。
- **契约/数据**：PredictionSnapshot 增加或保证 `sourceStrategyType/sourceTradeDate/sourceResultId/abstainReason` 可查询；旧快照不回填伪来源，标 legacy_unknown。
- **迁移与兼容**：新增列须 Flyway；先兼容读旧行，再切写新契约；不得重写历史快照的交易日。
- **手工验证**：选一个没有 selector result 的历史日生成，必须 abstain；构造该日前后各一条结果，确认都不被采用；有同日不同策略时只取指定策略。
- **验收**：代码中不存在跨日 fallback；生成响应、详情页和日报展示同一 sourceResultId；固定样例无未来日期来源。
- **依赖/复杂度/执行者**：依赖 V2-MP-004 的 deploy contract；M；Java+Web+DB。
- **禁止事项**：禁止用“最近 N 日”“最近一次成功”掩盖缺数；禁止仅改页面文案。

### V2-MP-002（P0）新研究强制 raw `label_v2` 与不可空 snapshot

- **证据/根因**：`api/data.ts`、`DataQuality.vue`、`ProbabilityResearch.vue` 与 `ResearchController` 的校准/训练仍默认 `label_v1`；snapshot 可空。旧标签基于 qfq，快照字段又仅作为可选元数据。
- **影响**：最常用 UI/API 路径继续生成不可审计旧口径模型，V1 已实现的 raw 标签无法成为生产基线。
- **目标**：新建 label、训练、校准、实验的默认且唯一生产口径为 `label_v2`；snapshotId、factorVersion、strategyType、horizon 必填并贯穿 lineage；v1 仅供历史只读查询。
- **实施步骤**：1）移除后端默认 v1 并对缺参返回 HTTP 400；2）前端先选择/创建 snapshot，再开放研究按钮；3）legacy endpoint/选项显式标红且禁止进入晋级；4）sample collector 禁止“每日取任意最新 factorVersion”；5）返回完整 lineage。
- **主要文件**：`controller/ResearchController.java`、`research/LogisticModelTrainer.java`、`research/ProbabilityCalibrationService.java`、`research/StrategyBoundSampleCollector.java`、`api/data.ts`、`views/data/DataQuality.vue`、`views/research/ProbabilityResearch.vue`。
- **契约/数据**：请求 DTO 使用非空字段与枚举；ModelVersion/ExperimentRun 显式保存 labelVersion、snapshotId、factorVersion、strategyType。
- **迁移与兼容**：历史 v1 模型统一降级 `legacy/non_promotable`；不删除旧标签，避免破坏审计。
- **手工验证**：从页面尝试空 snapshot、v1、空 factorVersion 均应被前后端阻止；使用 v2 完成一次标签→训练→校准并逐层核对 lineage。
- **验收**：全局检索新建请求不再出现 `label_v1` 默认值；所有生产候选都有四个必填 lineage；旧模型不能晋级。
- **依赖/复杂度/执行者**：依赖 V2-MP-007 真快照、V2-MP-015 精度迁移；M；Java+Web+DB。
- **禁止事项**：禁止把空 snapshot 自动替换成“最新”；禁止静默兼容 v1 写路径。

### V2-MP-003（P0）按实际标签退出日实施 purge/embargo

- **证据/根因**：`ResearchWindowValidator.validatePurgeEmbargo` 只要求 trainEnd 与 testStart 之间交易日数 `>= horizon`。按 t 信号、t+1 入场、再持有 h 个交易日的约定，h=2 的训练样本可能在 testStart 收盘才退出。
- **影响**：训练/校准窗口与测试窗口发生标签重叠，OOS 指标被未来信息污染。
- **目标**：对训练集中最后一个可用标签计算真实 entryDate/exitDate，严格保证 `max(train.exitDate) < testStart`；所有 trainer/calibrator/WFO 共用一个验证器。
- **实施步骤**：1）Validator 接受 label convention/calendar 或直接读取 max exitDate；2）错误返回 trainEnd、lastExitDate、testStart 和建议最早 testStart；3）校准与 logistic 统一调用；4）计划中的 WFO 同样复用。
- **主要文件**：`research/ResearchWindowValidator.java`、`research/LogisticModelTrainer.java`、`research/ProbabilityCalibrationService.java`、`research/LabelFactoryService.java`。
- **契约/数据**：API 错误码 `PURGE_EMBARGO_OVERLAP`；不新增业务表。
- **迁移与兼容**：无 DB 迁移；旧实验保留但标记 `window_rule=legacy_unverified`，不能晋级。
- **手工验证**：用周一 trainEnd、周四 testStart、h=2 的固定交易日样例验证拒绝；将 testStart 移到实际 exit 后一日验证通过；覆盖节假日。
- **验收**：判定基于 exitDate 而非自然日/简单间隔计数；训练与校准返回完全一致的窗口结论。
- **依赖/复杂度/执行者**：依赖交易日历完整性；S；Java。
- **禁止事项**：禁止用 `horizon+1` 魔法常数代替真实日期计算；禁止只在 Controller 校验。

### V2-MP-004（P0）建立概率 deploy contract 并真实应用校准器

- **证据/根因**：预测加载 champion 只粗检 horizon/featureVersion；可能把其他策略模型用于当前 selector；推理直接对 rule score 做 logistic 后标为 `CALIBRATED_PROBABILITY`，`ProbabilityCalibrationService` 的 PAV 结果并未形成可部署 artifact。
- **影响**：输出类型虚假、模型与输入错配、概率不可解释；错误值可能进入日报和人工决策。
- **目标**：一个可发布概率版本必须原子绑定 strategyType、horizon、feature schema/hash、factorVersion、labelVersion、snapshot/train cutoff、outputKind、baseModelVersion、calibratorVersion、代码版本；推理顺序为特征→base probability/score→持久化 calibrator→calibrated probability。
- **实施步骤**：1）持久化校准器 knots/bins 与 hash；2）增加严格 ModelDeploymentContract；3）prediction 在加载和每次发布前全字段匹配；4）找不到完全匹配的 champion 时 abstain；5）UI 展示 lineage 与 outputKind；6）禁止 rule score 冒充模型特征。
- **主要文件**：`service/PredictionService.java`、`research/ProbabilityCalibrationService.java`、`entity/ModelVersion.java`、`research/artifact/ModelRegistryService.java`、`controller/PredictionController.java`、相关 Web 页面。
- **契约/数据**：新增显式 lineage 列及 calibrator artifact 表/版本；唯一约束保证同一 deploy key 仅一个 active champion。
- **迁移与兼容**：旧 champion 默认 `contract_incomplete` 并停止概率发布；提供只读审计页，不自动猜测字段。
- **手工验证**：分别篡改策略、horizon、schema、label、snapshot、calibrator 任一项，必须 abstain；用固定 knots 手算 3 个分数并与页面输出一致。
- **验收**：`CALIBRATED_PROBABILITY` 必须带 calibratorVersion/hash；无完整 contract 不产生概率 items；规则轨仍可独立发布并明确 `RULE_SCORE`。
- **依赖/复杂度/执行者**：依赖 V2-MP-002/007/018/025；L；Java+Python 契约+Web+DB。
- **禁止事项**：禁止仅通过 JSON contains 或字符串命名推断版本；禁止自动挑任意 champion。

### V2-MP-005（P0）修正事件驱动组合回测的现金因果与终态

- **证据/根因**：`PortfolioBacktestService` 每日先按 close SELL、再按 open BUY，并允许使用卖出所得；成交价 raw 缺失时回退 qfq；无最低佣金，无法退出的仓位可长期按 entryPrice 估值。
- **影响**：开盘买入使用未来收盘现金，收益和仓位不可能真实复现；停牌/退市、费用和估值进一步扭曲 NAV。
- **目标**：建立按时间排序的 OPEN/CLOSE 事件账本，原始价格严格执行，资金/持仓逐事件守恒，并给所有仓位明确 final status。
- **实施步骤**：1）同日 OPEN 买入先执行，只能使用前收盘后现金；2）CLOSE 卖出随后入账；3）raw 缺失拒单并记录原因；4）佣金含最低值、印花税、滑点且方向正确；5）停牌用最近有效 raw close 估值；6）结束日输出 CLOSED/OPEN_SUSPENDED/UNRESOLVED 并单列未实现损益；7）手工对账每个事件后的 cash+marketValue=NAV。
- **主要文件**：`service/PortfolioBacktestService.java`、`controller/BacktestController.java`、`dto/backtest/*`、后续组合页面。
- **契约/数据**：订单增加 eventTime/priceSource/rejectReason/feeBreakdown/finalStatus；推荐拆分 run/order/nav 表，避免大 JSON 单行。
- **迁移与兼容**：算法版本升级，旧 run 标 legacy_algorithm，禁止与新结果直接并表比较。
- **手工验证**：手算至少 5 个固定场景：普通换仓、现金不足、涨跌停/停牌、最低佣金、期末未退出；逐笔核对现金。

- **文件/契约/数据**：Prediction/DataSnapshot/ResearchTask/Experiment/MarketBatch services/controllers/entities、GlobalExceptionHandler/request.ts；新增 version/request_id/error_id 索引。
- **手工验证**：双击/并发发送同 requestId、不同 requestId、唯一键竞争、序列化非法对象、限流；检查一次副作用与正确状态码/errorId。
- **验收/依赖/复杂度/执行者**：重复请求可安全重放；无空 artifact 被当成功；依赖各领域 MP 契约；M；Java+DB+Web+运维。
- **不要做**：禁止用 synchronized 解决多实例并发；禁止捕获异常后返回 `{}`/`[]` 并标成功。

## 6. 分批实施路线图

原则：先 fail-closed 阻止错误结果，再建设数据底座，最后恢复概率发布。一个 MP 即使跨批依赖，也必须在其前置未满足时保持禁用/降级，不能先上线半套生产语义。

### Batch 1：止错、去误导与安全边界（8 项）

1. `V2-MP-001` 禁止预测跨日/跨策略回退。
2. `V2-MP-002` 默认强制 label_v2+snapshot；在真快照完成前只允许研究、不允许晋级。
3. `V2-MP-003` 修正真实退出日 purge/embargo。
4. `V2-MP-005` 先修组合回测现金因果；raw policy 完成前 API 标 blocked/Beta。

6. `V2-MP-010` 默认鉴权、修 IDOR、保护重计算端点。
7. `V2-MP-011` 让 Python 正式 stub fail-closed。
8. `V2-MP-027` 候选阈值优先于 TopN，允许零候选。

**Batch 1 出口**：不会发布跨日或伪校准概率；组合回测不再使用未来现金；未授权用户不能触发写/重算；Web typecheck/build 通过；无数据 Python 不再生成正式 artifact；弱信号日可返回零候选。

**Batch 2 出口**：相同 snapshot 可重放；部分行情批次不可见；成交不再用 qfq；数据库不截断收益/费率；历史名称/ST/行业来源可审计；存量库副本迁移通过。

## 7. 功能验证策略（仅手工/页面，不含单元测试）

### 7.1 验收前置与工程检查

1. 先备份真实数据库，并在恢复出来的副本执行 Flyway；保留 schema/row count/hash 前后对照。
2. 执行 `npx vue-tsc --noEmit` 与生产前端 build；二者必须退出码 0。
3. 执行 Java `clean compile`（不得 `-Dskip.frontend.build=true` 作为最终结论）；本轮本机因 Maven 镜像域名不可解析未完成，实施时必须在可访问依赖源的环境补验。
4. 启动 prod-like profile，确认 Flyway validate、auth、secret/password 启动校验；不得用 dev 默认凭据。
5. 本计划明确不要求、不新增、不修改、不运行单元测试或集成测试；下列全部使用真实应用、API、页面和固定金融样例。

### 7.2 Batch 1 固定止错样例

1. **跨日预测**：目标日 D 无 selector result，D-1 与 D+1 各有结果；生成 D 必须 `ABSTAINED/NO_SAME_DAY_SELECTOR_RESULT`，items=0。
2. **embargo**：h=2，trainEnd=周一、testStart=周四且无节假日；若周一标签退出日为周四必须拒绝，testStart 后移到周五才允许。
3. **组合现金**：初始现金 10 万，周一开盘待买 8 万、周一收盘才卖出旧仓得 5 万；开盘买入只能使用周一开盘前现金，不能使用 5 万。
4. **弱信号**：将规则阈值/概率阈值设为高于全部候选，页面显示“无合格标的”，不能补足 TopN。
5. **Python**：不传 data_path 执行正式 research run，退出非 0 且无 production artifact；demo 产物不能被 Java 导入。
6. **鉴权**：匿名调用每个 POST/DELETE/高成本端点得到 401；普通用户不能晋级；传其他 userId 仍只能看到自己的模板/账户/对账。

### 7.3 数据与可重放样例

1. 创建 cutoff=T 的 snapshot A；随后导入 T+1 数据并修改一条 T-10 live 数据。用 A 重放的 universe/features/labels/hash 必须不变，新 snapshot B 必须反映变更。
2. 行情批次故意只写 raw、不写 factor/qfq：active generation 不变，任务 FAILED/DEGRADED；恢复后同一 batchId 完成并一次发布。
3. 抽取一只正常股、一只历史 ST、一只改名/换行业股、一只退市股，按至少三个历史日查询 PIT master，并与源记录逐字段对照。
4. 向精度修复后的副本写入收益 `-0.01234567`、费率 `0.00030000`、价格 `12.3456`，从 API 与 SQL 读取必须一致。
5. 删除固定股票的 raw 开盘价但保留 qfq：标签、打分回测、组合回测、模拟账户均必须拒绝 execution，并返回同一 reason code。

### 7.4 概率与实验验收

1. 用固定 frozen snapshot 构建 label_v2、feature rows、训练/校准；从 label 到 model/calibrator/experiment/prediction 的 snapshot/strategy/horizon/schema/label/hash 必须逐层相同。
2. 用 3 个固定 base score 与已知 PAV knots 手算校准概率；API、prediction item 与页面四舍五入前值一致。
3. 逐一篡改 strategy、horizon、feature order/dtype、labelVersion、snapshotId、calibratorHash，prediction 必须 abstain，promotion 必须 409。
4. WFO 每窗人工核对最后训练标签退出日早于 testStart；未来 test 数据变化不能改变前窗模型/preprocessor/calibrator。
5. 同时提交两个 champion 晋级请求；最多一个成功，旧 champion 原子降级，rollback 后发布版本可追溯。

### 7.5 日常主旅程与 19 路由冒烟

1. 登录后依次走数据管理→数据质量→股票浏览→选股打分→T1/概率研究→打分/组合回测→日报→账户→对账。
2. 19 个路由逐一点击，核对菜单 active、首屏、正常/空/错误/401/403 状态；浏览器控制台无异常，网络请求路径/方法/参数与 Controller 一致。
3. prediction 生成后按 runId 查询明细；日报引用同一 item hash；重跑 selector 不改变旧日报；到期核销只追加 realization。
4. 组合回测逐事件检查 `cash + marketValue = NAV`；所有订单有 eventTime、priceSource、feeBreakdown、status/reason；期末仓位不消失。
5. 模拟账户用同一订单/价格/成本运行，和组合回测逐笔对账；周末/节假日 T+1 使用交易日历而非自然日。

### 7.6 通过/失败判定

- 任一 P0 样例失败、任一概率来源字段缺失、任一 execution 使用 qfq、任一 cancelled task 仍发布、任一历史 snapshot 随 live data 改变，整批失败。
- “页面能打开”“Controller 存在”“编译成功”“返回 HTTP 200”均不能单独判完成；必须同时满足该 MP 的手工金融样例、数据证据和错误态。
