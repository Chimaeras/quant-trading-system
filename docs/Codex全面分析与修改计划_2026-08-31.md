### P1 — 高优先级（错误结果 / 数据地基 / 质量闸）

#### P1-1 估值因子数据来源缺失 + MISSING_FINANCIAL 处理待确认
- **证据**：`market_data.pe_ratio/pb_ratio` 当前全为 NULL（大量 `MarketData(..., peRatio=null, pbRatio=null, ...)`），Java 端 grep `setPeRatio/setPbRatio` 无 `MarketData` 写入方（`DataController:346` 只写 `StockFinancialSnapshot.pbRatio`，非分时 bar）。但消费方假定其为 PIT：`CodexShortCycleScoringEngine:529-530,556-557`、`ComprehensiveScoringService:572-574`、`MultiDimScoringService:467-468`、`MarketService:70-71`。
- **影响**：`earningsYield=1/pe`、`bookToMarket=1/pb`（`CodexShortCycleScoringEngine:567-568` 仅当 >0 用，否则 `MISSING_FINANCIAL`）在大部分截面上落为 `MISSING_FINANCIAL`；估值维度因子实际退化。若 `MISSING_FINANCIAL` 被当作 0 参与排序/平均，则价值因子失真。
- **修复**：核验并写明来源；确认 `MISSING_FINANCIAL` 全集参与排序/平均前被**可靠排除而非当作 0**；在因子/回测输出加「估值因子缺失即退化」覆盖与来源披露；补回归测试断言 `MISSING_FINANCIAL` 不被当作 0。
- **待用户决策**：接入官方 PE/PB 源（需凭据）。
- **风险**：低（不改数值偏好，只加正确性兜底与披露）。**验证**：单测 + `mvn test`。
- **【已处理 2026-08-31】** 核验结论：`market_data.pe_ratio/pb_ratio` 无 Java 写入方且当前全为 NULL → 值因子（`earningsYield=1/pe`、`bookToMarket=1/pb`）在 `CodexShortCycleScoringEngine:567-568` 落为 `MISSING_FINANCIAL(NaN)`，若行业组中位数亦空则回退兜底 0。`medianField`（`:338`）显式剔除 NaN（缺失不入中位数，不被当 0）；`robustZScoresOnResiduals`（`CrossSectionFactorMath.java:52-65`）用 `1.4826*mad+1e-6` 兜底，恒定值因子列 → 全员 Z=0（中性、不产生 NaN/inf 污染聚合分）。已（a）在 `MISSING_FINANCIAL` 定义处补来源/口径 javadoc；（b）新增回归测试 `valueFactorMissingImputedFromIndustryMedianNotZero`（缺失用行业真实中位数 0.05/0.30 填充，非 0）、并在 `imputeFinancialAllMissingFallsBackToConstants` 断言全缺失时 ey/bm 兜底 0。官方 PE/PB 源仍属「需要用户决策」。

#### P1-2 PIT 股票池历史偏倚 + 同义反复的防护测试
- **证据**：`DataQualityService:174-181` `coverage_tag=LIMITED_BOOTSTRAP`，`delisted_coverage="NOT_COVERED_UNTIL_OFFICIAL_SOURCE"`；即用 `stock_info` 快照初始化，无历史 ST/改名/行业变更，退市证券不在 PIT 池 → 历史回放会把「当时已 ST/已退市」的股票当正常可交易。防护测试 `PitLeakageTest` 多数用例 mock 掉 `SecurityMasterHistoryRepository` 后断言 mock 返回值（如 `pitQueryReturnsNullForFutureListing` 断言 `findEffectiveAt(...).thenReturn(empty)` 后的 `isEmpty()`），是**同义反复**，抓不住真实 SQL 回归（例如删除 `valid_to > :as_of`）。
- **影响**：回测交易性/股票池带幸存者与 ST 偏倚；防护测试形同虚设。
- **修复**：重写 `PitLeakageTest` 为真实 JPA/SQL 语义测试（引真实测试数据或 H2，验证 `findEffectiveAt`/`findAllEffectiveAt` 的 as-of 语义，能抓「去掉 `valid_to` 子句」类回归）；回测输出补幸存者偏差/ST-停牌披露。
- **【已处理 2026-08-31】**（a）新增 `SecurityMasterHistoryPitTest`（`@DataJpaTest` + H2 内存库 + H2 方言，禁 Flyway、create-drop）用真实 JPA/SQL 语义验证 6 条 as-of 不变量：单查命中当且仅当 `valid_from<=as_of<valid_to`（null=无限期）、未来生效不含、已失效不含、`valid_from==as_of` 含而 `valid_to==as_of` 不含、批量仅返回当日生效、计数一致。（b）重写 `PitLeakageTest`：删除 7 个同义反复的 mock 用例（如 `pitQueryReturnsNullForFutureListing` 断言 mock 空值），保留 4 个纯逻辑标签/成本/状态码断言，使其只测真实信号构造而非自证 mock。注意：`@DataJpaTest` 必须显式覆盖 `spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.H2Dialect`，否则加载主 `application.yml` 的 MySQLDialect 会在 H2 上生成 `engine=InnoDB` 建表 DDL 导致失败。**真实历史池偏倚（无历史 ST/退市/改名）根治仍需官方数据源，归「需要用户决策」**；`DataQualityService` 的 `LIMITED_BOOTSTRAP`/`NOT_COVERED_UNTIL_OFFICIAL_SOURCE` 披露标签已存在。
- **风险**：中（改测试基建，需确保测试数据独立）。**验证**：`mvn test` 全套通过（290 用例）。

#### P1-3 批量导入非幂等（重跑必炸）
- **证据**：`DataController:323-354 bulkFinancial`、`:357-379 bulkMargin` 均 `repository.saveAll(rows)`，无去重/upsert；`StockMarginDaily` 带 `@UniqueConstraint(stock_code, exchange_type, trade_date)`（`entity/StockMarginDaily.java:15-17`），`StockFinancialSnapshot` 带 report_period 唯一键。EOD 导入天然重跑（重试/刷新同日）→ 撞唯一键抛 `DataIntegrityViolationException`（500）。
- **影响**：导入流水线重跑即断，而非幂等。
- **修复**：改为「查已有 key → 仅新增缺失，重复则更新或跳过」，返回 saved/updated/skipped。
- **【已处理 2026-08-31】** 两个端点均改为按唯一键 upsert：`bulkFinancial` 先查 `findByStockCodeAndExchangeTypeAndReportPeriod`，存在则更新复用原对象、不存在则新建，返回 `saved/updated/skipped`；`bulkMargin` 同理按 `(stock_code, exchange_type, trade_date)`。空列表返回 `saved=0`；键含 null 的行跳过不保存。新增 `DataControllerBulkImportTest` 5 用例：新增计 saved、重复走 update 复用原对象（不新建、不撞键）、null 键跳过、空列表零计数、margin 更新复用原对象。`StockFinancialSnapshotRepository`/`StockMarginDailyRepository` 各加一个唯一键查找方法。注意：重跑「刷新同日」时新数据会覆盖旧值（如 roe 无值会被覆盖为 null），这是刷新语义；如需保留旧值再降级为 skip 属于后续经营决策。
- **风险**：低。**验证**：单测（重复导入第二次不报错）+ `mvn test` 全套 295 通过（290 基线 + 5 新增）。

#### P1-4 K 线入库校验不一致 + 打分路径对重复交易日 order-dependent
- **证据**：单股增量入库（`HistoricalDataService:137-142`）只按 `existingDates` 过滤，**未跑** `isValidDailyBar`；批量路径（`:419`）跑了 `isValidDailyBar`。即（`high<low`、open/close 越界、零量非零价）在单股路径可入库。且 `StockTrendScoringService:150-158,391-397` 以 `bars.get(size-1)`/`[L-1]` 取「信号日/前收」，若 `(code,exchange,date)` 有重复行则可能同天两根，close 比较与指标失真。
- **影响**：异常 OHLC 污染选股输入；重复 K 线导致打分不唯一。
- **修复**：统一全部入库路径统一跑 `isValidDailyBar`；打分路径在按 `(code,exchange,date)` 去重后再取末两根。
- **风险**：中。**验证**：单测 + `mvn test`。

#### P1-5 ClassicFactorCalculator 质量闸绕过 + 流动性量纲
- **证据**：`ClassicFactorCalculator.java:208` `passMinTrendScore = shortProfile ? shortHorizonScore >= 35 : trend >= minTrendScore;` 短周期分支**把配置的 `minTrendScore` 硬编码成 35**（质量闸绕过；当前路由把短周期转 codex 引擎故此分支近死路，但存在泄漏风险）。`:196` `(avgAmount20 / Math.max(1, minAvgAmount)) * 60` 与 `:174` `volumeRatio = amount.get(size-1) / Math.max(1d, avgAmount20)` —— `Math.max(1, ...)` 把 <1 阈值压成 1、把阈值当无量纲，需与 `amount` 同单位；单位错位时流动性子分或饱和到 60 或近似为 0，信息量低。
- **影响**：阈值被绕过 / 流动性子分失真。
- **修复**：短周期分支尊重配置阈值（或显式路由/死分支注释）；修正 `Math.max(1, minAvgAmount)`/`Math.max(1d, avgAmount20)` 量纲与 0/负阈值防护；补单元测试。
- **风险**：中。**验证**：单测 + `mvn test`。

#### P1-6 市值可靠性静默剔除 size 因子
- **证据**：`HistoricalDataService:634-648 populateTotalMarketValue` 标 `type=FLOAT_CAP_APPROX, source=amount_div_turnover, reliability=UNKNOWN_LEGACY`；日志亦显示 `totalMarketValue=215756... , marketCapReliability=UNKNOWN_LEGACY`。截面中性化按市值可靠性只计「官方」可靠值 → 大量股票 size 暴露被排除在中性化之外。
- **影响**：size（A 股主溢价之一）可能未中性化，影响所评估的因子 IC。
- **修复**（本期）：在因子/回测输出**显式披露**「size 中性化因市值可靠性不足被排除」，不静默。真实可靠市值归「需用户决策」。
- **风险**：低（只加披露）。**验证**：单测 + `mvn test`。
