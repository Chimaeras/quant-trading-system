## 0. 给后续 AI 的硬约束

1. 先读再改：`paper/decide.py`、`paper/risk.py`、`paper/runner.py`、`paper/cli.py`、`strategies/ma_cross_strategy.py`、`macd_strategy.py`、`boll_strategy.py`、`StrategyBacktestEngine.java`（仅对照口径，不要把 Java 回测改成盘中引擎）。
2. 默认 **dry-run**。没有会话级 `--live` 且 `PAPER_WATCH_LIVE=1` 时，循环只写 Intent，禁止 `trade`。
3. 默认观察池为 **热门股 Top200**，人工观察标的可在此之外叠加少量代码。禁止把全市场作为默认轮询范围。
4. **只在已收盘的 bar 上出信号**（forming bar 禁止）。与 Java 回测「用未完成当日收盘」同罪，属于未来函数。
5. 策略对象里的 `self.position` **不算数**。持仓只来自妙想 `positions`。
6. V1 必须同时支持 **买和卖**（相对当前 paper 只买）。卖出数量 ≤ 柜台 `available_quantity`。
7. 同一标的两次反向信号之间必须有 **冷却**（默认 15 分钟），防止 5 分钟均线来回抽。
8. 单测禁止打网。HTTP 用 fixture。`on_bar` 用固定 close 序列断言金叉/死叉。
9. 密钥只走 `MX_APIKEY`。日志、快照、前端文案必须带「模拟」。
10. 不要改 `UnifiedScoringService`、打分权重、T+1 候选公式。T+1 最多当 **观察池名单**，不当买卖开关。

## 1. 结论与现状缺口

盘中一笔单 = 方向 × 股数 × 本 bar 是否发单。

| 层 | 现状 | 本规格要补 |
|----|------|------------|
| 方向 | 日频打分/T+1 是排序；MA/MACD/布林只在回测或未接线的 `on_bar` | 在观察池上，每根已收盘 bar 跑技术信号 |
| 股数 | 回测满仓整手；paper V1 `资金×20%/现价` 只买 | 买入沿用该公式；卖出 = 可卖数量（可配部分卖，V1 默认全卖） |
| 发单 | SimAccount 人手点；`paper.cli run --confirm` 一次性；无调度 | `watch` 循环：交易时段拉行情 → 聚合 bar → 信号 → 风控 →（live 才）下单 |

**不在范围：** 盘中重算全市场因子、LLM 读新闻下单、实盘、逐笔 Level2。

## 3. 架构（落在 Python paper 扩展，不改选股 Java）

```

    → universe（默认热门股票 + 人工观察池；可显式切换 FULL/T1）
    → 观察池批量快照（价格/涨跌幅/成交量/名称）
```

## 4. 观察池（Universe）

妙想 `/query` 不是推送，不能对全市场逐只调用；全量模式使用东方财富批量快照
完成每轮扫描，只有产生买卖信号的股票才补查妙想权威行情。

默认模式：

1. `PAPER_WATCH_UNIVERSE_MODE=WATCHLIST`：启动时调用
   `GET {PAPER_T1_BASE}/api/data/hot-stocks`，用数据管理热门榜填充默认观察池；
   再合并 SQLite 运行库中的人工标的。热门榜刷新只替换默认项，不覆盖人工项。
2. 监控页可按 6 位证券代码人工加入/移除；运行中的 watch 会检测观察池版本，
   下一轮重新加载和预热，无需重启。观察池写请求必须经过 Java `/pyapi/**`
   同源鉴权代理；持仓、活动委托与未知订单始终强制纳入运行候选，不受人工移除影响。

受控兼容模式优先级：

1. `PAPER_WATCHLIST_FILE` JSON：`{"codes":[{"stock_code":"600519","exchange_type":"SH","stock_name":"贵州茅台"}]}`
2. 否则 `PAPER_CANDIDATE_FILE`（已有 examples）
3. `PAPER_WATCH_UNIVERSE_MODE=FULL` 时，分页读取股票主数据全量；
   `PAPER_WATCH_UNIVERSE_MODE=T1` 时，读取
   `GET {PAPER_T1_BASE}/api/research/t1/candidates/{昨日}` 的 `candidates`。

规则：

- WATCHLIST/文件/T1 模式使用 `max_observe_codes`（默认 200，热门榜 TopN）；人工标的叠加在热门 TopN 之外。全量模式使用
  `max_watch_universe_codes`（默认 10000）。
- 全量模式扫描创业板/科创板，但默认不允许买入；设置
  `PAPER_ALLOW_CHINEXT/STAR=1` 后才放开对应买入，卖出不受该策略限制。
- 空名单：循环空转，不报崩溃。

T+1 分数 **不得** 映射为买/卖。用户选定技术信号为主。

## 5. K 线与「已收盘 bar」

### 5.1 周期

| 配置 | 默认 | 说明 |
|------|------|------|
| `PAPER_BAR_PERIOD_MIN` | `5` | 5 分钟一根。1 分钟噪声大、配额更紧 |

聚合：用快照的 `last` 填入当前 5 分钟桶的 high/low/close；**仅当本地时间越过桶结束**（如 09:35:00）才把 09:30–09:35 这根标为 closed，送入策略。

### 5.2 启动预热

历史分钟 K 线默认由 `kline_client` 调用东方财富官方公开 K 线接口获取，使用
`fqt=0` 原始行情；实时快照、账户、委托和模拟交易仍走妙想接口。这样避免当前
实测环境中妙想自然语言问句把“5 分钟”降级为 `DAY` 的问题。若明确设置
`PAPER_KLINE_SOURCE=mx_query`，才使用下面的兼容问句：

```text
{name}({code}) 近 80 根 5分钟 开盘价 最高价 最低价 收盘价 成交量
```

`eastmoney` 路径解析原始 `klines`，仅保留 `end_ts <= as_of` 的已收盘 bar；
`mx_query` 路径只接受显式 `dateGranularity=MIN`（表级、`field` 或字段定义）。
两条路径失败都不使用日线 fallback，直接将该票当日 `KLINE_DISABLED`，避免把日线
MA 和 5 分钟 close 拼在同一序列。

需要 closed bar 数量：

| 策略 | 最少 closed bars |
|------|------------------|
| MA_CROSS 默认 5/20 | 21 |
| MACD 12/26/9 | `26+2*9`（与现 `macd_strategy.py` warmup 一致） |
| BOLL 20/2 | 20 |

不足 → 该票 `NOOP / WARMUP`。

### 5.3 盘中追加

`watch` 每 `PAPER_QUERY_INTERVAL_SEC`（已有，默认 60）拉快照：

- 写入 **当前未结束桶** 的 high/low/close（可更新）。
- 不调用策略。
- 桶结束后冻结 OHLCV，`on_closed_bar` **恰好一次**。

禁止用未结束桶的 close 判断金叉。

## 6. 方向公式（必须与现码一致）

实现放在 `signal_adapter.py`：输入 `closes: list[float]`（仅 closed），输出 `buy|sell|hold`。不要依赖 `BaseStrategy.position`。持仓由 `positions_qty[code]` 决定能否卖、能否再买。

### 6.1 MA_CROSS（默认）

与 `ma_cross_strategy.py` / `StrategyBacktestEngine.maCross`：

- `sma` 口径与 `utils.indicators.sma`（= Java `TechnicalIndicators`）一致。
- 金叉：`s_prev <= l_prev and s_curr > l_curr` → 若无持仓则 **buy**。
- 死叉：`s_prev >= l_prev and s_curr < l_curr` → 若有持仓则 **sell**。
- 已有仓再金叉 → hold（不加仓，V1 不加仓）。
- 空仓死叉 → hold。

参数：`short_period=5`，`long_period=20`。

### 6.2 MACD

与 `macd_strategy.py`：

- `hist` 由 `utils.indicators.macd` 第三返回值（柱线，含 ×2 口径）。
- `prev_h <= 0 < curr_h` 且空仓 → buy。
- `prev_h >= 0 > curr_h` 且有仓 → sell。

### 6.3 BOLL

与 `boll_strategy.py`：

- `close <= lower` 且空仓 → buy。
- `close >= upper` 且有仓 → sell。
- 标准差 `ddof=1`，与 `bollinger_bands` 一致。

配置：`PAPER_WATCH_STRATEGY=MA_CROSS|MACD|BOLL`，一次 watch 只用一种，避免三套同时打架。

## 7. 股数

买入（与现 `decide.target_qty` 对齐）：

```text
target = floor(avail_balance * max_name_weight / last / 100) * 100
qty = min(target, floor((avail_balance - 5) / last / 100) * 100)
qty < 100 → NOOP / QTY_TOO_SMALL
```

限价买：`last * (1 + slippage_bps/10000)`，沪 2 位深 3 位。

卖出 V1：

```text
qty = available_quantity - (available_quantity % 100)   # 可卖整手
qty < 100 → NOOP / NO_SELLABLE
限价 = last * (1 - slippage_bps/10000)
```

`available_quantity` 以妙想持仓字段为准（绑定后别名映射，与 paper Position 解析同一套）。禁止用「买入日+1 个自然日」本地瞎算覆盖柜台。

V1 **不加仓、不减半仓**。有仓且再出 buy → hold。

## 8. 风控（必须改 `risk.py`）

当前 `check_intent` 对非 `BUY_LIMIT` 处理不当，卖出无法落地。改为：

- `NOOP` → PASS，不发单。
- `BUY_LIMIT` → 保留现有买入闸（确认、白名单、整手、资金、涨停附近、HALT、日限额、重复买单）。
- `SELL_LIMIT` → 新闸：

| 闸 | 拒绝码 |
|----|--------|
| 无持仓或可卖 < 100 | `NO_SELLABLE` |
| qty > 可卖整手 | `SELL_QTY_EXCEEDS_AVAILABLE` |
| 跌停锁死弱信号（pct_chg ≤ -9.0 且无真实跌停价） | `NEAR_LIMIT_DOWN` |
| 同向未完成卖单 | `DUPLICATE_SELL_ORDER` |
| HALT | 卖出 **允许**（熔断时只禁开仓，与纸面「halt 禁买」一致；在代码注释写明） |
| 冷却期内 | `COOLDOWN` |

全局：

| 项 | 默认 |
|----|------|
| `PAPER_COOLDOWN_MIN` | 15 |
| `PAPER_MAX_TRADES_PER_DAY` | 20（买+卖合计） |
| `PAPER_MAX_TRADES_PER_RUN` | 循环里改成「本分钟最多 3 笔」以防一轮打爆配额 |
| `PAPER_HALT` | 1 则禁买，仍可卖 |
| 配额 113 | 停止 live，转 dry-run 并告警 |

**组合级闸（v1.1 增补，风控对象从单票扩展到整个账户）**——watch 是循环，多只标的先后触发信号会持续开仓，单票闸拦不住组合层面的过度暴露：

| 闸 | 配置 | 默认 | 拒绝码 |
|----|------|------|--------|
| 总仓位上限 | `PAPER_MAX_TOTAL_WEIGHT` | `0.8` | `TOTAL_WEIGHT_EXCEEDED`（成交后持仓市值/总资产 不得超限） |
| 最大持仓只数 | `PAPER_MAX_POSITIONS` | `0` | `0` 表示不限制持仓只数；大于 0 时启用 `MAX_POSITIONS` |
| 现金下限 | `PAPER_MIN_CASH_RESERVE` | `5000` 元 | `CASH_RESERVE_FLOOR` |
| 大盘急跌禁开仓 | `PAPER_INDEX_CIRCUIT_BREAKER` | `1` | 观察池任一标的或基准指数 pct_chg ≤ -3% 时，当轮禁新开仓（`INDEX_CIRCUIT_BREAKER`），卖出不受影响；基准指数实时行情拉取若失败则降级为「观察池中位数跌幅」判定并在快照标注 `index_source=POOL_MEDIAN` |

确认模型：

- `watch` 启动时若 `--live`，必须同时 `--confirm` **一次**（会话确认），不要每根 bar 问人。
- 没有 `--live`：全部当 dry-run。

## 9. 主循环

```text
cli: python -m paper.cli watch [--live --confirm] [--strategy MA_CROSS]
  校验 Key、时段、watchlist
  预热 K 线
  while True:
    若非连续竞价：sleep，不请求
    若 113：break
    拉 balance/positions/orders（可每轮一次，不要每票都拉账户）
    对每只股票拉 quote（串行，防配额）
    bar_store 更新
    对每个新 closed bar:
       signal = adapter(closes)
       intent = decide_watch(...)
       intent = check_intent(...)
       记录
       if live and PASS and BUY/SELL: broker.trade 同步
    sleep interval
```

`watch-once`：只跑一轮 closed-bar 检查，便于单测和人工。

**交易日历（v1.1 增补）**：`decide.in_trading_window` 只判周末，watch 是长跑进程，遇国庆/春节等法定节假日会在休市日空转并白白消耗预热配额。循环启动前先做一次日历校验（任选其一，失败不阻塞、快照标注 `calendar_source`）：

1. `GET {PAPER_T1_BASE}/api/market/trade-calendar?date={今日}`（若 Java 已有 `TradingCalendarService` 暴露接口则优先）；
2. 降级：开盘后 5 分钟拉一次任一观察池快照，若 `market_time` 仍为上一交易日则判定休市，进程休眠至次日再查。

**状态持久化与重启恢复（v1.1 增补）**：`bar_store`、冷却表、当日成交计数都在内存，进程崩溃/重启后会全部丢失，重启首根 bar 又可能立刻触发信号造成重复建仓。要求：

- `logs/watch/{date}/state.json`：每笔 submit 后落盘 `{day_trade_count, cooldowns: {code: ts}, open_order_ids}`；
- 重启流程：重拉预热 K 线 → 读 state.json 恢复计数与冷却 → 拉柜台 orders 对账（复用 `reconcile`），未完成同向委托天然被 `DUPLICATE_*` 闸拦截；
- 当日 state 文件跨日自动归档，计数从 0 开始。

**配额预算（v1.1 增补）**：watch 一轮的请求量必须可估算，防配额在开盘半小时内打光。当前默认观察池最多 100 只，L1 使用批量快照，只有 L2 活跃池（默认最多 30 只）逐只请求执行行情；调整 L1/L2 间隔或池容量时必须同步评估日请求量。收到 113 后除停止 live 外，在快照记录当日已消耗估算值，供次日调参。

Windows 任务计划：V1 **不默认安装**。文档写明用户可自行把 `watch --live` 放进任务计划；实现不依赖 Java `@Scheduled`。

退出：Ctrl+C 写最终快照；不自动 `cancel --all`。

## 11. 配置增量

| 变量 | 默认 | 含义 |
|------|------|------|
| `PAPER_WATCH_STRATEGY` | `MA_CROSS` | `MA_CROSS` / `MACD` / `BOLL` |

## 19. v1.1 增补说明（基于全项目决策链路分析）

本节是 2026-08-18 对全仓库「产生买卖信号/计算股数」代码扫描后的结论性增补，上面各节已就地插入对应内容，此处汇总依据，供后续 AI 理解为什么加：

**扫描结论（当前项目决策点全景）：**

| 决策点 | 位置 | 盘中可用 | 股数公式 |
|---|---|---|---|
| T+1 候选打分 | `T1CandidateService`（Java） | 否，日频 | 无（只排名） |
| 技术策略信号 | `strategies/`（Python） | `on_tick` 空实现，未接线 | 无 |
| SimAccount 下单 | `SimAccountService.placeOrder` | 用日线收盘价，非盘中 | 调用方传入 |
| 回测引擎 ×2 | `StrategyBacktestEngine` / `PortfolioBacktestService` | 否 | 全仓 / cash÷n 等权 |
| Paper Live | `paper/decide.py` | **是（唯一）** | `avail×20%/last` 固定权重 |

**由此推出 watch 规格必须补、而 v1.0 未覆盖的六块：**

1. **组合级风控闸**（§8 增补）：现有 paper 风控全部是单票粒度；watch 循环会在多标的上连续开仓，必须加总仓位/持仓只数/现金下限/大盘急跌四道组合闸。持仓只数默认 5 与 `PortfolioBacktestService` 的 maxPositions 口径对齐，保证回测与模拟盘可比。
2. **交易日历**（§9 增补）：`in_trading_window` 只判周末，长跑进程必须处理法定节假日。
3. **重启恢复与幂等**（§9 增补）：冷却表/日计数在内存，进程重启即丢，会重复建仓；用 state.json + 柜台 orders 对账恢复。
4. **配额预算**（§9 增补）：默认参数下每交易日约 3100 次请求，可估算、可控制，113 时记录消耗。
5. **验收用例补 5 条**（§14 W-A13~A17）：对应上述四块 + 重启场景。
6. **告警与复盘衔接**：watch 收盘后把当日 signals/intents/submits 汇总写入 `logs/watch/{date}/daily.md`，格式对齐 `paper/artifacts.render_daily_md`；次日可用 `paper.cli reconcile --trade-date` 对账。113/UNKNOWN_SUBMIT 除日志外，向 stderr 打印醒目告警行（V1 不做外部通知渠道，钉钉/邮件留 V2）。

**V2 仓位模型路线（明确不进本规格 V1）：**

| 阶段 | 模型 | 公式 | 前置条件 |
|---|---|---|---|
| V1（本规格） | 固定权重 | `avail×w/last` | 无 |
| V2-a | 波动率倒数 | `w_i=(1/σ_i)/Σ(1/σ_j)`，σ 取预热期 5 分钟收益标准差年化 | 预热 K 线已稳定（开放问题 1 关闭） |
| V2-b | 半凯利 | `f=0.5×(p-(1-p)/r)`，p/r 由该信号历史复盘统计 | watch 运行 ≥20 个交易日、信号样本足够 |
| V2-c | 组合优化 | 目标持仓 = maxpositions 只等风险贡献 | 引入相关性矩阵，依赖更长历史 |

V1→V2 切换只改 `paper/watch/size.py` 一个文件，接口固定为 `size(signals, account, quotes, config) -> {code: qty}`，实现时先按此签名写，避免 V2 推翻。
