## 1. 项目概况（你需要知道的）

### 1.1 定位

个人开发者友好的 A 股量化选股系统：数据管理 → 多策略选股打分 → 打分回测 → 概率研究 → 组合仿真。

### 1.2 技术栈

| 层 | 技术 | 关键路径 |
|----|------|---------|
| 前端 | Vue3 + Element Plus + ECharts + TypeScript | `modules/web/src/`（views/api/stores/router） |
| 后端 | Spring Boot 3.2 + JPA + MySQL 8.0 + Flyway V1-V21 | `modules/backend-java/src/main/java/com/quant/` |
| 量化脚本 | Python 3.9+ + pandas/numpy（独立，未接入运行时） | `modules/compute-python/` |
| 数据库 | MySQL 8.0 | `modules/database/` |

### 1.3 核心业务模块

- **行情中心**：股票列表、详情、K 线、实时行情（东财 API）
- **数据管理**：历史行情更新、财报快照导入、融资余额导入、数据质量看板
- **多策略选股打分**：经典多因子 / 超跌反弹 / 趋势 / 综合三维度 / 多维度 v1 / Codex 短周期
- **T+1 次日选股闭环**：涨停基因 + 短期动量 + 量能 + 趋势位置，次日核销命中率
- **因子研究**：覆盖率 / Rank IC / Pearson IC / 分组 / 两腿价差 / 多持仓期统一报告
- **概率研究**：规则分数校准（Brier/ECE/BSS）+ Logistic 模型训练注册 + 可靠性图
- **打分回测 / 策略回测 / 组合回测**：持有期收益统计、分段稳定性（vs 沪深300）、事件驱动组合 NAV
- **模拟账户**：持仓、模拟下单、订单历史（T+1 / 整手 / raw 价 / 拒单原因）
- **研究任务工作台**：异步队列、断点续跑、取消、模板管理

### 1.4 当前转型方向

系统正从「规则分数/截面百分位」向「经样本外校准的 P(T+2上涨)、P(T+3上涨)」转型。核心路径：可信数据 → 历史重放 → 统计基线 → 概率模型 → 组合验证 → 生产化。

## 2. 迭代纪律（每轮必须遵守）

### 2.1 选题优先级

```
P0（致命） > P1（重要） > P2（次要） > P3（观察）
```

存在多个候选问题时，按以下顺序选题：

1. **选股未来函数 / 信号日数据时点错误 / 可交易性遗漏**（P0/P1）
2. **行情与入库质量**影响选股输入（重复 K 线、OHLC 异常、缺失交易日）
3. **因子定义、权重、阈值、质量闸**（不得绕过 minTrendScore、流动性等硬条件）
4. **股票池过滤**（ST、停牌、零成交量、涨跌停、上市时间）
5. **选股结果可解释性**（reasons、factor_snapshot、策略版本、数据日期）
6. **前端选股体验**（筛选、排序、导出、空状态、假设说明）
7. **选股效果度量**（打分回测口径、幸存者偏差披露、持有期统计）
8. **回测成交模型 / 模拟交易 / 组合回测**
9. **概率模型 / 概率校准 / Walk-Forward**
10. **通用工程**（性能、安全、文档、测试覆盖）

**A 类（选股准确性）问题优先于 C/D 类（回测/下单完善）。**

### 2.2 每轮工作流程

每轮迭代必须按以下步骤执行，不可跳过：

```
1. 扫描 → 定位一个具体问题（给出文件:行号 + 证据）
2. 分析 → 说明根因、影响范围、修复方案
3. 修改 → 实施代码改动（匹配周边代码风格：注释密度、命名、惯用法）
4. 验证 → 执行对应级别的验证（见 2.3）
5. 记录 → 在 .cursor/optimization-progress.md 追加本轮记录
6. 提交 → git commit（遵循 2.4 的 message 规范）
```

### 2.3 验证矩阵（改动类型 → 最低验证标准）

| 改动类型 | 必须验证 | 命令 |
|----------|---------|------|
| 因子/选股逻辑 | 相关单元测试 + 全量编译 | `mvn test -Dskip.frontend.build=true` |
| 股票池/可交易性 | 边界用例测试（ST/零量/涨跌停/退市） | `mvn test` |
| API/Controller | 编译 + 接口文档一致性核对 | `mvn clean compile` |
| 前端页面 | TypeScript 类型检查 + 构建 | `cd modules/web && npx vue-tsc --noEmit && npm run build` |
| Python 研究 | 语法检查 + 烟雾测试 | `python -m py_compile <file>` + `python main.py demo indicators/ic/label-smoke` |
| 配置/DDL | 编译 + Flyway 脚本有序性核对 | `mvn clean compile` |
| 数据层 | Repository 测试 + 抽样入库校验 | `mvn test` |

**编译必须通过才算完成。测试失败必须修复，不允许跳过或注释掉。**

### 2.4 Commit Message 规范

```
<type>(<scope>): <简要描述>

<详细说明：改了什么、为什么改、怎么验证的>

验证：<mvn/vue-tsc/py_compile 结果>
```

type: `fix` / `feat` / `refactor` / `docs` / `perf` / `test`
scope: `scoring` / `backtest` / `research` / `data` / `web` / `security` / `python` 等

### 2.5 禁止事项

- ❌ **不允许引入未来函数**：任何因子/指标/信号只能使用信号日及之前的数据
- ❌ **不允许静默造数**：数据缺失时报错或标注，不填 0/NaN/假数据冒充
- ❌ **不允许吞异常**：catch 必须有处理（日志/重抛/降级标注），不允许空 catch 或仅 print
- ❌ **不允许硬编码密码/密钥/连接串**：一律走环境变量/配置
- ❌ **不允许用 `select *` 或字符串拼接 SQL**：全参数化
- ❌ **不允许把 score 包装成概率**：`rule_score` 是规则分数/截面百分位，不是上涨概率
- ❌ **不允许在 dev 用 ddl-auto:update**：DDL 只走 Flyway
- ❌ **不允许无验证提交**：每轮必须跑对应验证
- ❌ **不允许与选股无关的大范围 UI 美化/格式化**占用迭代轮次
- ❌ **不允许无证据的因子权重调优**：权重变更必须配回测/IC 证据

## 3. 改进方向清单（按优先级排序的 backlog）

以下是结合项目当前状态、转型路线图和行业对标，整理出的可执行改进方向。每轮选取 1-2 个推进。

### 🔴 方向一：Point-in-Time 数据底座完善（P0，核心地基）

**现状**：已有 `security_master_history` + `PointInTimeUniverseProvider`，但退市/ST/行业变更的历史事件流不完整；复权因子来源是本地推算（`source=derived_local, reliability=limited`）。

**可做的改进**：
1. 接入权威退市/更名/ST 事件流（Tushare/东方财富），建立 SCD2（Type 2 Slowly Changing Dimension）历史主数据
2. 接入官方复权因子源，替换 `derived_local`，实现 raw + factor 双写原子世代
3. 完善 `financial_point_in_time`：报告期 + 公告日 + 修订版本，确保财报因子只取信号日已公告的数据
4. 建立交易日历权威源（当前是东财推导），补齐节假日/半日交易
5. 建立指数历史（沪深300/中证500/创业板指），用于基准对比与牛熊分段

**验证**：退市股回测对比（有/无 PIT 主数据）、复权因子抽样对拍。

### 🔴 方向二：历史信号可重放流水线（P0，研究核心）

**现状**：`POST /research/replay/signals` 已实现逐日 PIT + 在线打分，但全市场完整特征矩阵重算和分区续跑尚未完成。

**可做的改进**：
1. 完善特征快照分区存储（Parquet），支持按日/按股续跑与原子发布
2. 实现 Java/Python 特征矩阵对拍自动化（golden test），确保两端一致
3. 建立特征快照内容指纹（已有 hash），扩展为完整 artifact 契约校验链
4. 实现 `FeaturePipeline(feature_set_version)`：技术/量价/横截面/市场环境特征统一产出 + 质量标记

**验证**：固定 snapshot 双跑 hash 一致、特征覆盖率报告。

### 🟠 方向三：概率模型与校准深化（P1，转型关键）

**现状**：Logistic 模型（L2 正则）已有版本化训练 + 注册；概率校准有 PAV isotonic + Brier/ECE/BSS。但 Python 侧训练管线未落地（`main.py` 正式模式 `exit 4`）。

**可做的改进**：
1. **落地 Python 正式训练管线**：从 Parquet 特征矩阵 → train/cal/test split → Logistic/GBDT 训练 → 校准 → model_manifest 产出 → Java 导入注册
2. **引入树模型 challenger**：LightGBM/XGBoost 作为 Logistic 的对照组，在相同数据切分下对比
3. **完善 Walk-Forward 验证**：实现真正滚动实验（`/research/rolling-experiments`），per-window train/cal/test + embargo，而非分段统计
4. **概率校准增强**：温度缩放（Temperature Scaling）作为 PAV 的对照组；可靠性图交互式展示
5. **模型退化检测**：滚动监控 OOS Brier/IC，触发自动降级到规则轨（已有 ABSTAIN 机制，需完善监控告警）

**验证**：OOS TopN uplift 为正、Brier Skill Score 为正、扣费组合超额收益为正、可靠性图近似对角线。

### 🟠 方向四：组合级回测真实性（P1）

**现状**：事件驱动组合回测已有 MVP（现金/等权/仓位/T+1/整手/NAV JSON），但分钟撮合、成交量约束、与账户逐单对账未完成。

**可做的改进**：
1. **成交量约束**：每笔成交不超过当日成交量的 N%（默认 10%），避免假设可以买入巨量流动性差的标的
2. **重叠持仓权益曲线**：T+2/T+3 信号每日产生但持仓重叠，需正确计算资本占用与组合权益曲线（而非简单 forward return 汇总）
3. **基准对比与归因**：组合 vs 沪深300 超额收益、Brinson 归因（行业/选股效应）
4. **压力测试**：极端行情（千股跌停/流动性枯竭）下的组合表现
5. **滑点模型升级**：从固定滑点改为成交量相关的非线性滑点（Almgren-Chriss 简化版）

**验证**：组合 NAV 曲线合理性、与模拟账户逐单对账一致、基准 alpha 分解。

### 🟡 方向五：选股效果度量与反馈闭环（P1）

**现状**：打分回测有持有期收益统计 + 分段稳定性 + vs 沪深300。但因子变更后的 IC 重跑、换手率监控、信号稀疏日处理不完善。

**可做的改进**：
1. **因子变更自动重跑**：`factor_version` 变更时自动触发历史 IC/分组收益重算，避免旧因子结果混入
2. **换手率监控**：每日 TopN 与前日 TopN 的重叠率，过高换手意味着交易成本侵蚀收益
3. **信号稀疏日处理**：当合格标的不足时，明确输出「今日无合格标的」而非凑满 TopN
4. **分组收益完整性**：两腿价差的统计显著性（t-stat / HAC 标准误，已有 Newey-West 工具待用）
5. **选股结果漂移监控**：同一 result_id 的统计随行情更新是否漂移，漂移超阈值告警

**验证**：固定样例集（牛/熊/震荡各一段）的回测结果稳定性。

## 4. 金融业务正确性检查清单

迭代中涉及以下领域时，必须逐项检查：

### 4.1 未来函数（Look-Ahead Bias）

- [ ] 因子计算是否只用了信号日及之前的数据？（`isSignalBarOnTradeDate` 校验）
- [ ] 财报因子是否只取了信号日已公告的报告？（公告日 ≤ 信号日）
- [ ] 指标的 warmup 期是否足够？（EMA/MACD/BOLL/RSI 的种子收敛）
- [ ] 横截面中性化是否在截面内完成？（不跨日使用未来截面信息）

### 4.2 幸存者偏差（Survivorship Bias）

- [ ] 历史回测是否使用了 PIT 证券主数据？（退市日 ≤ as_of 剔除）
- [ ] 股票池是否按信号日的实际状态过滤？（当时的 ST/停牌/上市天数）
- [ ] 行业归属是否按信号日的行业？（而非当前行业）

### 4.3 交易成本与成交约束

- [ ] 佣金是否双向计算？（买入 + 卖出，含最低佣金 5 元）
- [ ] 印花税是否仅卖出方计算？（万五）
- [ ] 滑点是否合理？（固定万二 or 成交量相关）
- [ ] T+1 是否正确执行？（买入当日不可卖，FIFO 批次消耗）
- [ ] 涨跌停封板是否拒成交？（按板块区分 5%/10%/20%/30%）
- [ ] 停牌（零成交量）是否跳过成交？
- [ ] 整手约束是否执行？（A 股 100 股一手）

### 4.4 概率校准正确性

- [ ] 标准化参数是否仅在 fit/train 窗拟合？（不在样本外重新拟合）
- [ ] train/test 切分是否有 embargo？（`lastTrainExit < testStart`，purge 重叠窗口）
- [ ] 校准参数是否仅在 fit 窗拟合？（PAV/isotonic/温度缩放）
- [ ] Brier Score 的基线是否是 fit 窗的 base rate？（非 eval 窗）
- [ ] 多 horizon IC 是否做了 Newey-West HAC 调整？

### 4.5 数据版本与可复现

- [ ] 每次实验是否记录了 data_snapshot_id + feature_set_version + model_version？
- [ ] 同一 snapshot 重跑是否产出相同 hash？
- [ ] 前复权数据是否不用于成交价？（成交价一律走 raw 不复权价）

## 6. 明确不做（当前阶段）

- ❌ 毫秒级/分钟级高频交易
- ❌ 深度学习（Transformer/GNN 等），在数据与验证框架稳定前不引入
- ❌ 新闻 NLP / 舆情选股
- ❌ 自动连接券商实盘（风控/数据/仿真未达标前）
- ❌ 微服务拆分（单体应用足够个人使用）
- ❌ 复杂组合优化（Markowitz/Black-Litterman，当前等权足够）
- ❌ 无证据的因子权重「调优」
