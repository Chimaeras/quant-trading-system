# Quant Trading System：2–3 日上涨概率选股优化迭代规划

> 文档日期：2026-07-30  
> 适用项目：`quant-trading-system`  
> 文档性质：只定义产品、研究、数据与工程迭代计划，不直接实施代码改动  
> 核心目标：基于历史时点可得数据，每个交易日筛选未来 2–3 个交易日上涨概率较高的 A 股，并通过可复现、无泄漏、含真实交易约束的回测持续验证与迭代。

---

## 1. 执行摘要

项目已经不是一个空白原型。当前已具备行情管理、五类选股/打分、统一选股工作台、异步任务、可交易性过滤、因子快照、forward return 回测、Rank IC、分组收益、换手率、分段稳定性、简易 walk-forward、日报、自选股、数据质量看板和模拟账户等能力；后端 166 个测试通过，前端类型检查通过。

但是，系统目前的核心输出仍是“规则分数/截面百分位”，还不能被解释为“上涨概率”。围绕目标场景，当前最重要的工作不是继续增加选股页面或再造一套人工权重，而是完成以下转型：

1. 从“当前股票表 + 可变前复权行情”升级为**历史时点可复现的数据底座**。
2. 从“保存过的选股结果做收益统计”升级为**任意历史区间可重放的研究流水线**。
3. 从“Score 90”升级为**经样本外校准的 `P(T+2上涨)`、`P(T+3上涨)`**。
4. 从“单笔 forward return 汇总”升级为**信号研究 + 组合回测 + 概率校准三层验证**。
5. 从“固定公式版本”升级为**实验、模型、特征、数据快照均可追溯的迭代闭环**。

建议按“可信数据 → 历史重放 → 统计基线 → 概率模型 → 组合验证 → 生产化”的顺序推进。模型应从可解释的逻辑回归和现有规则基线开始，树模型作为 challenger；在数据与验证框架稳定前，不建议引入深度学习、新闻 NLP 或自动实盘。

## 2. 目标定义与成功标准

### 2.1 产品输出定义

每日收盘数据完成后，系统针对当日可交易股票池输出：

| 字段 | 含义 |
|---|---|
| `signal_date` | 信号所使用数据的截止交易日 |
| `entry_assumption` | 默认下一交易日开盘可成交；同时支持 VWAP/收盘等研究口径 |
| `prob_up_t2` | 从实际入场价到第 2 个持有交易日退出价，净收益大于阈值的校准概率 |
| `prob_up_t3` | 从实际入场价到第 3 个持有交易日退出价，净收益大于阈值的校准概率 |
| `expected_return_t2/t3` | 样本外期望净收益，可选但不替代上涨概率 |
| `uncertainty` | 置信区间、模型分歧或低样本告警 |
| `rank` | 当日可交易股票池内排序 |
| `reasons` | 主要正/负贡献、触发条件、风险与失效条件 |
| `model_version` | 模型、特征、标签和代码版本 |
| `data_snapshot_id` | 使用的数据快照和数据截止时间 |

“上涨”的默认标签建议定义为：

```text
y_h = 1[(exit_price_h × (1 - sell_cost - slippage)
         / (entry_price × (1 + buy_cost + slippage)) - 1) > min_net_return]
```

- `h ∈ {2, 3}`，分别建模，不把 T+2/T+3 混为同一个标签。
- 默认 `entry_price = signal_date 下一交易日开盘价`。
- 默认 `exit_price_h = 入场后第 h 个持有交易日收盘价`。
- `min_net_return` 初始可设为 0；研究中另增 0.5%、1% 等阈值，但必须作为不同标签版本。
- 涨停无法买入、停牌、跌停无法卖出等不能简单删除样本，必须按成交状态单独记录并进入组合回测。

### 2.2 第一阶段业务成功标准

不是要求“保证上涨”，而是要求在严格样本外测试中证明：

- Top10/Top20 的 T+2、T+3 胜率显著高于同日可交易股票池基准胜率。
- 预测概率有基本校准性：例如预测 60% 的样本组，实际胜率应接近 60%，并展示可靠性图。
- 扣除佣金、印花税、滑点后，TopN 组合相对基准仍有正的样本外超额收益。
- 不同年份、牛熊震荡环境、大中小市值、主要行业中不过度依赖单一时期或单一板块。
- 模型退化、数据缺失或市场环境越界时，系统允许输出“今日无合格标的”。

建议上线闸门由历史基线计算后固化，不提前拍脑袋指定绝对值。首版至少同时满足：样本外 TopN uplift 为正、T+2/T+3 中至少一个标签 Brier Skill Score 为正、扣费组合超额收益为正、最近两个滚动窗口没有同时失效。

### 2.3 明确非目标

- 不承诺个股一定上涨，不把分数包装成确定性结论。
- 当前阶段不做毫秒级/分钟级高频交易。
- 风控、数据和仿真未达标前不自动连接券商实盘。
- 不以深度学习复杂度作为进度指标。
- 不用全样本反复调参后再把同一段历史称为“样本外”。

## 3. 现有能力盘点

### 3.1 已具备且应保留的能力

| 能力 | 当前实现 | 评价 |
|---|---|---|
| 多策略选股 | 经典多因子、趋势、综合、多维度、超跌反弹 | 可作为 baseline/challenger，不应全部删除 |
| 短周期公式 | `CodexShortCycleScoringEngine`，T/F/R 因子、截面中性化与百分位 | 已接近短周期目标，但输出仍是 score，不是概率 |
| 时点控制 | 信号日 K 线校验、财报公告日过滤、次日开盘入场 | 方向正确，应推广为统一 PIT 契约 |
| 可交易性 | ST、上市时长、零成交、涨跌停等过滤 | 已有良好基础，但历史名称/状态仍非 PIT |
| 因子追溯 | `factor_version`、`factor_snapshot`、公式审计 | 可扩展为完整 experiment/model/data lineage |
| 因子评价 | Rank IC、分组收益、T/F/R 子因子 IC | 已实现研究核心的一部分 |
| 回测成交成本 | 佣金、卖出税、固定滑点、次日开盘 | 比简单 close-to-close 更可靠 |
| 稳定性工具 | 前后半段、分窗、换手率 | 可保留，但需重构成真正的滚动样本外验证 |
| 质量与测试 | 数据质量页面；166 个后端测试；前端类型检查通过 | 工程基线良好，缺集成/数据契约/研究黄金样例 |

### 3.2 现有功能与目标的主要错位

| 目标问题 | 当前状态 | 影响 | 优先级 |
|---|---|---|---|
| 输出 2–3 日上涨概率 | 现有核心是 3–5 日规则公式与百分位分数 | `Score=90` 不能解释为 90% 上涨概率 | P0 |
| 任意历史日重算信号 | 回测依赖 `selector_result` 中过去实际保存过的结果 | 信号日稀疏，无法形成稳定训练样本和完整历史回放 | P0 |
| 历史时点股票池 | `stock_info` 主要是当前名称、行业、状态，代码已明确披露幸存者偏差 | 退市股、历史 ST、行业变更可能导致前视/幸存者偏差 | P0 |
| 稳定的价格历史 | 当前前复权数据直接用于因子和模拟成交，且文档已提示会被后续除权事件改写 | 同一历史回测会随未来公司行为变化；成交价也不应直接用前复权价 | P0 |
| 真正 walk-forward | 当前仅把回测区间切成连续窗口并重复统计，没有训练、校准、选参和 embargo | 不能证明模型在未知未来上的泛化能力 | P0 |
| 概率质量评估 | 有胜率、IC、收益，无 log loss、Brier、ECE、校准曲线 | 无法判断概率是否可信 | P1 |
| 组合级真实性 | 打分回测把每天/每股 forward return 汇总，没有资本占用和重叠持仓权益曲线 | 每日信号与 2–3 日持仓重叠时，收益容易被重复计算 | P1 |
| 基准与环境 | 缺指数历史、动态基准和正式牛熊分段 | 不能区分选股 alpha 与市场 beta | P1 |
| 研究/生产一致性 | Java 是主运行时，Python 仍是独立脚本且依赖很薄 | 训练模型难以复现或稳定上线 | P1 |
| 失败样本处理 | 无行情、无法买卖会被 skip；汇总主要基于可计算样本 | 若被跳过样本系统性偏差，绩效会被高估 | P1 |
| 数据版本 | 行情行没有 source、adjust factor、vendor timestamp、snapshot/version | 无法复现某次实验当时使用的数据 | P1 |

## 4. 市面常见量化系统对标与差距

对标重点不是照搬所有功能，而是提取与短周期选股目标直接相关的研究规范。

| 对标对象 | 常见核心能力 | 本项目现状 | 应吸收的能力 |
|---|---|---|---|
| 聚宽 | 历史回测、财务数据按当时可见时间取数、研究/回测 API | 财报已有公告日过滤，但股票主数据和价格版本还不完整 | 统一 point-in-time 数据接口与“数据可用时间”语义 |
| 米筐/RQAlpha | 基准、滑点、手续费、最小佣金、成交量限制、撮合与绩效报告 | 有固定成本和涨跌停，缺成交量占比、最小佣金、基准与完整组合账户 | 插件式成交模型、容量约束、基准和组合级报告 |
| Microsoft Qlib | 数据处理、训练、预测、记录、回测的配置化工作流；train/valid/test；rolling task；实验记录 | 打分/回测链路存在，但训练、模型记录、数据集切分缺失 | 建立 dataset/feature/model/prediction/record 五层研究工作流 |
| QuantConnect/LEAN | 动态股票池、幸存者偏差控制、现实成交模型、walk-forward、回测/优化/实盘结果联动 | 已披露偏差但没有消除；分窗不等于 WFO | 动态 PIT universe、滚动训练、现实模型和 live-vs-backtest 对账 |

参考依据：

- 聚宽官方 API 文档说明财务查询会按查询日期选择此前已发布数据，以避免未来函数：<https://cdn.joinquant.com/help/img/JoinQuantAPI.pdf>
- 米筐官方回测文档覆盖滑点、成交量限制、手续费和性能分析：<https://rqopen.ricequant.com/doc/quant/backtest.html>
- Qlib 官方 workflow 将数据加载/处理/切片、模型训练/推理和信号/回测记录纳入一次可追踪执行，并明确 train/valid/test 分段：<https://qlib.readthedocs.io/en/stable/component/workflow.html>
- Qlib rolling task 提供 expanding/sliding 与 `trunc_days` 防未来信息泄漏：<https://qlib.readthedocs.io/en/latest/reference/api.html>
- QuantConnect 官方研究指南强调动态股票池以规避幸存者偏差：<https://www.quantconnect.com/docs/v2/writing-algorithms/key-concepts/research-guide>
- QuantConnect 官方 walk-forward 文档强调按历史窗口优化并在后续时期使用，且指出过高优化频率会加剧过拟合：<https://www.quantconnect.com/docs/v2/writing-algorithms/optimization/walk-forward-optimization>
- 概率校准应使用可靠性图并结合 Brier/log loss 等严格概率评分：<https://scikit-learn.org/stable/modules/calibration.html>

结论：本项目的 UI 和功能数量已接近个人量化工具，但研究底座仍弱于成熟平台。下一阶段应把资源从外围功能转向 PIT 数据、实验可复现、概率校准和组合仿真。

## 5. 建议的目标架构

```text
原始数据层
  ├─ raw_price（不复权 OHLCV、vendor、ingested_at、版本）
  ├─ corporate_action / adjust_factor
  ├─ security_master_history（上市/退市/ST/名称/行业的有效期）
  ├─ financial_point_in_time（报告期、公告日、修订版本）
  └─ benchmark / trading_calendar
        ↓
时点数据服务 PointInTimeDataService(as_of)
        ↓
特征流水线 FeaturePipeline(feature_set_version)
  ├─ 技术/量价/横截面/市场环境
  ├─ 质量标记与缺失处理
  └─ feature_snapshot
        ↓
标签流水线 LabelPipeline(label_version: T2/T3)
        ↓
实验流水线 ExperimentRunner
  ├─ train / validation / calibration / test
  ├─ purged rolling split + embargo
  ├─ baseline / challenger
  └─ experiment registry + artifacts
        ↓
预测服务 PredictionService(model_version, as_of)
  ├─ prob_up_t2 / prob_up_t3
  ├─ uncertainty / reason codes
  └─ abstain / no-candidate gate
        ↓
组合与仿真 PortfolioBacktestEngine
  ├─ 成交、容量、T+1、涨跌停、停牌
  ├─ 资金/持仓/重叠信号
  └─ benchmark / attribution / stress test
        ↓
每日选股工作台 + 模型监控 + 回测研究页
```

Java 继续承担 API、任务编排、用户功能、权限和结果展示；Python 建议承担特征矩阵构建、模型训练、概率校准和统计检验。两者通过明确的数据表/Parquet artifact 和版本契约协作，避免把训练算法硬塞进 Java，也避免 Python 脚本游离于主系统之外。

## 6. 分阶段迭代路线图

### 阶段 0：口径冻结与基线固化（P0，1 个迭代）

目标：先让所有 Agent 对“预测什么、何时可用、如何成交”使用同一套定义。

任务：

1. 新增《研究口径规范》，固定 T+2/T+3 标签、入场/退出、成本、涨跌停和停牌处理。
2. 将 `CodexShortCycleScoringEngine` 明确标记为 `rule_score`，前端不得显示为“上涨概率”。
3. 为现有五套策略建立 baseline 卡片：公式版本、适用周期、必需数据、已知偏差、当前回测覆盖日数。
4. 保存当前基准报告：信号数、覆盖率、T+2/T+3 胜率、平均收益、Rank IC、分组收益、跳过率。
5. 统一时间字段语义：`trade_date` 改在新模块中称 `signal_date`，另有 `data_cutoff_time`、`prediction_created_at`、`entry_date`。

验收：任一信号都能回答“使用了截至何时的数据、预测哪个持有期、按什么成交、输出是分数还是概率”。

### 阶段 1：Point-in-time 数据底座（P0，2–3 个迭代）

目标：消除最影响可信度的未来信息与不可复现问题。

任务：

1. 拆分价格口径：
   - `market_price_raw` 保存不复权 OHLCV，专供成交仿真。
   - `adjust_factor` 保存每日复权因子和来源。
   - 特征计算按“截至 signal_date 可知的复权因子”生成连续序列，不直接依赖会回写历史的最新 qfq。
2. 建立 `security_master_history`：代码、名称、ST/退市状态、行业、上市/退市日期、`valid_from/valid_to`。
3. 引入真实交易日历表，覆盖法定节假日、临时休市；不再用“工作日”近似。
4. 行情、财务、证券主数据增加 `source`、`source_record_time`、`ingested_at`、`data_version`、质量状态。
5. 财报维持公告日过滤，并增加修订/更正公告版本；公告日为空的旧数据只允许降级研究，不进入正式模型训练。
6. 指数数据至少接入沪深 300、中证 500、中证 1000、上证指数，供市场环境和基准使用。
7. 总市值不再默认使用成交额/换手率推算值作为可靠中性化输入；保留 `value_source` 和 reliability gate。

验收：

- 指定 `as_of=2023-06-30` 查询时，不出现该日之后上市、改名、ST 变化、财报公告或公司行为信息。
- 同一个 `data_snapshot_id` 重跑得到完全一致的数据和特征。
- 原始成交价与复权特征价职责分离。
- 数据质量页能显示 source、版本、复权因子覆盖、历史证券状态覆盖和真实交易日历差异。

### 阶段 2：历史重放与标签工厂（P0，2 个迭代）

目标：不依赖过去是否点过“运行选股”，可在任意历史区间逐日重算全市场信号。

任务：

1. 新建 `HistoricalReplayService`：输入策略/特征版本、起止日、股票池规则，按交易日重放 PIT 特征与打分。
2. 新建 `feature_snapshot` 或分区 Parquet artifact；键至少为 `(snapshot_id, signal_date, stock_key, feature_set_version)`。
3. 新建 `label_snapshot`，分别生成 T+2/T+3 二分类标签、净收益、最大有利/不利变动、成交状态。
4. 标签生成时保留所有拒单/无法退出样本，不用删除来“净化”结果；分别统计 `not_buyable`、`suspended`、`not_sellable`、`delisted`。
5. 任务必须幂等、可断点续跑、可分区重算；不得覆盖旧实验所引用的数据快照。
6. 生成数据集健康报告：每日股票池规模、特征缺失率、标签覆盖率、各类 reject 率、行业和市值分布。

验收：至少 3–5 年历史能逐日重放；任取 20 个日期人工核对无未来 K 线/财报/证券状态；重复运行 hash 一致；标签日与交易日严格对齐。

### 阶段 3：统计研究基线升级（P1，1–2 个迭代）

目标：在训练 ML 前，先弄清现有规则到底有没有稳定信息含量。

任务：

1. 把因子研究页与 `ScoringBacktestService` 的 Rank IC 合并为统一研究报告。
2. 对 T+1/T+2/T+3/T+5 输出：Pearson IC、Rank IC、ICIR、正 IC 比例、分组单调性、Top-bottom spread。
3. 增加置信区间、block bootstrap 或 Newey-West/HAC 统计，处理每日重叠持有期造成的序列相关。
4. 逐因子做覆盖率、稳定性、缺失机制、极值、行业/市值暴露和相关矩阵/VIF。
5. 增加环境切片：年份、指数趋势/波动、市场宽度、行业、市值、流动性。
6. 建立 naive baselines：全市场基础胜率、随机 TopN、等权规则、仅 1 日动量、仅超跌、现有 Codex 规则。
7. 因子消融实验：逐项移除 T/F/R 及其子因子，不以全样本最优为结论。

验收：每个保留因子都有 PIT 样本外证据；没有证据的因子降权、隔离为实验项或删除；报告可以解释收益来自市场、行业还是个股排序。

### 阶段 4：概率模型 MVP（P1，2–3 个迭代）

目标：输出真正可解释、可校准的上涨概率。

模型阶梯：

1. `Baseline 0`：全市场/分环境基础概率。
2. `Baseline 1`：现有规则分数做单调概率映射（isotonic 或 sigmoid），验证“仅校准是否足够”。
3. `Champion 候选`：带正则的 Logistic Regression，便于审计和解释。
4. `Challenger`：LightGBM/XGBoost 类梯度提升树，只有在严格 OOS 明显胜出后才替换 champion。

任务：

1. T+2、T+3 建立独立模型；可共享特征但模型与校准器版本分开。
2. 使用时间顺序 train/validation/calibration/test；标签跨度产生重叠时使用 purged split + 至少 h 日 embargo。
3. 预处理器只在训练窗拟合；截面 winsorize/standardize、中性化和缺失插补不得看到验证/测试未来分布。
4. 概率校准器只在独立 calibration 窗拟合；比较 sigmoid、isotonic，低样本优先 sigmoid。
5. 指标：ROC-AUC 只作辅助；核心为 log loss、Brier、Brier Skill Score、ECE/可靠性图、TopK precision、lift、净收益。
6. 解释：逻辑回归系数；树模型使用 SHAP/feature contribution，并输出正负贡献与数据质量告警。
7. 不确定性：滚动窗口模型分歧、bootstrap 区间或校准桶样本量；低置信度允许 abstain。
8. 防止概率虚高：设置概率上限/最小桶样本、外推检测和最近校准窗口有效性检查。

验收：

- 概率可靠性图、Brier/log loss 均来自从未参与训练/选参/校准的最终测试段。
- 高概率桶实际胜率整体单调上升；若不单调，产品不得展示“上涨概率”，只能退回 rank score。
- 与现有规则相比，至少在一个核心持有期上同时改善概率指标和扣费 TopN 表现，另一个持有期不得显著恶化。

### 阶段 5：真正的滚动样本外与实验注册（P1，2 个迭代）

目标：把当前“分窗统计”升级为真正 walk-forward。

建议默认窗口：

```text
训练 24–36 个月 → 验证/选参 3–6 个月 → 校准 3 个月 → 测试 1–3 个月
按月或按季度滚动；train 可 expanding 或 sliding；边界做 purge + embargo。
```

任务：

1. 将现有 `WalkForwardService` 更名为“分段稳定性”，避免概念误导。
2. 新建真正 `RollingExperimentRunner`，每个测试窗只能使用此前数据训练和校准。
3. 建立 `experiment_run`、`model_registry`、`prediction_snapshot`、`artifact_manifest`。
4. 记录 git commit、配置、随机种子、依赖锁、训练时间窗、特征/标签/数据版本、指标和 artifact hash。
5. champion/challenger 规则自动化，但晋升仍需人工确认；禁止同一测试窗被重复用于选参。
6. 增加多重尝试披露：记录试验总数、参数搜索空间和最终选择依据，降低 backtest overfitting。

验收：从任一线上预测可反查到模型、训练窗、特征和数据；清空临时目录后可从 registry 重现；每个滚动窗都能证明训练截止早于测试开始。

### 阶段 6：组合级回测与 A 股现实成交（P1，2–3 个迭代）

目标：证明“高概率排序”在真实资金与持仓约束下仍可用。

任务：

1. 新建事件驱动 `PortfolioBacktestEngine`，管理现金、持仓、T+1、每日新信号和 2/3 日重叠持仓。
2. 支持 TopN、概率阈值、最大持仓数、单票上限、行业上限、等权/波动率权重。
3. 成交模型支持：固定滑点、成交额占比冲击、最大参与率、最小佣金、涨跌停/一字板、停牌延迟退出。
4. 不可成交订单有状态机：pending、partial、rejected、expired；不能直接从收益样本中消失。
5. 输出权益曲线、最大回撤、Sharpe、Sortino、Calmar、换手、容量、持仓集中度、胜率、盈亏比、尾部损失。
6. 对比沪深 300/中证 500/中证 1000及股票池等权基准，输出超额收益、tracking error、information ratio、beta 和行业归因。
7. 压力测试：成本 ×2/×3、延迟一天入场、TopN 变化、概率阈值变化、极端行情、随机丢失部分信号。

验收：信号级收益和组合权益能对账；现金与持仓守恒；所有订单有最终状态；扣费、容量和延迟压力下不过度脆弱。

### 阶段 7：每日生产流水线与监控（P2，2 个迭代）

目标：稳定生成每日候选，并监控模型是否失效。

任务：

1. 固定每日任务 DAG：数据同步 → 质量闸 → PIT 快照 → 特征 → 预测 → 组合建议 → 报告。
2. 质量闸失败、数据日期落后、股票池异常缩小、特征漂移时停止发布，不沿用静默旧结果。
3. 每日预测结果保存，不允许事后被新模型覆盖；新模型产生新版本。
4. 监控输入漂移（PSI/KS）、预测分布、覆盖率、拒单率、行业集中、概率校准延迟指标。
5. 标签成熟后自动回填 T+2/T+3 实际结果，形成 prediction-vs-outcome 看板。
6. champion 退化规则：连续窗口 Brier Skill、TopN lift、净超额或覆盖率跌破门槛时降级到规则 baseline/不出信号。
7. 保留人工观察与模拟盘阶段；至少经过若干月 shadow/paper trading 后再讨论实盘。

验收：任务可重试且幂等；失败不会发布半成品；每日候选能自动完成事后验证；线上预测与历史回测使用同一特征实现。

### 阶段 8：产品体验与解释增强（P2，1–2 个迭代）

目标：让用户看到“概率、证据、风险”，而不是只看到漂亮分数。

页面建议：

1. 每日概率选股页：T+2/T+3 概率、净期望收益、排名、置信度、数据质量、主要贡献、失效条件。
2. 概率校准页：预测桶 vs 实际胜率、样本量、Brier/log loss、时间滚动。
3. 实验对比页：champion/challenger、训练/验证/测试窗、版本、指标差异。
4. 组合回测页：权益曲线、基准、回撤、持仓、订单拒绝、成本和压力测试。
5. 选股详情页：同一股票近 20 日概率轨迹、特征变化、模型分歧、历史相似场景。
6. 所有页面明确展示：“概率为历史条件概率估计，不构成收益保证或投资建议”。

## 7. 特征迭代建议

### 7.1 第一批：只使用现有数据可可靠构建的特征

- 1/2/3/5/10/20 日收益及加速度，去除当日行业/市场收益后的残差动量。
- 隔夜 gap、日内 open-to-close、收盘位置、振幅、连续上涨/下跌天数。
- 成交额、换手率、量比、成交额分位、量价背离、缩量回调/放量突破。
- 5/10/20 日 realized volatility、downside volatility、ATR、最大 gap、Amihud illiquidity。
- MA 斜率与排列、RSI 形态、MACD 柱变化；避免同一信息重复堆多个高度相关指标。
- 市场/行业宽度、指数 1/5/20 日收益、波动状态、成交额状态。
- 上市时长、板块、ST、涨跌停距离、近期涨停次数、是否可交易。

### 7.2 第二批：需要补数据后再做

- 自由流通市值、可靠总市值、真实行业历史分类。
- 融资融券变化、龙虎榜、解禁、股东减持、公告事件。
- 财务公告 surprise 与公告后漂移，而不是把静态 PE/ROE 高权重塞入 2–3 日模型。
- 北向资金须先确认历史口径、可得时间和规则变化；不可只抓当前截面。

### 7.3 暂缓

- 新闻/社交情绪 NLP：除非能获得带发布时间、去重、修订和稳定覆盖的历史语料。
- 深度学习时序模型：样本、数据版本和严格 OOS 未建立前，复杂模型只会扩大过拟合空间。
- 分钟级微观结构：当前主要数据与目标是日线 2–3 日，先把日频闭环做好。

## 9. 测试与验证策略

现有 166 个测试主要证明函数和服务契约没有回归，但概率研究还需要以下测试层次：

1. **黄金指标测试**：RSI/MACD/收益/复权序列与可信库固定样例对比。
2. **PIT 防泄漏测试**：在未来插入财报、改名、ST、除权事件后，过去 `as_of` 结果不得变化。
3. **标签边界测试**：春节长假、停牌、涨跌停、退市、缺失 bar、上市不足、不同板块限制。
4. **训练隔离测试**：验证/测试数据的统计量变化不得影响训练预处理器和模型参数。
5. **滚动窗口测试**：每个模型的最大训练可用时间严格早于测试信号时间，并满足 purge/embargo。
6. **成交对账测试**：现金、持仓、市值、手续费、印花税、部分成交和 T+1 守恒。
7. **数据契约测试**：供应商字段、单位、前后复权、时区、重复数据和 schema 漂移。
8. **集成测试**：Testcontainers MySQL 跑数据导入 → 特征 → 预测 → 回测完整链路。
9. **回放确定性测试**：固定 snapshot/config/seed 两次运行 artifact hash 与指标一致。
10. **前端 E2E**：每日预测、实验对比、回测任务和失败状态的关键路径。

CI 建议分层：PR 跑单元/契约/小型黄金数据；夜间跑 1 年历史集成回放；周末跑完整滚动实验和压力测试。

## 12. 关键风险与决策点

### 12.1 必须优先确认的数据决策

1. 是否引入带历史证券状态、公司行为、指数、可靠市值的正式数据源。
2. 数据许可证是否允许本地长期存储、训练和回测。
3. 至少需要多少年历史；建议覆盖完整牛熊震荡周期，而非只看最近一年。
4. 财务/事件数据公告时间能否可靠获得；不能获得则不要进入正式短周期模型。

### 12.2 统计风险

- 2–3 日上涨噪声大，基础胜率会随市场状态变化；准确率不能单独使用。
- 每日滚动信号的 T+2/T+3 标签高度重叠，普通独立同分布显著性检验会过于乐观。
- 反复试因子、窗口、阈值会形成隐性多重检验；必须记录全部实验。
- 若只保留当前上市股票，策略结果可能被幸存者偏差严重抬高。

### 12.3 工程风险

- `ddl-auto:update` 不适合承载研究数据模型的长期演化；建议引入 Flyway/Liquibase 版本迁移。
- Maven 构建中执行 `npm install` 影响可重复与速度；建议 CI 分离构建并使用锁文件安装。
- 训练依赖必须锁版本；模型 artifact 应记录 Python、库版本和 seed。
- 供应商接口若无 SLA，需保留原始响应、重试、断路、字段契约告警和替代源。

## 13. 最终建议

本项目下一轮不要把目标设成“再新增 20 个功能”，而应设成：

> 在一个冻结的数据快照上，能够逐日重放至少 3–5 年历史，生成无未来信息的 T+2/T+3 标签；训练并校准一个可解释概率模型；通过严格滚动样本外与现实组合回测证明其相对规则基线具有稳定增益；最后每天自动生成可追溯、可放弃输出的候选名单。

其中优先级最高的不是模型，而是四件事：PIT 股票池、原始价/复权因子分离、历史重放、真正滚动样本外。只有这四项完成，后续“上涨概率”才有可信含义。

## A.4 建议增加「Thin Slice / 最小可信闭环」（插在阶段 1～2 之间）

全文路线偏「平台级」。个人量化仓库建议增加 **M0.5 最小可信闭环**，用有限股票池证明链路，再扩全市场：

```text
目标股票池：沪深 300（或主板流动性 Top500）× 最近 2 年
数据：在「已知偏差已披露」前提下，允许暂用现有行情表做研究原型
输出：逐日重放 → T+2/T+3 标签 → 规则分数校准 baseline → 可靠性图 + Brier
```

## A.5 双轨产品共存（rule_score ↔ probability）

转型期 UI/API 建议强制双轨，避免用户把分数当概率：

| 轨道 | 字段 | 展示规则 |
|---|---|---|
| A 规则轨 | `rule_score` / `rank` | 文案固定为「规则分/截面排名」，禁止「概率」字样 |
| B 概率轨 | `prob_up_t2/t3` | 仅当模型通过校准单调性闸门后展示；否则灰显或隐藏 |
| 共存期 | `output_kind` | 枚举：`RULE_SCORE` / `CALIBRATED_PROB` / `ABSTAIN` |

选股工作台默认排序：有概率且通过闸门时按概率；否则按规则分，并显示「今日仅规则排序，概率模型未发布/已降级」。

## A.6 标签与建模补充建议

正文以绝对净收益上涨为主标签，建议**并行研究**下列变体（必须不同 `label_version`，不得覆盖默认）：

1. **相对上涨标签**：`y = 1[净收益 > 同日可交易池中位数]` 或 `> 基准指数同期收益`。牛市中绝对胜率虚高时，相对标签更能刻画选股 alpha。
2. **Meta-labeling（强烈建议作为 Logistic MVP 变体）**：用 `CodexShortCycle` 规则给出交易方向/是否入选，概率模型只预测「该信号是否赚到钱」。样本更少、解释更贴合现有引擎，且与正文 Baseline1→Champion 路径兼容。
3. **收益回归头（可选）**：在分类概率之外，用同一特征预测期望净收益，仅作排序辅助，不替代校准概率。
4. **多重检验披露**：因子消融与参数搜索须记录试验次数；报告中至少披露「尝试次数 / 最终入选」，条件允许时用 FDR（如 BH）或预注册特征清单，降低隐性 p-hacking。
5. **组合交叉验证备选**：除滚动 WFO 外，可评估 Combinatorial Purged CV（Lopez de Prado）作为稳健性附录，不作为唯一晋升依据。

## A.7 A 股微观结构与个人可交易性（正文可再钉死）

已有涨跌停/T+1/停牌，建议在口径与组合引擎中显式补充：

| 项 | 建议 |
|---|---|
| 开盘价成交假设 | 默认「次日开盘」须区分：集合竞价成交价 vs 连续竞价首笔；无法建模时披露为乐观假设 |
| 整手约束 | A 股 100 股整数倍；小资金 TopN 等权会因整手产生显著偏差，组合回测必须建模 |
| 最小佣金 | 券商常见 5 元下限；短持有、小金额时成本占比大，应进入默认成交模型 |
| 板块涨跌幅 | 主板/注册制/ST 已有部分规则，须与 `TradingLimitRules` 单一真相源对齐，禁止研究模块另写一套 |
| 个人权限股票池 | 若使用者无创业板/科创板权限，生产选股默认增加「可交易板块白名单」过滤，并与回测股票池一致，避免回测可买、实盘不可买 |
| 半日市/临时停市 | 交易日历须支持半日；标签的「第 h 个持有交易日」按日历会话计数，不按自然日 |

## A.8 计算、存储与性能预算（否则 M1 会卡死）

建议在阶段 1～2 开工前写一页《研究算力预算》：

1. **规模估算**：全 A × 5 年 × 日频特征矩阵的行数、Parquet 体积、单次全市场重放墙钟时间。
2. **分区策略**：按 `signal_date` 月分区；特征宽表与元数据索引分离；MySQL 只存 manifest/指标。
3. **增量重算**：仅重算新增交易日 + 受公司行为影响需作废的日期区间；禁止每次全量打满。
4. **早期抽样**：开发期可用「每月抽样 N 日」或「成分股子集」做 CI；夜间再跑全量。
5. **任务隔离**：研究重放与生产每日选股分队列/分资源，避免打满 DB 连接导致应用不可用。

没有预算数字就开全市场重放，极易把迭代拖死在基础设施上。

## A.9 Java ↔ Python 契约建议（正文架构的落地钉）

正文已划分职责，建议再规定最低契约，否则两套实现会漂移：

1. **特征契约文件**：`feature_set_version` + 列名/dtype/缺失语义/winsor 边界的 JSON Schema；Java 推理与 Python 训练必须校验同一 schema。
2. **禁止双实现**：同一因子要么 Java 算、Python 只消费 artifact，要么 Python 算、Java 只读结果表；过渡期允许「Python 权威 + Java 黄金样例对拍」。
3. **Artifact 布局**：`artifacts/{experiment_id}/{snapshot_id}/...` + `manifest.json`（hash、git、依赖锁、口径版本）。
4. **失败语义**：Python 任务失败不得写半截 `prediction_snapshot`；采用 temp + 原子发布。
5. **依赖锁**：`requirements.txt`/`uv.lock`/`poetry.lock` 任选其一并进 CI；模型文件旁路记录精确版本。

## A.10 生产发布与「今日无标的」运营规则

阶段 7 可再补充显式运营策略：

1. **数据截止 SLA**：例如交易日 16:30 前未完成质量闸 → 状态 `DATA_LATE`，不沿用昨日预测冒充今日。
2. **Abstain 分级**：`NO_CANDIDATE`（模型有效但无过阈值标的）vs `MODEL_DEGRADED`（监控触发降级）vs `DATA_UNRELIABLE`（质量闸失败）；前端文案三者分开。
3. **Shadow 对账**：同一日同时跑规则轨与概率轨，记录分歧率；晋升前要求 shadow 期分歧可解释。
4. **预测不可变**：已发布 `prediction_snapshot` 禁止 update；纠错只能新版本 + 作废标记。
